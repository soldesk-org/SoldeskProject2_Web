# 영수증 OCR - 프론트엔드 연동 가이드
------------------------------------------------------------------------
프론트엔드 전달용 API 요청 URL/스펙 정리 문서
[001-02.영수증OCR-분석-설계.md](001-02.영수증OCR-분석-설계.md), [001-03.영수증OCR-구현-테스트.md](001-03.영수증OCR-구현-테스트.md) 참고 (2026-07-22 카카오 전환 갱신 반영된 최신 스펙 기준)

------------------------------------------------------------------------
## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- Base path: `/api/receipts`
- **로그인 필수** — `Authorization: Bearer {accessToken}` 헤더 없이/무효 토큰으로 호출하면 `401 NOT_LOGGED_IN`.
- `Content-Type: multipart/form-data` (업로드 API 하나뿐).

------------------------------------------------------------------------
## 2. 꼭 알아야 할 것: `restaurantName`을 반드시 같이 보내야 한다
------------------------------------------------------------------------
음식점 상호명은 우리 서버가 저장하지 않는다(07의 카카오 ToS 준수 아키텍처, `docs/07.음식점-메뉴-검색/001-07`
참고). 그래서 영수증에 찍힌 상호명과 "지금 리뷰를 쓰려는 음식점"의 상호명을 서버가 스스로 비교할 방법이
없다 — **프론트가 검색/상세 화면에서 이미 갖고 있는 그 음식점의 이름(`name`)을 `restaurantName` 파라미터로
그대로 함께 보내야** 방문 인증(`verified`) 판정이 정상적으로 동작한다. 이 값을 빼먹으면 OCR 인식이 아무리
정확해도 항상 `verified: false`로 응답한다(2-1장 매칭 로직 자체가 두 값을 비교하는 방식이라).

------------------------------------------------------------------------
## 3. 기능별 호출 흐름
------------------------------------------------------------------------
### 3-1. 리뷰 작성 화면에서 영수증 첨부
1. 사용자가 음식점 상세 화면(07)에서 "영수증으로 인증하기" 같은 버튼을 누르면 파일 선택창을 띄운다
2. 사진을 고르면 즉시 `POST /api/receipts`로 업로드(현재 화면에 이미 있는 `restaurantId`와 `name`을
   각각 `restaurantId`/`restaurantName` 필드에 실어서)
3. 응답을 받으면:
   - `verified: true`면 "영수증 인증 완료" 뱃지를 보여주고, `receiptId`를 기억해뒀다가 리뷰 작성
     (`POST /api/reviews`, `docs/10.리뷰` 참고) 요청의 `receiptId` 필드에 그대로 실어 보낸다
   - `verified: false`면 "방문 인증에 실패했습니다"를 보여주되, **리뷰 작성 자체는 막지 않는다**(잠정 정책,
     001-02 8장) — `receiptId`를 그냥 안 보내거나, 보내도 서버가 재검증하므로 `receiptVerified: false`인
     미인증 리뷰로 등록됨
   - `storeName`/`orderDatetime`/`totalPrice`/`menuItems`는 OCR로 읽어낸 값 — 리뷰 작성 폼에 참고용으로
     보여주고 싶으면 그대로 사용 가능(리뷰 저장 항목은 아님)
4. 실패 응답(422 계열)이 오면 5장의 코드에 맞는 안내 문구(예: "영수증 사진이 흐릿해요, 다시 찍어주세요")를
   보여주고 재업로드를 유도

### 3-2. 중복 영수증
같은 영수증(정확히는 같은 승인번호)을 이미 업로드한 적이 있으면 `409 DUPLICATE_RECEIPT`가 온다 — "이미
사용된 영수증입니다"로 안내.

## 4. API 상세
------------------------------------------------------------------------
### 4-1. 영수증 업로드 + OCR + 방문 인증
```
POST http://localhost:8081/api/receipts
Content-Type: multipart/form-data
Authorization: Bearer {accessToken}

image: (파일)
restaurantId: "16421356"        // 카카오 장소 id 문자열 (07 상세 화면에서 이미 갖고 있는 값)
restaurantName: "농민백암순대 강남직영점"   // 2장 참고 — 필수
```

성공 응답 (200, 인증 성공):
```json
{
  "success": true, "receiptId": 1, "storeName": "농민백암순대 강남직영점",
  "orderDatetime": "2026-07-22 14:30", "totalPrice": 17000,
  "menuItems": [ { "name": "김치찌개", "price": 9000 }, { "name": "된장찌개", "price": 8000 } ],
  "verified": true, "restaurantId": "16421356"
}
```

성공 응답 (200, 인증 실패 — 상호명 불일치):
```json
{
  "success": true, "receiptId": 2, "storeName": "엉뚱한식당",
  "orderDatetime": "2026-07-22 14:30", "totalPrice": 17000, "menuItems": [ ... ],
  "verified": false, "restaurantId": null
}
```
HTTP 상태는 **200**(실패가 아니라 "미인증 성공"으로 취급) — `verified`/`restaurantId` 값으로만 구분한다.

실패 응답 (422, OCR 일부 인식 실패 — 상호명을 못 읽은 경우 예시):
```json
{ "success": false, "code": "RECEIPT_STORE_NAME_NOT_FOUND", "message": "상호명을 인식하지 못했습니다.",
  "parsed": { "orderDatetime": "2026-07-22 14:30", "totalPrice": 17000 } }
```
`parsed`에 일부라도 읽어낸 값이 있으면 같이 내려온다 — 재입력 화면에서 참고용으로 보여줄 수 있음.

실패 응답 (409, 중복):
```json
{ "success": false, "code": "DUPLICATE_RECEIPT", "message": "이미 사용된 영수증입니다." }
```

실패 응답 (401, 로그인 안 됨):
```json
{ "success": false, "code": "NOT_LOGGED_IN", "message": "로그인 상태가 아닙니다." }
```

## 5. 에러 코드
------------------------------------------------------------------------
| 코드 | 상황 | HTTP | 안내 문구 예시 |
|---|---|---|---|
| RECEIPT_EMPTY_FILE | 빈 파일 업로드 | 400 | "이미지를 다시 선택해주세요" |
| RECEIPT_INVALID_IMAGE | 이미지 디코딩 실패 | 400 | "지원하지 않는 이미지 형식입니다" |
| INVALID_RECEIPT_IMAGE | 형식/용량 초과(jpg/png/gif/webp, 5MB 제한) | 400 | "5MB 이하의 이미지만 업로드 가능합니다" |
| RECEIPT_NO_TEXT_DETECTED | 글자를 전혀 못 읽음 | 422 | "영수증이 잘 안 보여요, 밝은 곳에서 다시 찍어주세요" |
| RECEIPT_PARSE_FAILED | 정보를 하나도 못 뽑음 | 422 | "영수증 인식에 실패했습니다" |
| RECEIPT_STORE_NAME_NOT_FOUND | 상호명 인식 실패 | 422 | "상호명이 잘 안 보여요" (부분 인식 결과는 `parsed`로 확인 가능) |
| RECEIPT_ORDER_DATETIME_NOT_FOUND | 주문일시 인식 실패 | 422 | 위와 동일 톤 |
| RECEIPT_TRANSACTION_ID_NOT_FOUND | 승인번호 인식 실패 | 422 | 위와 동일 톤 |
| RECEIPT_OCR_SERVICE_UNAVAILABLE | OCR 서버 통신 실패(서버 쪽 문제) | 500 | "잠시 후 다시 시도해주세요" |
| DUPLICATE_RECEIPT | 이미 사용된 영수증(승인번호 중복) | 409 | "이미 사용된 영수증입니다" |
| NOT_LOGGED_IN | 로그인 안 됨/토큰 무효 | 401 | 로그인 화면으로 이동 |

## 6. 참고
------------------------------------------------------------------------
- OCR을 처리하는 내부 Python 서버(`receipt-biz-verify`)가 별도로 떠 있어야 이 API가 정상 동작한다(로컬 개발
  환경에서는 `uvicorn main:app --port 8000` 수동 기동 필요, 001-03 2-1장 참고) — 서버가 안 떠 있으면
  `500 RECEIPT_OCR_SERVICE_UNAVAILABLE`이 난다.
- 리뷰 작성 자체(`POST /api/reviews`)는 `docs/10.리뷰/001-04` 참고 — 이 문서는 업로드까지만 다룸.
