## 1. 동작 요약
------------------------------------------------------------------------
- 같은 IP에서 하루(자정 기준) 최대 5회까지만 전화번호 인증 SMS 발송 가능
- 회원가입/이메일찾기/회원정보수정 3곳 API가 전부 이 한도를 공유(IP 기준이라 기능과 무관하게 합산)
- 6번째부터는 `429 PHONE_SMS_DAILY_LIMIT_EXCEEDED`("SMS 인증 요청 횟수를 초과했습니다. 내일 다시
  시도해주세요.")로 거부, 다음날 자정이 지나면 자동으로 다시 허용

------------------------------------------------------------------------
## 2. 한도 값 조정
------------------------------------------------------------------------
`PhoneSmsRateLimitService.MAX_SMS_PER_IP_PER_DAY` 상수 하나만 바꾸면 된다. 값을 바꾸는 데 배포 외의
별도 설정(환경변수, DB 등)은 없음 — 필요하면 나중에 `.env` 값으로 뺄 수도 있지만 지금은 코드 상수로
충분하다고 판단(자주 바꿀 값이 아님).

------------------------------------------------------------------------
## 3. Redis에서 직접 확인/초기화하는 법
------------------------------------------------------------------------
```bash
# 오늘 특정 IP가 몇 번 요청했는지 확인
redis-cli -h <REDIS_HOST> -p 6379 -a <비밀번호> GET "phone:sms:count:203.0.113.10:2026-07-30"

# 테스트 등의 이유로 강제로 리셋하고 싶을 때
redis-cli -h <REDIS_HOST> -p 6379 -a <비밀번호> DEL "phone:sms:count:203.0.113.10:2026-07-30"
```
날짜(`2026-07-30`)는 오늘 날짜로, IP는 실제 확인하려는 클라이언트 IP로 바꿔서 사용.

------------------------------------------------------------------------
## 4. 새로운 SMS 발송 지점을 추가할 때
------------------------------------------------------------------------
새로운 기능에서 전화번호 SMS 인증이 필요해지면, `PhoneAuthService.sendVerificationCode(...)`를
그대로 재사용하면 이 한도 체크가 자동으로 적용된다 — 별도로 신경 쓸 필요 없음. 단, 호출하는 컨트롤러
메서드에 `HttpServletRequest`를 받아서 `ClientIpUtil.resolve()`로 IP를 뽑아 넘겨야 한다(이미 있는
3개 진입점의 코드를 그대로 참고).

------------------------------------------------------------------------
## 5. 알려진 한계 (001-01 참고)
------------------------------------------------------------------------
- IP만 차단하고 "기기" 단위 차단은 없음 — 같은 사람이 IP를 바꾸면(모바일 데이터 재연결, VPN 등) 한도를
  우회할 수 있음
- 전화번호(수신자) 기준 제한은 없음 — 공격자가 여러 IP에서 같은 피해자 번호로 나눠서 발송시키는
  시나리오는 이 기능만으로는 못 막음. 필요해지면 `phone:sms:count:by-target:{phone}:{date}` 같은
  별도 카운터를 추가로 도입할 수 있음
- 실제 SMS 비용이 발생하는 6회차 시나리오의 라이브 종단 테스트는 비용 문제로 진행하지 않음(001-03
  3장) — 실사용 중 문제 발견 시 알려줄 것
