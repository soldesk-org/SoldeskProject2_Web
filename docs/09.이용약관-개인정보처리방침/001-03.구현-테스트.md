## 2. 프론트엔드 신규/변경 파일

신규:
- `static/notices.html`, `static/notice-detail.html`
- `static/assets/js/notices.js`, `static/assets/js/notice-detail.js`

변경:
- `static/terms-service.html`, `static/terms-privacy.html` — 정적 본문/목차를 걷어내고 `#termsBody`/
  `#termsToc`(privacy는 `#privacyBody`/`#privacyToc`) 뼈대만 남긴 뒤 `assets/js/api.js`를 로드하도록 수정,
  하단에 버전 select(`#versionPicker`) 추가.
- `static/assets/js/terms-service.js`, `static/assets/js/terms-privacy.js` — 정적 스크롤스파이 코드에서
  `GET /api/terms/{docType}` 기반 동적 렌더링 + 목차 자동 생성 + 버전 select 연동으로 전면 교체.
- `static/index.html` — 푸터 "고객지원·정책" 목록에 "공지사항" 링크 추가.
- `static/admin.html` — 사이드바에 "약관 관리" 탭 추가, `#sectionTerms` 신규 섹션(버전 등록 폼 + 버전
  목록 표 + 공지 목록 표).
- `static/assets/js/admin.js` — `SECTIONS.terms` 매핑, 약관 관리 탭 지연 로드(`loadTermsSection`),
  14/30일 규칙 클라이언트 힌트(`updateTermsLeadTimeHint`), 등록 폼 제출 핸들러.

기존 signup-terms.js는 이용약관/개인정보처리방침 페이지에 앵커 딥링크를 걸지 않고(체크박스 상태만
관리하는 스크립트) 페이지 이동은 signup-info.html 쪽에서 처리하므로, 이번 변경으로 깨지는 부분이 없음을
소스 확인으로 검증했다.

## 3. 검증

### 3-1. 백엔드 컴파일

```
cd Project2 && ./mvnw.cmd -q compile
```

경고/에러 없이 정상 종료(BUILD SUCCESS, 조용한 모드라 출력 없음 = 성공).

### 3-2. 프론트 JS 구문 검사

```
node --check assets/js/terms-service.js
node --check assets/js/terms-privacy.js
node --check assets/js/notices.js
node --check assets/js/notice-detail.js
node --check assets/js/admin.js
```

전부 통과.

### 3-3. 라이브 서버/DB 검증

**이번 세션에서는 수행하지 않았다.** 서버를 기동해서 시드 데이터가 실제로 채워지는지, 관리자 등록
플로우(14/30일 검증 포함)가 실제로 동작하는지, notices.html/notice-detail.html이 실제 데이터로 정상
렌더링되는지는 아직 확인하지 못한 상태다 — 리뷰 후 실 서버 기동 검증이 필요하다(요청사항에 "compile+
verify locally, 사람이 리뷰 후 배포" 원칙이 명시돼 있어 커밋/배포는 하지 않았다).

## 4. 시드 데이터

`TermsInitialDataSeeder`(`ApplicationRunner`)가 서버 최초 기동 시(해당 docType 행이 하나도 없을 때만)
기존 정적 페이지 본문을 그대로 v1로 심는다 — `versionLabel="2026-08-01"`, `effectiveDate=2026-08-01`
(오늘 날짜 기준 이미 지난 날짜라 즉시 "현재 버전"으로 조회된다).
