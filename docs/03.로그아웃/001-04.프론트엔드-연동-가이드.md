
------------------------------------------------------------------------
# 로그아웃 - 프론트엔드 연동 가이드
------------------------------------------------------------------------
프론트엔드(윤지) 전달용 API 요청 URL/스펙 정리 문서
[001-02.로그아웃-분석-설계.md](001-02.로그아웃-분석-설계.md), [001-03.로그아웃-구현-테스트.md](001-03.로그아웃-구현-테스트.md) 참고
※ 로그인 쪽 문서([002 로그인 001-04](../02.로그인/001-04.프론트엔드-연동-가이드.md))를 먼저 보고 오시는 걸 추천합니다 — accessToken/refreshToken을 어떻게 받는지가 거기 나와있어요.

------------------------------------------------------------------------
## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- Base path: `/api`
- 로그아웃도 다른 API처럼 별도 인증 헤더 없이, **요청 본문에 accessToken을 실어서** 호출하면 됩니다. `Content-Type: application/json` 필수.

------------------------------------------------------------------------
## 2. 로그아웃 흐름
------------------------------------------------------------------------
1. 로그인 성공 응답에서 받아 프론트가 보관 중인 `accessToken`을 그대로 실어서 `POST /api/members/logout` 호출 1회면 끝
2. 응답을 받으면(성공이든 실패든) **프론트에 저장해둔 accessToken/refreshToken을 지우고 로그인 화면으로 이동**시키면 됩니다 (3-1 응답 예시, 6장 참고)

------------------------------------------------------------------------
## 3. API 상세
------------------------------------------------------------------------
### 3-1. 로그아웃
```
POST http://localhost:8081/api/members/logout
Content-Type: application/json

{
  "accessToken": "eyJhbGciOi..."
}
```
성공 응답 (200)
```json
{ "success": true, "message": "로그아웃되었습니다." }
```

------------------------------------------------------------------------
## 4. 입력값 검증 규칙
------------------------------------------------------------------------
| 필드 | 규칙 |
|---|---|
| accessToken | 필수 입력 (로그인 응답에서 받은 값을 그대로 전달) |

------------------------------------------------------------------------
## 5. 에러 응답 형식
------------------------------------------------------------------------
모든 에러는 아래 형식으로 내려옵니다. HTTP status와 `code`로 분기 처리하면 됩니다.
```json
{ "success": false, "code": "NOT_LOGGED_IN", "message": "로그인 상태가 아닙니다." }
```

| code | 상황 | HTTP Status | 안내 문구(그대로 사용 가능) |
|---|---|---|---|
| INVALID_INPUT | accessToken 미입력 | 400 | message 그대로 노출 |
| NOT_LOGGED_IN | accessToken이 무효(위조/만료 등)이거나, 이미 로그아웃되어 로그인 상태로 볼 수 없음 | 401 | "로그인 상태가 아닙니다." |

------------------------------------------------------------------------
## 6. 참고 / 주의사항
------------------------------------------------------------------------
- **로그아웃 응답이 실패(`NOT_LOGGED_IN`)여도 프론트는 그냥 로그인 화면으로 보내면 됩니다.** 이미 로그인 상태가 아니라는 뜻이라, "로그아웃 실패했다"고 사용자에게 알릴 필요 없이 조용히 로그인 화면으로 이동시키는 게 자연스럽습니다. 저장된 토큰도 이 경우 포함해서 항상 지워주세요.
- **로그아웃 후 메인 화면 이동은 아직 프론트에 메인 화면이 없어서 서버 응답에 별도 리다이렉트 정보가 없습니다.** 요구사항대로 `success` 값과 무관하게 프론트에서 원하는 화면(로그인 화면 등)으로 이동시켜주시면 됩니다.
- **로그아웃해도 다른 API가 막히지는 않습니다.** 지금은 로그인 여부를 검사하는 보호된 API 자체가 없어서(로그인 001-05 1번 항목), 로그아웃은 "서버에 저장된 로그인 기록(access/refresh token)을 지우는 것"까지만 하는 상태입니다. 나중에 보호된 API가 생기면 그때부터 로그아웃이 실질적으로 그 API들을 막는 효과가 생깁니다.
- refreshToken은 로그아웃 요청에 **포함하지 않습니다.** accessToken 하나만 보내면 서버가 그 안의 정보로 알아서 해당 계정의 refresh token까지 같이 지웁니다.
- 로그아웃 요청 자체가 실패(네트워크 오류 등)해도, 프론트 쪽 토큰은 지우고 로그인 화면으로 보내는 걸 권장합니다 — 서버 상태와 무관하게 클라이언트 쪽 로그인 상태 정리는 항상 해주는 게 안전합니다.
- 현재 CORS 설정은 별도로 열려있지 않습니다. 프론트 개발 서버 주소가 정해지면 알려주시면 CORS 허용 처리하겠습니다.
