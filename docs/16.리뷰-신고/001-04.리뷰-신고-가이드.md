## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- 신고 등록은 **로그인 필수**(`Authorization: Bearer {accessToken}`). 관리자 API(목록/처리)는 로그인 +
  ADMIN 권한 필수(`docs/14.관리자-권한` 참고, 같은 인증 방식).

------------------------------------------------------------------------
## 2. 기능별 호출 흐름
------------------------------------------------------------------------
### 2-1. 회원 — 리뷰 신고
1. 음식점 상세의 리뷰 목록에서 신고하고 싶은 리뷰에 "신고" 버튼을 둔다
2. 사유는 반드시 고정 목록 중 하나여야 한다 — 프론트에도 아래 5개를 그대로 하드코딩해서 선택지(라디오
   버튼 등)로 보여줄 것:
   | 코드 | 의미 |
   |---|---|
   | SPAM | 광고/도배성 내용 |
   | ABUSE | 욕설/비방 |
   | FALSE_INFO | 허위 사실 |
   | PRIVACY | 개인정보 노출 |
   | ETC | 기타(상세 내용에 자유 텍스트 권장) |
3. `POST /api/reviews/{reviewId}/report` 호출, 성공하면 "신고가 접수되었습니다" 안내
4. 이미 신고한 리뷰면 `409 REVIEW_ALREADY_REPORTED` — "이미 신고한 리뷰입니다" 정도로 안내하고 버튼을
   비활성화하는 것을 권장(다시 시도해도 항상 같은 에러가 남)

### 2-2. 관리자 — 신고된 리뷰 확인/처리
1. `GET /api/admin/reports?status=PENDING`으로 목록 표시(리뷰 단위로 이미 집계되어 있음, 같은 리뷰가 여러
   줄로 중복되지 않음). `status`는 `PENDING`(기본)/`RESOLVED`/`REJECTED` 세 가지 — 대기중/처리완료/반려
   탭을 만들어 각각 조회하는 것을 권장(2026-07-23 2차 추가)
2. PENDING 탭에서만 "처리 완료"/"처리 불가" 두 버튼을 노출할 것(RESOLVED/REJECTED 탭은 조회 전용):
   - "처리 완료" → `PATCH /api/admin/reports/{reviewId}/resolve` — 신고가 타당해서 조치(예: 리뷰 삭제)를
     했거나 조치가 필요하다고 판단한 경우
   - "처리 불가" → `PATCH /api/admin/reports/{reviewId}/reject` — 신고를 검토했지만 근거가 없거나 조치할
     필요가 없다고 판단한 경우
   - 둘 다 **리뷰는 지워지지 않는다**, 신고 상태만 바뀐다
3. 그 리뷰를 실제로 지우고 싶으면 `docs/14.관리자-권한`의 `DELETE /api/admin/reviews/{id}`를 따로 호출할
   것(신고 처리와 리뷰 삭제는 별개 버튼으로 둘 것을 권장)
4. `docs/14.관리자-권한`의 대시보드(`GET /api/admin/dashboard`)에 "신고된 리뷰 수"가 이 기능의 `PENDING`
   신고 기준으로 실시간 반영된다 — 신고 등록/처리(완료·반려 모두) 액션 후에는 대시보드도 함께 재조회할 것

## 3. API 상세
------------------------------------------------------------------------
### 3-1. 리뷰 신고
```
POST http://localhost:8081/api/reviews/55/report
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "reasonCode": "SPAM", "detail": "같은 문구로 여러 매장에 도배성 리뷰를 남기고 있습니다." }
```
`detail`은 선택(최대 500자).

성공(200): `{ "success": true, "message": "신고가 접수되었습니다." }`
실패(404): `{ "success": false, "code": "REVIEW_NOT_FOUND", "message": "..." }`
실패(400, 목록에 없는 사유): `{ "success": false, "code": "REPORT_REASON_NOT_ALLOWED", "message": "..." }`
실패(409, 중복 신고): `{ "success": false, "code": "REVIEW_ALREADY_REPORTED", "message": "..." }`

### 3-2. 신고된 리뷰 목록 (관리자)
```
GET http://localhost:8081/api/admin/reports?status=PENDING
Authorization: Bearer {accessToken}
```
`status`는 선택(`PENDING`/`RESOLVED`/`REJECTED`, 생략 시 `PENDING`, 2026-07-23 2차 추가).

응답(200):
```json
[
  {
    "reviewId": 7, "authorNickname": "test_user", "restaurantName": "정월",
    "rating": 5, "content": "...", "reportCount": 1, "latestReasonCode": "SPAM",
    "latestReportedAt": "2026-07-23T14:43:42.391276", "status": "PENDING"
  }
]
```
요청한 `status` 값에 해당하는 신고가 있는 리뷰만, 최근 신고순. 없으면 `[]`.

### 3-3. 신고 처리 완료 (관리자)
```
PATCH http://localhost:8081/api/admin/reports/7/resolve
Authorization: Bearer {accessToken}
```
성공(200): `{ "success": true, "message": "신고 처리를 완료했습니다." }`
실패(404, 처리할 PENDING 신고가 없음): `{ "success": false, "code": "REPORT_NOT_FOUND", "message": "..." }`

### 3-4. 신고 반려/처리 불가 (관리자, 2026-07-23 2차 추가)
```
PATCH http://localhost:8081/api/admin/reports/7/reject
Authorization: Bearer {accessToken}
```
성공(200): `{ "success": true, "message": "신고를 반려(처리 불가)했습니다." }`
실패(404, 처리할 PENDING 신고가 없음): `{ "success": false, "code": "REPORT_NOT_FOUND", "message": "..." }`

## 4. 에러 코드
------------------------------------------------------------------------
| code | 상황 | HTTP |
|---|---|---|
| NOT_LOGGED_IN | 신고 시 미로그인, 또는 관리자 API 미로그인 | 401 |
| ADMIN_ACCESS_DENIED | 관리자 API를 비관리자로 호출 | 403 |
| REVIEW_NOT_FOUND | 존재하지 않거나 이미 삭제된 리뷰 | 404 |
| REPORT_REASON_NOT_ALLOWED | 고정 목록에 없는 사유 코드 | 400 |
| REVIEW_ALREADY_REPORTED | 같은 회원의 중복 신고 | 409 |
| REPORT_NOT_FOUND | 처리(resolve 또는 reject)할 PENDING 신고가 없음 | 404 |
