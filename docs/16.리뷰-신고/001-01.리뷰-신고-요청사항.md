## 요청사항 원문 요약
------------------------------------------------------------------------
14(관리자-권한) 대시보드 확장 요청("회원 관리 / 음식점 관리 / 신고 관리 / 리뷰 관리")에서 "신고 관리 -
신고된 리뷰 관리" 항목이 나왔는데, 그 전제가 되는 "리뷰를 신고하는 기능" 자체가 이 프로젝트에 아직
없었다. 사용자가 이걸 별도 신규 기능으로 만들기로 확정하고, 별도 docs 폴더(16)로 분리해서 문서화하기로 함.

------------------------------------------------------------------------
## 배경
------------------------------------------------------------------------
14(관리자-권한) 001-01에서 애초에 요청됐던 관리자 기능 4가지 중:
- 회원 관리(전체/일반/사업자) — 14에서 확장 구현
- 음식점 관리 — **"DB에 저장이 금지되기 때문에 구현 불가"로 사용자가 직접 확인**(07의 카카오 ToS 준수
  재설계 이후 `restaurants` 테이블이 상호명/주소를 저장하지 않는 구조라, "우리 DB의 음식점을 관리"한다는
  개념 자체가 성립하기 어려움 — 14 001-01 9장에 이미 반영됨)
- 신고 관리(신고된 리뷰 관리) — **이 기능(16)이 그 전제 조건**
- 리뷰 관리(작성된 리뷰 수/신고된 리뷰 수) — 14에서 대시보드로 확장 구현, "신고된 리뷰 수"는 이 기능에
  의존

즉 16(리뷰-신고)은 14의 "신고 관리" 요청을 실제로 가능하게 만드는 선행 기능이다 — 관리자가 신고된 리뷰를
보려면, 먼저 회원이 리뷰를 신고할 수 있는 기능 자체가 있어야 한다.

------------------------------------------------------------------------
## 이번 범위 정리
------------------------------------------------------------------------
- 로그인한 회원이 리뷰 하나를 고정된 사유(광고/비방/허위사실/개인정보노출/기타) 중 하나로 신고
- 같은 회원이 같은 리뷰를 중복 신고하는 것은 막음
- 관리자가 신고된 리뷰 목록을 리뷰 단위로 확인(신고 건수/최근 사유 포함)
- 관리자가 신고를 "처리 완료"로 표시(리뷰 자체를 지우는 것과는 별개 액션 — 리뷰 삭제는 14의 기존
  `DELETE /api/admin/reviews/{id}`를 그대로 재사용)
- 14(관리자-권한) 대시보드의 "신고된 리뷰 수" 통계가 이 기능의 데이터를 사용

------------------------------------------------------------------------
## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- 리뷰 신고 자동 처리(신고 N건 이상이면 자동 숨김/삭제 등) — 이번엔 관리자가 직접 확인 후 수동으로만 처리
- 신고 사유 자유 입력(고정 목록 밖의 값) — 10.리뷰의 태그 목록과 같은 패턴으로 고정 목록만 허용
- 신고자에게 처리 결과 알림(이메일/푸시 등) — 이번 범위 밖
- 음식점 자체에 대한 신고(이번엔 리뷰 신고만) — 음식점은 배경 장에서 설명한 이유로 애초에 관리 대상이
  아님

상세 설계는 [001-02.리뷰-신고-분석-설계.md](001-02.리뷰-신고-분석-설계.md) 참고.

## 후속 요청 1 (2026-07-23 2차): 신고 UI를 팝업 모달로, 처리 완료/반려 구분
------------------------------------------------------------------------
1차 구현 직후 두 가지 후속 요청이 이어졌다.

**요청 1** — "신고 사유를 입력하세요 (SPAM/ABUSE/FALSE_INFO/PRIVACY/ETC) 모달 말고 팝업 창으로 뜨게 해서
거기서 신고 카테고리 선택 후 밑에 신고 내용 적을 수 있도록 해줘": 원래 `prompt()` 브라우저 기본 대화상자로
사유 코드를 텍스트로 직접 입력받던 신고 UI(`tmp-map-test.html`)를, 사유를 라디오 버튼으로 고르고 상세
내용을 textarea에 입력하는 실제 팝업 모달로 교체.

**요청 2** — "신고 관리 (신고된 리뷰)에 처리된 기록도 볼 수 있도록 해주고 처리 완료가 있으면 처리 불가
이렇게도 있어야 하지 않니?": 관리자 화면에서 대기중인 신고만 보이고 이미 처리된 신고는 조회할 방법이
없었던 것을 지적. 이에 따라:
- 처리 결과를 `RESOLVED`(처리 완료)와 `REJECTED`(반려/처리 불가) 두 가지로 구분(기존엔 `RESOLVED` 하나뿐)
- 관리자 목록 조회 API에 `status` 필터를 추가해 대기중/처리완료/반려 세 목록을 각각 확인 가능
- 관리자 테스트 페이지에 3개 탭 버튼으로 반영

상세 설계는 [001-02.리뷰-신고-분석-설계.md](001-02.리뷰-신고-분석-설계.md) 2-6장, 구현/검증은
[001-03.리뷰-신고-구현-테스트.md](001-03.리뷰-신고-구현-테스트.md) 참고.
