## 기능 정리하기
------------------------------------------------------------------------
현재 해당 기능은 프론트 연결하지 않고 개발만 하기
이메일 찾기 요청 시 닉네임 + 전화번호를 입력받아서 DB에서 확인 후 2개 다 일치할 경우 찾고자 하는 회원의 이메일 정보를 ab***@gm****.com 같이 일부 마스킹하여 보여주기
(마스킹 이유 : 회원가입 시 전화번호는 입력받지만 인증을 안 하게 일단 구성 하였고 이메일 찾기에서 해당 전화번호를 입력하여 인증이 가능하면 전부 보여줄 수 있는데 해당 구현이 아직 안 됨 추후에 프로젝트 멤버들에게 물어보고 결정하기, 추가하면 대신 SMS(문자)인증에서 발송 건당 50~75원 정도의 비용이 들어가게 됨)
이 때 전화번호는 
비밀번호 찾기 요청 시 이메일를 입력받아서 DB에서 존재하는 이메일인 경우만 이메일 보내고 존재하지 않은 이메일이여도 이메일 보낸거 처럼 프론트에서 하긴 하는데 전송은 안됨
이메일 전송 할 때 비밀번호 재설정 URL을 같이 보내서 새 비밀번호, 새 비밀번호 확인로 비밀번호 재설정 하기 DB에 올릴 때는 암호화 환경에 있는 저 알고리즘으로 처리하여 저장
비밀번호 재설정 URL은 유효시간 1시간, 유효시간 지날 경우 URL 만료, URL에 토큰? 같은 값으로 유효기간이 지난 URL이나 아무 값이나 입력해서 못 들어오게 처리하기

## SMS(문자) 본인인증 도입 결정 (2026-07-18 요구사항 추가)
------------------------------------------------------------------------
위 "기능 정리하기"에서 보류했던 "전화번호 인증이 가능하면 이메일을 전부 보여줄 수 있다"는 항목을 실제로 도입하기로 결정함.
- 사용 대행사/API/비용은 회원가입 쪽과 동일하게 뿌리오(Ppurio) 사용 — 상세 스펙은 [00.공통/SMS-인증-Ppurio-연동-가이드.md](../00.공통/SMS-인증-Ppurio-연동-가이드.md), 회원가입 쪽 적용 내용은 [01.회원가입 001-02 8-1장](../01.회원가입/001-02.회원가입-분석-설계.md#8-1-sms-전화번호-인증-설계-ppurio-연동-2026-07-18-요구사항-추가) 참고
- 이메일 찾기 요청(닉네임+전화번호로 회원 조회) 이후, 그 전화번호로 SMS 인증번호를 발송 → 인증 성공 시 마스킹 없이 전체 이메일 공개, 미인증 상태로는 기존처럼 마스킹된 이메일만 제공
- 상세 설계는 [001-02.이메일찾기-비밀번호찾기-분석-설계.md 12장](001-02.이메일찾기-비밀번호찾기-분석-설계.md#12-sms-인증으로-이메일-전체-공개-설계-ppurio-연동-2026-07-18-요구사항-추가) 참고
