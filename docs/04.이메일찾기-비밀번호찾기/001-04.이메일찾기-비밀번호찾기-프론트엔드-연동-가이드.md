# 이메일 찾기 / 비밀번호 찾기 - 프론트엔드 연동 가이드
------------------------------------------------------------------------
프론트엔드 전달용 API 요청 URL/스펙 정리 문서

## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- Base path: `/api`
- 별도 인증 헤더 없이 호출하면 됩니다. `Content-Type: application/json` 필수.

------------------------------------------------------------------------
## 2. 기능별 호출 흐름
------------------------------------------------------------------------
### 2-1. 이메일 찾기 (마스킹 조회)
1. `POST /api/members/find-email` — 닉네임 + 전화번호 입력 후 조회
2. 응답으로 마스킹된 이메일(`ab***@gm****.com` 형태)과 `verificationToken`이 함께 내려옵니다. 마스킹된 이메일만 보여줄 거라면 `verificationToken`은 무시해도 됩니다.

### 2-2. 이메일 찾기 (SMS 인증 → 전체 이메일 공개, 2026-07-18 추가)
> 아직 실제로 동작하지 않습니다 — 6장 참고. 화면/연동 코드는 아래 스펙 기준으로 준비해두시면 됩니다.

1. 2-1의 응답에서 받은 `verificationToken`을 들고, `POST /api/members/find-email/verify-phone/send-code`로 (2-1에서 입력했던 것과 같은) 전화번호에 SMS 인증번호 발송 요청
2. 사용자가 받은 인증번호로 `POST /api/members/find-email/verify-phone/confirm` 호출
3. `POST /api/members/find-email/reveal`로 마스킹 없는 전체 이메일 조회 (인증 성공 후 10분 이내에만 가능)

### 2-3. 비밀번호 찾기
1. `POST /api/members/password-reset/request` — 이메일 입력 후 재설정 메일 발송 요청
2. 사용자가 메일에 담긴 링크(`{프론트주소}?token=xxx`)를 클릭해 재설정 페이지로 진입
3. `POST /api/members/password-reset/confirm` — 그 페이지에서 새 비밀번호 / 새 비밀번호 확인 입력 후 제출 (1번 응답에 URL만 포함되어 있으므로 링크에서 `token` 쿼리스트링 값을 꺼내 그대로 3번 요청에 실어 보내면 됩니다)

## 3. API 상세
------------------------------------------------------------------------
### 3-1. 이메일 찾기
```
POST http://localhost:8081/api/members/find-email
Content-Type: application/json

{
  "nickname": "홍길동",
  "phone": "010-1234-5678"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "일치하는 회원 정보를 찾았습니다.", "maskedEmail": "ab***@gm****.com", "verificationToken": "Xy82f..." }
```
실패 응답 (400, 닉네임/전화번호 조합이 일치하는 회원 없음)
```json
{ "success": false, "code": "MEMBER_NOT_FOUND", "message": "일치하는 회원 정보를 찾을 수 없습니다." }
```
※ 닉네임만 맞고 전화번호가 틀린 경우 등 "부분적으로만 맞는 경우"도 전부 위와 동일한 MEMBER_NOT_FOUND로 응답합니다. 어느 값이 틀렸는지 구분해서 알려주지 않습니다(보안상 의도된 동작).
※ `verificationToken`은 회원의 PK가 아니라 10분짜리 단기 세션 토큰입니다. 마스킹 해제(3-2~3-4) 흐름을 쓰지 않는다면 응답에서 그냥 버려도 됩니다.

### 3-2. 이메일 찾기 - SMS 인증번호 발송 (2026-07-18 추가, 현재 실제 발송 불가 — 6장 참고)
```
POST http://localhost:8081/api/members/find-email/verify-phone/send-code
Content-Type: application/json

{
  "verificationToken": "3-1 응답의 verificationToken",
  "phone": "010-1234-5678"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "인증번호가 발송되었습니다." }
```
`phone`은 3-1에서 조회에 사용했던 전화번호와 같아야 합니다(다르면 `PHONE_NOT_FOUND`).

### 3-3. 이메일 찾기 - SMS 인증번호 확인
```
POST http://localhost:8081/api/members/find-email/verify-phone/confirm
Content-Type: application/json

{
  "verificationToken": "3-1 응답의 verificationToken",
  "phone": "010-1234-5678",
  "code": "123456"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "전화번호 인증이 완료되었습니다." }
```

### 3-4. 이메일 찾기 - 전체 이메일 공개
```
POST http://localhost:8081/api/members/find-email/reveal
Content-Type: application/json

{
  "verificationToken": "3-1 응답의 verificationToken"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "이메일을 확인했습니다.", "email": "abcdef@gmail.com" }
```
실패 응답 (400, 인증 미완료 또는 인증 후 10분 경과)
```json
{ "success": false, "code": "PHONE_NOT_VERIFIED", "message": "전화번호 인증이 완료되지 않았습니다." }
```

### 3-5. 비밀번호 재설정 요청
```
POST http://localhost:8081/api/members/password-reset/request
Content-Type: application/json

{
  "email": "user@example.com"
}
```
성공 응답 (200) — **입력한 이메일이 실제로 가입되어 있는지와 무관하게 항상 아래와 동일하게 응답합니다.**
```json
{ "success": true, "message": "입력하신 이메일로 비밀번호 재설정 안내를 보냈습니다." }
```
※ 존재하지 않는 이메일을 입력해도 200이 내려오지만 실제 메일은 발송되지 않습니다(계정 존재 여부가 노출되지 않도록 의도된 동작). 프론트에서는 이 응답을 받으면 "메일함을 확인해주세요" 같은 안내만 보여주면 되고, 실패 케이스를 별도로 처리할 필요는 없습니다(입력값 형식 오류 제외, 5장 참고).

### 3-6. 비밀번호 재설정 확정
```
POST http://localhost:8081/api/members/password-reset/confirm
Content-Type: application/json

{
  "token": "메일 링크의 token 쿼리스트링 값",
  "newPassword": "N3wP@ss1",
  "newPasswordConfirm": "N3wP@ss1"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "비밀번호가 재설정되었습니다." }
```
실패 응답 예시 (400, 토큰 만료/위조/이미 사용됨 — 원인 구분 없이 동일하게 응답)
```json
{ "success": false, "code": "INVALID_RESET_TOKEN", "message": "유효하지 않거나 만료된 링크입니다." }
```

## 4. 입력값 검증 규칙 (프론트 단에서도 동일하게 미리 검증 추천)
------------------------------------------------------------------------
| 필드 | 규칙 |
|---|---|
| nickname (이메일 찾기) | 한글/영문/숫자 2~10자 (특수문자 불가) — 회원가입과 동일 |
| phone (이메일 찾기) | `010-XXXX-XXXX` 형식 (하이픈 포함해서 그대로 전송) — 회원가입과 동일 |
| verificationToken (SMS 인증/전체공개) | 3-1 응답 값을 그대로 전달 (프론트에서 별도 형식 검증 불필요) |
| code (SMS 인증 확인) | 숫자 6자리 |
| email (재설정 요청) | 이메일 형식, 최대 100자 |
| token (재설정 확정) | 메일 링크의 값을 그대로 전달 (프론트에서 별도 형식 검증 불필요) |
| newPassword / newPasswordConfirm (재설정 확정) | 8~20자, 영문+숫자+특수문자 모두 포함, 둘 다 서로 동일해야 함 — 회원가입 비밀번호 규칙과 동일 |

------------------------------------------------------------------------
## 5. 에러 응답 형식
------------------------------------------------------------------------
모든 에러는 아래 형식으로 내려옵니다. HTTP status와 `code`로 분기 처리하면 됩니다.
```json
{ "success": false, "code": "MEMBER_NOT_FOUND", "message": "일치하는 회원 정보를 찾을 수 없습니다." }
```

| code | 상황 | 발생 API | HTTP Status |
|---|---|---|---|
| INVALID_INPUT | 입력값 형식 오류 (검증 실패한 첫 필드명이 message에 포함됨) | 전체 API 공통 | 400 |
| MEMBER_NOT_FOUND | 닉네임+전화번호 조합이 일치하는 회원 없음 | find-email | 400 |
| INVALID_VERIFICATION_TOKEN (2026-07-18 추가) | `verificationToken`이 없거나 만료됨(발급 후 10분 경과) | find-email/verify-phone/*, find-email/reveal | 400 |
| PHONE_NOT_FOUND (2026-07-18 추가) | SMS 발송 이력이 없거나, 3-1에서 조회했던 것과 다른 전화번호로 요청 | find-email/verify-phone/* | 400 |
| INVALID_CODE / EXPIRED_CODE (2026-07-18 추가) | SMS 인증번호 불일치 / 만료 | find-email/verify-phone/confirm | 400 |
| PHONE_NOT_VERIFIED (2026-07-18 추가) | SMS 인증 미완료 상태로 전체 이메일 조회 시도 (또는 인증 후 10분 경과) | find-email/reveal | 400 |
| INVALID_RESET_TOKEN | 재설정 토큰이 없거나 만료됨/이미 사용됨/위조됨 | password-reset/confirm | 400 |
| PASSWORD_CONFIRM_MISMATCH | 새 비밀번호와 새 비밀번호 확인이 다름 | password-reset/confirm | 400 |
| SMS_SEND_FAIL (2026-07-18 추가) | SMS 발송 실패 (현재 뿌리오 계정 미발급으로 인해 항상 이 에러가 남, 6장 참고) | find-email/verify-phone/send-code | 500 |

※ `password-reset/request`는 입력값 형식 오류(INVALID_INPUT) 외에는 항상 200으로 응답하므로, 이 API에 대해서는 위 표의 나머지 에러코드를 처리할 필요가 없습니다.

## 6. 참고 / 주의사항
------------------------------------------------------------------------
- **(2026-07-18 추가) 이메일 찾기 SMS 인증(2-2장, 3-2~3-4장)은 현재 실제로 동작하지 않습니다.** SMS 발송 대행사(뿌리오) 계정 발급이 아직 완료되지 않았습니다. 지금 `verify-phone/send-code`를 호출하면 서버에서 `SMS_SEND_FAIL`로 실패합니다. 화면/연동 코드는 API 스펙 기준으로 준비해두시고, 실제 연동 테스트는 계정 발급 완료 안내가 갈 때까지 보류해주세요. 그 전까지는 이메일 찾기에서 마스킹된 이메일(3-1)만 사용하시면 됩니다.
- **`verificationToken`은 발급 후 10분간만 유효**합니다. 이 시간 안에 SMS 인증 발송→확인→전체공개 조회까지 끝내야 합니다(10분이 지나면 3-1부터 다시 시작).
- **비밀번호 재설정 URL의 프론트 주소는 아직 정해지지 않았습니다.** 현재 서버는 `http://localhost:5173/reset-password?token=xxx` 형태로 메일을 보내도록 임시 설정되어 있습니다. 실제 프론트 재설정 페이지 경로가 정해지면 알려주세요 — 서버 설정값만 바꾸면 되고 API 스펙(3-6장)은 변하지 않습니다.
- **비밀번호 재설정 링크는 발급 후 1시간만 유효**하고, **1회만 사용**할 수 있습니다(성공적으로 재설정하고 나면 같은 링크로 다시 요청해도 INVALID_RESET_TOKEN이 납니다). 프론트에서 "링크가 만료되었거나 이미 사용되었습니다. 다시 요청해주세요" 같은 안내와 함께 재설정 요청 화면(2-3장)으로 돌아가는 도선을 넣어주시면 좋습니다.
- **(2026-07-18 해결됨) 비밀번호 재설정 메일 발송 문제는 해결되었습니다.** 기존 Gmail 발송 계정이 정지되어 있던 문제를 Daum 메일(`eattyway@daum.net`)로 교체해 해결했고, 실제 메일 발송/수신까지 확인했습니다([001-03.회원가입-구현-테스트.md 1-2장](../01.회원가입/001-03.회원가입-구현-테스트.md) 참고). `password-reset/request`를 정상 호출하면 실제로 메일이 도착합니다.
- 현재 CORS 설정은 별도로 열려있지 않습니다. 프론트 개발 서버 주소가 정해지면 알려주시면 CORS 허용 처리하겠습니다.
