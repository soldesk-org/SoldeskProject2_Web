# 음식점·메뉴 검색 - 프론트엔드 연동 가이드
------------------------------------------------------------------------
프론트엔드 전달용 API 요청 URL/스펙 정리 문서
[001-07.카카오-로컬-API-전환-및-리뷰-기능-구현.md](001-07.카카오-로컬-API-전환-및-리뷰-기능-구현.md) 기준 최종 아키텍처를 그대로 반영한 문서 — 001-02/001-03의 네이버/공공데이터 기반 스펙은 더 이상 유효하지 않음.

------------------------------------------------------------------------
## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- Base path: `/api/restaurants`
- 목록/검색/필터/상세/메뉴/주변조회는 **전부 로그인 불필요**(공개 API). 로그인한 상태면
  `Authorization: Bearer {accessToken}` 헤더를 실어 보내면 응답의 `favorite` 필드가 실제 즐겨찾기 여부로
  채워지고, 안 보내거나 무효 토큰이면 그냥 `false`로 내려간다(에러 아님).
- **음식점 관련 데이터(이름/주소/좌표/카테고리/전화번호)는 우리 서버가 저장하지 않고 카카오 로컬 API를
  매 요청마다 실시간으로 호출해서 그 자리에서 만들어 응답한다** — 이 때문에 아래 API들이 일반적인 REST API와
  다른 제약이 몇 가지 있으니 2장을 꼭 읽고 연동해달라(001-07 2장 참고).
- 사업자 등록(전화/영업시간/메뉴/사진 쓰기) API는 로그인 필수 + 그 음식점의 ACTIVE 관리자만 가능하며, 이번
  가이드에서는 조회 계열만 다룬다(쓰기 API는 001-02 5-8장 참고, 이번 가이드 범위 밖).

------------------------------------------------------------------------
## 2. 꼭 알아야 할 제약 3가지
------------------------------------------------------------------------
### 2-1. 목록/검색은 항상 "지금 지도가 보여주는 범위"가 필요하다
카카오 로컬 API 자체가 좌표 기반 검색만 지원해서, `GET /api/restaurants/filter`는 지도 뷰포트 좌표
(`minLat`/`maxLat`/`minLng`/`maxLng`) **4개가 전부 필수**다(하나라도 빠지면 `400 INVALID_INPUT`). 지도를
옮기거나 줌할 때마다(예: 네이버 지도의 `idle` 이벤트) 현재 뷰포트로 다시 호출해서 마커를 새로 그리는 방식으로
연동해야 한다 — "한 번 불러온 목록을 계속 쓰다가 필요할 때만 갱신" 방식은 쓸 수 없다(캐싱 자체를 하지 않음).

### 2-2. 상세 조회 시 "지금 갖고 있는 데이터"를 같이 실어 보내야 한다
카카오 로컬 API에는 장소 id로 단건을 다시 조회하는 기능이 없다. 그래서 `GET /api/restaurants/{restaurantId}`를
호출할 때, **검색 결과 카드/마커를 클릭하는 시점에 이미 갖고 있던 `name`/`address`/`roadAddress`/`latitude`/
`longitude` 값을 쿼리 파라미터로 그대로 같이 보내야** 상세 화면에 정상적으로 채워진다. 이 값들 없이 호출하면
그 필드들은 `null`로 내려간다(에러는 아님).

### 2-3. `categoryId`는 하드코딩하지 말 것
카테고리 목록은 서버가 부팅할 때마다 auto-increment 값이 달라질 수 있으므로, 화면 진입 시 반드시
`GET /api/restaurants/categories`를 먼저 호출해서 받은 `categoryId`를 그대로 필터 버튼에 매핑해서 써야 한다.

## 3. 기능별 호출 흐름
------------------------------------------------------------------------
### 3-1. 지도 최초 진입
1. `GET /api/restaurants/categories`로 카테고리 버튼 목록을 받아 렌더링
2. 현재 지도 뷰포트로 `GET /api/restaurants/filter?minLat=...&maxLat=...&minLng=...&maxLng=...`(카테고리/가격대
   조건 없이) 호출해서 마커를 표시 — 별도의 "동기화" 버튼/로딩 없이 진입 즉시 호출(001-07 3-4장, 캐시가 없어
   지연 없는 실시간 응답을 그대로 보여주는 게 자연스럽다고 판단)

### 3-2. 지도를 움직였을 때("이 지역에서 검색")
1. 지도 `idle`(이동/줌 종료) 이벤트에서 현재 뷰포트로 3-1의 2번을 다시 호출
2. 검색창에 입력된 키워드가 있으면 필터 대신 3-3(검색)을 호출(검색과 카테고리 필터는 상호 배타 — 하나를
   쓰면 다른 쪽 입력을 프론트에서 초기화해줄 것을 권장, 지도 테스트 페이지도 이렇게 동작)

### 3-3. 검색창(가게명 + 메뉴명 통합)
1. 사용자가 검색어를 입력하고 엔터/버튼 클릭 시 `GET /api/restaurants/search?keyword=...&minLat=...&maxLat=...
   &minLng=...&maxLng=...` 호출(뷰포트 파라미터는 선택이지만, 넘기면 그 범위로 편향된 결과를 받는다 —
   3-1장 참고)
2. 응답에는 **가게명이 검색어를 포함하는 음식점**과 **그 검색어를 메뉴명으로 파는 음식점**이 하나의 목록으로
   합쳐져서 내려온다(백엔드가 카카오 키워드 검색 + 우리 DB 메뉴명 검색을 내부에서 병합, 001-07 3-3장) —
   프론트는 구분 없이 그대로 마커/리스트로 렌더링하면 됨
3. `keyword`만 있고 뷰포트가 없으면 전국 대상 검색(메뉴명 매칭은 이 경우 동작하지 않음 — 좌표가 있어야
   하는 로직이라, 001-07 3-3장)

### 3-4. 카테고리/가격대 필터
1. 카테고리 버튼 클릭 시 `GET /api/restaurants/filter?categoryId=...&minLat=...&maxLat=...&minLng=...&maxLng=...`
2. 가격대까지 같이 걸고 싶으면 `minPrice`/`maxPrice`(그 음식점 메뉴 평균가 기준) 추가
3. 검색창을 쓸 때는 이 필터 상태를 초기화(2-1장 상호 배타)

### 3-5. 마커 클릭 → 상세 패널
1. 목록/검색/필터 응답의 항목(카드/마커)을 클릭하면, 그 항목이 가진 `name`/`address`/`roadAddress`/
   `latitude`/`longitude`를 그대로 쿼리 파라미터에 실어 `GET /api/restaurants/{restaurantId}?name=...&address=
   ...&roadAddress=...&latitude=...&longitude=...` 호출(2-2장 필수)
2. 응답의 `menus`/`businessHours`가 빈 배열이면 "메뉴/영업시간 정보가 없습니다"처럼 프론트에서 표시
3. 이 상세 화면에서 이어서 리뷰 목록/작성(별도 문서, `docs/10.리뷰` 참고)과 영수증 업로드(08 문서)로 연결됨

### 3-6. 메뉴만 다시 불러오기(선택)
"메뉴 더보기" 같은 화면이 있으면 `GET /api/restaurants/{restaurantId}/menus`로 메뉴만 별도 재조회 가능(상세
조회에도 이미 포함돼 있어 필수는 아님).

## 4. API 상세
------------------------------------------------------------------------
### 4-1. 카테고리 목록
```
GET http://localhost:8081/api/restaurants/categories
```
응답(200): `[ { "categoryId": 1, "categoryCode": "KOREAN", "categoryName": "한식" }, ... ]`

### 4-2. 목록/검색/필터 공통 응답 형식
아래 세 API 전부 같은 형식으로 응답한다.
```json
{
  "success": true, "page": 0, "size": 20, "totalCount": 42,
  "restaurants": [
    {
      "restaurantId": "16421356", "name": "농민백암순대 강남직영점", "category": "한식",
      "roadAddress": "...", "address": "...", "latitude": 37.123, "longitude": 127.456,
      "naverPlaceUrl": "https://place.map.kakao.com/16421356",
      "imageUrl": null, "averageRating": 4.5, "reviewCount": 3, "favorite": false
    }
  ]
}
```
`restaurantId`는 이제 숫자가 아니라 **카카오 장소 id 문자열**이다. `naverPlaceUrl` 필드명은 과거 네이버
연동 시절 이름이 그대로 남아있는 것뿐이고, 실제 값은 **카카오** 장소 상세 URL이다(필드명 자체를 바꾸면
프론트 코드도 같이 바뀌어야 해서 이번엔 값만 교체, 향후 정리 여지 있음). `imageUrl`은 사업자가 직접
등록하기 전까지 `null`(001-02 5-0장의 "이미지는 예외적으로 기본값 대체" 규칙은 아직 실제 기본 이미지
자산이 없어 현재는 그냥 `null`로 내려감).

### 4-3. 음식점 목록
```
GET http://localhost:8081/api/restaurants?page=0&size=20
```
뷰포트 없이 부르면 카카오 API 특성상 사실상 임의의(또는 빈) 결과가 나올 수 있다 — **실제 화면에서는
3장의 흐름대로 `filter`를 뷰포트와 함께 쓰는 것을 권장**하고, 이 API는 참고용으로만 남겨둠.

### 4-4. 검색
```
GET http://localhost:8081/api/restaurants/search?keyword=써브웨이&minLat=37.49&maxLat=37.51&minLng=127.02&maxLng=127.05&page=0&size=20
```
`keyword` 생략 시 빈 목록 반환(전체 목록으로 대체되지 않음 — 검색창이 비어있을 땐 프론트가 이 API를
호출하지 않는 것을 권장). 응답 형식은 4-2장과 동일.

### 4-5. 필터
```
GET http://localhost:8081/api/restaurants/filter?categoryId=1&minPrice=8000&maxPrice=15000&minLat=37.49&maxLat=37.51&minLng=127.02&maxLng=127.05&page=0&size=20
```
`minLat`/`maxLat`/`minLng`/`maxLng` 넷 중 하나라도 빠지면:
```json
{ "success": false, "code": "INVALID_INPUT", "message": "..." }
```
(400)

### 4-6. 상세 조회
```
GET http://localhost:8081/api/restaurants/16421356?name=농민백암순대%20강남직영점&address=...&roadAddress=...&latitude=37.123&longitude=127.456
```
응답(200):
```json
{
  "success": true, "restaurantId": "16421356", "name": "농민백암순대 강남직영점", "category": "한식",
  "description": null, "roadAddress": "...", "address": "...", "latitude": 37.123, "longitude": 127.456,
  "phone": null, "naverPlaceUrl": "https://place.map.kakao.com/16421356", "imageUrl": null,
  "businessStatus": "OPEN", "averageRating": 4.5, "reviewCount": 3, "favorite": false,
  "categories": ["한식"], "tags": [], "businessHours": [], "menus": []
}
```
`name`/`address`/`roadAddress`/`latitude`/`longitude` 쿼리 파라미터 없이 호출하면 그 필드들만 `null`로
내려가고 나머지(카테고리/리뷰/메뉴 등 우리 DB의 부가정보)는 정상적으로 채워진다 — 완전히 실패하지는 않음.

### 4-7. 메뉴 조회
```
GET http://localhost:8081/api/restaurants/16421356/menus
```
응답(200): `{ "success": true, "restaurantId": "16421356", "menus": [ { "menuId": 10, "menuName": "...", "price": 9000, ... } ] }`

### 4-8. 주변 조회
```
GET http://localhost:8081/api/restaurants/nearby?latitude=37.5665&longitude=126.9780&radiusKm=1.5
```
`radiusKm` 생략 시 1km. 응답 형식은 4-2장 + `distanceKm` 필드 추가, 거리순 정렬.

## 5. 에러 코드
------------------------------------------------------------------------
| 코드 | 상황 | HTTP |
|---|---|---|
| RESTAURANT_NOT_FOUND | 상세 조회 대상이 소프트 삭제된 경우(드뭄 — 평소엔 없으면 그냥 부가정보 없이 조회됨) | 404 |
| INVALID_INPUT | 필터 API에 뷰포트 4개 중 일부 누락, 페이지/좌표 값 형식 오류 등 | 400 |
| KAKAO_LOCAL_SEARCH_FAILED | 카카오 로컬 API 호출 자체가 실패(네트워크/키 문제) — 이 경우 결과가 빈 배열로 내려갈 수도 있음(요청 성격에 따라 다름) | 500 |
