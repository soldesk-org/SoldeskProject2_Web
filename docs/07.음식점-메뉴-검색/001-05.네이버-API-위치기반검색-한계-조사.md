# 네이버 API로 "현재 지도 범위 기준 음식점 검색"이 안 되는 이유 (조사 결과)
------------------------------------------------------------------------
2026-07-20 요청사항 논의 중 나온 "검색창에 키워드 입력 → 지금 보고 있는 지도 범위 안에서 그 키워드로 음식점을 찾아
지도에 마커+옆에 리스트로 표시" UX가, 네이버가 공식적으로 제공하는 API만으로 구현 가능한지 조사한 결과.
**결론: 불가능함 — 네이버가 이 기능을 서드파티 개발자에게 공개한 적이 없음.** 우리 구현이 부족해서가 아니라
플랫폼 자체의 한계이며, 아래에 그 근거를 정리한다.

> **참고(2026-07-22)**: 이 조사 결과가 이후 카카오 로컬 API로 데이터 소스를 완전히 교체하는 결정의 배경이
> 되었음 — 카카오는 좌표/반경 기반 검색을 공식 지원. 최종 전환 내용은
> [001-07.카카오-로컬-API-전환-및-리뷰-기능-구현.md](001-07.카카오-로컬-API-전환-및-리뷰-기능-구현.md) 참고.

------------------------------------------------------------------------
## 1. 결론
------------------------------------------------------------------------
네이버가 외부 개발자에게 공개한 API 중, "위도/경도(또는 지도 범위) + 키워드"로 주변 장소를 검색할 수 있는 API는
**단 하나도 없다.** 이미 이 프로젝트에 붙여둔 지역 검색 API(`NaverLocalSearchClient`)도, 그 대안으로 검토했던
네이버 지도 API(NCP Maps, 유료 상품)도 마찬가지다. 스크린샷에서 보이는 "지도 범위 기준 검색"은 네이버 지도
앱/플레이스 자체의 내부 기능이고, 외부에는 공개돼 있지 않다.

------------------------------------------------------------------------
## 2. 근거 1 — 지역 검색 API(현재 이 프로젝트가 쓰고 있는 것)
------------------------------------------------------------------------
`Project2/.../restaurant/client/NaverLocalSearchClient.java`에서 실제로 호출하고 있는 API
(`GET https://openapi.naver.com/v1/search/local.json`)를 기준으로 확인.

### 2-1. 파라미터 자체에 위치 개념이 없음
공식 문서/여러 구현 사례를 확인한 결과, 이 API가 받는 파라미터는 **`query`(검색어), `display`(출력 건수),
`start`(시작 위치), `sort`(정렬)뿐이다.** 위도/경도, 반경(radius), bounding box 같은 "위치를 좁히는" 파라미터가
애초에 존재하지 않는다. 순수하게 "전국 기준으로 이 키워드와 관련도 높은 곳 몇 개"를 돌려주는 구조다.

### 2-2. `display`가 트래픽 문제로 최대 5개까지만 허용됨
"트래픽 문제로 최대 출력 건수(display)를 5개로 제한한다"는 게 네이버 쪽에서 명시한 정책으로 확인됨 — 임의 제한이
아니라 공지된 사양. 이 프로젝트의 `NaverLocalSearchClient`에도 `MAX_DISPLAY = 5`로 이미 반영돼 있음
(`// 지역 검색 API는 display 최대 5까지만 허용(공식 문서 기준).`).

### 2-3. `start`로 페이지를 넘겨도 "위치 필터"가 생기는 게 아님
`start` 파라미터로 다음 페이지(6번째~10번째 결과 등)를 요청하는 것 자체는 가능하다는 사례를 확인했다. 하지만
이건 "더 많은 전국 결과를 순서대로 더 보는 것"이지, 그 추가 결과들이 지금 보고 있는 지도 범위 안으로 좁혀지는 게
아니다 — 애초에 위치 조건이 없는 API라 페이지를 넘겨도 위치 관련성은 그대로 없다.

------------------------------------------------------------------------
## 3. 근거 2 — 네이버 지도 API(NCP Maps, 유료 상품) 쪽도 확인
------------------------------------------------------------------------
"그럼 지역 검색 API 말고 네이버 지도 API 쪽에는 주변 검색이 있지 않을까?"를 확인하기 위해 공식 API 가이드
(`https://api.ncloud-docs.com/docs/application-maps-overview`)를 직접 확인함.

**공식적으로 제공되는 Maps API 목록은 다음 6개뿐이다**:
1. Dynamic Map (동적 지도 이미지)
2. Static Map (정적 지도 이미지)
3. Geocoding (주소 → 좌표)
4. Reverse Geocoding (좌표 → 주소)
5. Directions 5 (경로 탐색, 경유지 최대 5개)
6. Directions 15 (경로 탐색, 경유지 최대 15개)

**"주변 장소 검색"이나 좌표 기반으로 근처 음식점/장소를 찾는 API는 이 목록에 없다.** 네이버 클라우드 플랫폼
상품 소개 페이지(ncloud.com)에 "주변 장소 정보(POI) 제공"이라는 마케팅 문구가 있어서 혹시나 하고 확인했지만,
이건 **지도 타일 자체가 화면에 마커를 그려서 보여주는 시각적 기능**을 설명하는 것이지, 개발자가 좌표로 질의해서
"이 근처 장소 목록을 JSON으로 달라"고 요청할 수 있는 API가 아니었다. `naver.maps.Service` 객체(지도 API v3의
서버 API 래퍼)가 제공하는 메서드도 geocode/reverseGeocode 두 가지뿐이었다.

------------------------------------------------------------------------
## 4. 근거 3 — 실제로 같은 걸 시도했던 다른 개발자 사례
------------------------------------------------------------------------
"스프링부트 네이버 지역검색 API를 활용한 맛집 리스트 만들기"라는, 이 프로젝트와 거의 동일한 목적(네이버 지역
검색 API로 맛집 리스트 서비스 구현)의 개발 블로그 시리즈를 확인함.

- 이 구현에서도 **위치 기반(위도/경도, 지도 범위) 검색은 구현되지 않았다** — 요청 파라미터가 `query`/`display`/
  `start`/`sort`뿐이라 애초에 할 수가 없었던 것으로 보임(우리와 동일한 제약).
- `display`는 "검색 결과 출력 건수 지정(1~5)"로 명시.
- DB는 검색 결과 자체를 저장하는 용도가 아니라, **사용자가 결과 중에서 직접 선택한 항목을 "위시리스트"로
  저장**하는 용도로만 쓰였다 — 즉 검색/탐색은 매번 네이버 API를 실시간으로 호출하고, DB는 부가 기능(찜하기)에만
  쓰는 구조. 이건 이번 프로젝트가 검토 중인 방향("검색은 라이브 API 호출, DB는 사업자 등록 정보 보관용")과
  본질적으로 같은 결론에 다른 팀도 독립적으로 도달했다는 뜻으로 볼 수 있음.

------------------------------------------------------------------------
## 5. 그래서 실무적으로 가능한 선택지
------------------------------------------------------------------------
네이버 API를 그대로 쓰면서 최대한 요구사항에 가깝게 만들 수 있는 현실적인 방법:

1. **검색은 매 요청마다 네이버 API를 실시간으로 호출**(사전 동기화/캐싱 없음) — "DB에서 꺼내온다"는 인상을
   피하면서 네이버 API를 그대로 활용하는 부분은 그대로 유지 가능
2. **위치는 "필터"가 아니라 "검색어에 섞어서 유도"하는 방식으로 근사**: 예) 프론트가 현재 지도 중심 좌표를
   Reverse Geocoding으로 동/구 이름으로 바꾼 뒤, `"강남구 빙수"`처럼 검색어에 지역명을 합쳐서 요청. 다만 이건
   진짜 "그 범위 안에 있는 것만" 걸러주는 게 아니라 관련도 순위에 영향을 주는 정도의 힌트일 뿐임
3. **최대 5개(또는 페이지 넘겨서 조금 더)라는 결과 개수 제한은 그대로 받아들여야 함** — 스크린샷처럼 지도에
   10개 넘는 마커가 촘촘히 뜨는 화면은 이 API로는 원천적으로 안 나옴
4. **메뉴/가격/전화번호/영업시간/리뷰/가게사진처럼 네이버가 아예 안 주는 정보**는 사업자가 직접 등록한 값을
   저장해뒀다가 매칭해서 보여주는 것 외에는 방법이 없음(네이버 API 응답 자체에 없는 데이터라 그 어떤 방식으로도
   네이버에서 실시간으로 가져올 수 없음) — 이건 "검색 결과를 DB에서 가져오는 것"과는 다른 성격(사업자가 직접
  입력한 부가정보 보관)이라는 점을 구분해서 봐야 함
