# Docker 컨테이너화 — 현황 및 보류 결정 (2026-08-14)

------------------------------------------------------------------------
## 배경
------------------------------------------------------------------------
지금까지 이 프로젝트에서 Docker는 Redis 하나만(`soldesk-redis` 컨테이너, `~/redis/docker-compose.yml`)
간단히 쓰고 있었고, Spring Boot 앱 자체는 이미지화하지 않은 채 Jenkins가 war 파일을 VM에 복사해
`java -jar`로 직접 실행하는 방식이었다(`Jenkinsfile` 참고). "실무에서 쓰는 형태의 Docker화가 아니다"라는
문제의식으로 이번에 다시 논의됨.

- 웹앱(Spring Boot + Redis) 자체를 제대로 컨테이너화하는 건 GPU가 필요 없고, 반나절 정도면 충분한 작업.
- 다만 팀원이 확인해온 견적(GPU 서버·드라이버 준비에 반나절~1일)은 저희 웹앱이 아니라 **AI 추천
  Python 서버**(CUDA GPU 필요) 쪽 얘기였음 — 두 작업을 혼동하지 않도록 이 문서에 분리해서 기록.

## 이번 세션의 결정 — 보류
------------------------------------------------------------------------
사용자 지시: "아 일단 Docker는 보류 해놔". 그래서 이번 세션에서는:
- `feature/web-docker`/`feature/py-docker` 브랜치만 신규로 만들어둠(둘 다 웹/Python 저장소 각각,
  `develop` 기준).
- 팀원이 `develop`에 올려둔 위 커밋들은 그대로 두고 **손대지 않음**.
- `main`↔`develop`을 언제 어떻게 합칠지는 아직 결정 안 됨 — Docker 작업을 이어서 진행하기로 하면
  그때 `develop`을 검토해서 `main`으로 가져오거나, 반대로 `main`의 최신 작업을 `develop`으로 가져와
  그 위에서 Docker화를 마저 진행하는 방향을 다시 논의해야 함.
