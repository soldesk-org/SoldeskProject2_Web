## 1. 서버 접속 정보
------------------------------------------------------------------------
- Spring 로컬 개발 서버: `http://localhost:8081`(기존과 동일)
- WebSocket(STOMP) 엔드포인트: `ws://localhost:8081/ws-chat`(HTTPS로 붙었다면 `wss://`)
- 클린봇용 필터 Python 서버(17과 동일, 선택): `http://localhost:8002` — 꺼져 있어도 채팅은 되고 클린봇만
  동작 안 함(fail-open)

------------------------------------------------------------------------
## 2. 프론트 연동 흐름
------------------------------------------------------------------------
1. `POST /api/chat/rooms`(방 생성) 또는 `POST /api/chat/rooms/join`(참가코드로 입장)으로 `chatRoomId` 획득
2. `GET /api/chat/rooms/{roomId}/messages`로 최근 대화 50건을 먼저 불러와 화면에 표시
3. WebSocket(STOMP)에 연결 — CONNECT 프레임의 커스텀 헤더로 accessToken을 실어 보내야 함:
   ```js
   const client = new StompJs.Client({
     brokerURL: 'ws://localhost:8081/ws-chat',
     connectHeaders: { Authorization: 'Bearer ' + accessToken },
     onConnect: () => {
       client.subscribe(`/topic/rooms/${roomId}`, frame => { /* 메시지 렌더링 */ });
       client.subscribe('/user/queue/errors', frame => { /* 에러 안내(클린봇 거부 등) */ });
     }
   });
   client.activate();
   ```
4. 메시지 전송:
   ```js
   client.publish({ destination: `/app/rooms/${roomId}/send`, body: JSON.stringify({ content: text }) });
   ```
5. 방을 나갈 땐 `POST /api/chat/rooms/{roomId}/leave`, 방장이 방을 없애고 싶으면
   `DELETE /api/chat/rooms/{roomId}`(방 폭파, 방장만 가능)
6. 신고 버튼은 메시지/방 둘 다에 노출 — `POST /api/chat/messages/{messageId}/report` 또는
   `POST /api/chat/rooms/{roomId}/report`

------------------------------------------------------------------------
## 3. 알아둘 것
------------------------------------------------------------------------
1. WebSocket CONNECT 시 토큰이 없거나 무효하면 연결 자체가 거부된다 — 로그인 안 한 상태로는 오픈채팅을
   아예 쓸 수 없다(REST의 "로그인 필수 아님" API들과 다름).
2. 메시지 전송이 실패해도(클린봇에 걸림, 방에서 나간 뒤 등) 방 전체(`/topic/rooms/{roomId}`)에는 아무
   것도 오지 않는다 — 실패 알림은 보낸 사람만 구독하는 `/user/queue/errors`로 온다. 이 구독을 안 걸어두면
   전송 실패를 사용자가 알 방법이 없으니 반드시 같이 구독할 것.
3. `/topic/rooms/{roomId}`로 오는 메시지의 `type` 필드로 네 가지를 구분해야 한다:
   - `MESSAGE`: 일반 메시지
   - `SYSTEM`: 안내만 하면 되는 범용 공지(`memberId`/`nickname`이 `null`)
   - `DELETED`(2026-07-24 후속 추가): 관리자가 메시지를 강제 삭제했을 때 옴, `chatMessageId`만 채워져 있고
     나머지 필드는 `null` — 새 말풍선을 추가하지 말고, 이미 화면에 그려진 그 `chatMessageId`의 말풍선을
     찾아 "삭제된 메시지입니다" 등으로 바꿔야 한다(완전히 지우지 않는 걸 권장 - 대화 흐름 유지)
   - `ROOM_CLOSED`(2026-07-24 3차 후속): 방이 폭파됐을 때 옴 — 안내만 하고 끝나면 안 되고, **그 방에서
     즉시 나가야 한다**(구독 해제, 화면을 메인/빈 상태로 전환, 방 목록 다시 조회). 방장이 직접 폭파를
     눌렀어도 방장 본인의 화면도 이 이벤트로 정리해야 한다(REST 응답만으로 화면을 정리하지 말 것 — 소켓
     이벤트 하나로 통일하는 걸 권장, `chat-test.html`도 이렇게 구현돼 있음)
4. 방이 폭파(`status: CLOSED`)되면 `GET /api/chat/rooms/my` 목록에서 즉시 사라진다(2026-07-24 3차 후속 —
   더 이상 "폭파됨" 배지를 달고 남아있지 않음). 접속 중이던 사람은 `ROOM_CLOSED` 소켓 이벤트로 강제
   퇴장되므로, 프론트가 별도로 폭파된 방 상태를 화면에 유지할 필요가 없다.
5. 참가코드는 8자리가 기본값이고 대소문자 구분 없이(서버에는 항상 대문자로 저장) 입력받는 걸 권장 —
   `0/O`, `1/I/L`은 코드에 아예 안 쓰이므로 굳이 구분 안내는 필요 없음.
6. 방 생성 시 `maxMembers`를 생략하면 5명이 기본값(2026-07-24 4차 후속). 정원이 찬 방에 입장 시도하면
   `409 CHAT_ROOM_FULL`이 온다 — "정원이 가득 찼습니다" 같은 안내를 보여주고 입장 버튼을 막으면 된다.

## 4. API 상세
------------------------------------------------------------------------
### 4-1. 방 생성
```
POST http://localhost:8081/api/chat/rooms
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "title": "강남 맛집 오픈채팅", "maxMembers": 5 }
```
`maxMembers`는 선택(2~50 사이), 생략하면 5.

응답(200)
```json
{
  "chatRoomId": 1, "title": "강남 맛집 오픈채팅", "joinCode": "QYRYKWG3",
  "hostMemberId": 10, "hostNickname": "닉네임", "memberCount": 1, "maxMembers": 5, "status": "OPEN",
  "createdAt": "2026-07-24T16:58:27"
}
```

### 4-2. 참가코드로 입장
```
POST http://localhost:8081/api/chat/rooms/join
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "joinCode": "QYRYKWG3" }
```
실패(404, 없거나 폭파된 방)
```json
{ "success": false, "code": "CHAT_ROOM_NOT_FOUND", "message": "존재하지 않거나 폭파된 채팅방입니다." }
```

### 4-3. 내 채팅방 목록
```
GET http://localhost:8081/api/chat/rooms/my
Authorization: Bearer {accessToken}
```

### 4-4. 최근 메시지 조회
```
GET http://localhost:8081/api/chat/rooms/{roomId}/messages
Authorization: Bearer {accessToken}
```
응답: `ChatMessageResponseDto` 배열(오래된 순, 최대 50건)

### 4-5. 나가기 / 방 폭파
```
POST   http://localhost:8081/api/chat/rooms/{roomId}/leave
DELETE http://localhost:8081/api/chat/rooms/{roomId}      (방장만, 아니면 403 CHAT_ROOM_ACCESS_DENIED)
```

### 4-6. 신고
```
POST http://localhost:8081/api/chat/rooms/{roomId}/report
POST http://localhost:8081/api/chat/messages/{messageId}/report
Content-Type: application/json

{ "reasonCode": "ABUSE", "detail": "선택 사항" }
```
`reasonCode`는 `SPAM`/`ABUSE`/`FALSE_INFO`/`PRIVACY`/`ETC` 중 하나(16.리뷰-신고와 동일 목록). 같은 대상을
같은 회원이 다시 신고하면 `409 CHAT_ALREADY_REPORTED`.

### 4-7. 관리자 - 채팅 신고 관리 (`/api/admin/**`, ADMIN 권한 필요)
```
GET    /api/admin/chat-reports?status=PENDING   (status 생략 시 PENDING, RESOLVED/REJECTED도 조회 가능)
PATCH  /api/admin/chat-reports/{chatReportId}/resolve
PATCH  /api/admin/chat-reports/{chatReportId}/reject
DELETE /api/admin/chat-messages/{chatMessageId}   (메시지 강제 삭제)
DELETE /api/admin/chat-rooms/{chatRoomId}         (방 강제 폭파)
```
`GET /api/admin/chat-reports` 응답 예시:
```json
[
  {
    "chatReportId": 1, "targetType": "MESSAGE", "chatRoomId": 1, "roomTitle": "강남 맛집 오픈채팅",
    "chatMessageId": 5, "reporterNickname": "닉네임", "reasonCode": "ABUSE", "detail": null,
    "contentSnapshot": "신고된 메시지 원문", "status": "PENDING", "createdAt": "2026-07-24T16:58:30"
  }
]
```

## 5. 에러 코드
------------------------------------------------------------------------
| code | 상황 | HTTP |
|---|---|---|
| CHAT_ROOM_NOT_FOUND | 없거나 폭파된 채팅방 | 404 |
| CHAT_ROOM_ACCESS_DENIED | 방장이 아닌데 폭파 시도 | 403 |
| CHAT_ROOM_NOT_MEMBER | 참가 중이지 않은 방에 접근 | 403 |
| CHAT_MESSAGE_NOT_FOUND | 메시지 없음 | 404 |
| CHAT_MESSAGE_CONTENT_REQUIRED | 빈 메시지 | 400 |
| CHAT_MESSAGE_PROFANITY | 클린봇에 걸림(WebSocket 에러 큐로 옴) | 400 |
| CHAT_ALREADY_REPORTED | 같은 대상 중복 신고 | 409 |
| CHAT_ROOM_FULL | 방 정원이 가득 참(2026-07-24 4차 후속) | 409 |

## 6. 테스트 페이지
------------------------------------------------------------------------
`chat-test.html` — 다른 테스트 페이지와 같은 `localStorage` 키(`tmp_test_access_token`)로 로그인 상태
공유. 방 생성/참가코드 입장/실시간 메시지/방장 전용 폭파 버튼/메시지·방 신고 모달을 모두 포함. 두 개의
브라우저(또는 시크릿 창)로 서로 다른 계정으로 로그인해서 열면 실시간 대화를 직접 확인할 수 있다.
