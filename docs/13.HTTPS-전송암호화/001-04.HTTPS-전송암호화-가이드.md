# HTTPS 전송 구간 암호화 - 실행/설정 가이드
------------------------------------------------------------------------
[001-02.HTTPS-전송암호화-분석-설계.md](001-02.HTTPS-전송암호화-분석-설계.md), [001-03.HTTPS-전송암호화-구현-테스트.md](001-03.HTTPS-전송암호화-구현-테스트.md) 참고

이 문서는 다른 기능 폴더의 "프론트엔드 연동 가이드"와 달리, API 스펙 문서가 아니라 **팀원이 로컬에서
HTTPS를 켜보는 방법**을 다룬다(이 기능은 API 계약을 바꾸지 않음, 001-02 4장).

------------------------------------------------------------------------
## 1. 기본값: 꺼져있음
------------------------------------------------------------------------
아무것도 안 하면 지금까지와 완전히 동일하게 동작한다 — `HTTPS_CONNECTOR_ENABLED`를 명시적으로 켜지 않으면
서버는 예전처럼 `http://localhost:8081`만 서비스한다(001-02 2-4장).

------------------------------------------------------------------------
## 2. 켜는 방법
------------------------------------------------------------------------
### 2-1. keystore 생성 (최초 1회, 팀원마다 각자)
JDK가 설치되어 있으면 `keytool`이 이미 있다(별도 설치 불필요). `Project2` 디렉터리에서:

```bash
mkdir -p keystore
keytool -genkeypair \
  -alias localhost \
  -keyalg RSA -keysize 2048 -validity 825 \
  -storetype PKCS12 \
  -keystore ./keystore/localhost.p12 \
  -storepass {원하는 비밀번호} -keypass {같은 비밀번호} \
  -dname "CN=localhost, OU=Eattyway Dev, O=Soldesk, L=Seoul, ST=Seoul, C=KR" \
  -ext "SAN=dns:localhost,ip:127.0.0.1"
```
- `-storepass`/`-keypass`는 같은 값으로(다르면 별도 설정 필요, 이 프로젝트는 같은 값 전제로 설계함)
- 이 파일(`keystore/localhost.p12`)은 개인키가 담긴 파일이라 **git에 절대 커밋하지 않는다**
  (`.gitignore`에 이미 `keystore/` 추가돼 있음) — 팀원마다 각자 생성해야 하고, 각자 생성한 인증서 값이
  달라도 상관없다(로컬 테스트 목적이라 팀 전체가 같은 인증서를 쓸 필요가 없음)

### 2-2. `.env`에 값 채우기
```
HTTPS_CONNECTOR_ENABLED=true
SSL_KEY_STORE_PASSWORD={2-1에서 정한 비밀번호}
```
`HTTPS_CONNECTOR_PORT`(기본 8443), `SSL_KEY_STORE`(기본 `./keystore/localhost.p12`), `SSL_KEY_STORE_TYPE`
(기본 `PKCS12`), `SSL_KEY_ALIAS`(기본 `localhost`)는 2-1의 예시 명령 그대로 따랐다면 생략해도 된다.

### 2-3. 서버 재기동 후 접속
```
https://localhost:8443/...
```
기존 `http://localhost:8081`도 그대로 살아있다(001-02 2-1장) — 소셜로그인 콜백처럼 외부에 등록된 URL은
계속 8081(HTTP)을 쓰고, 로그인 화면 등 직접 확인해보고 싶은 곳만 8443(HTTPS)으로 접속하면 된다.

------------------------------------------------------------------------
## 3. 브라우저 "안전하지 않음" 경고가 뜨는 것에 대해
------------------------------------------------------------------------
자체 서명 인증서라 브라우저가 신뢰하지 않는다는 경고를 보여준다 — **정상이다** (001-02 2-2장). Chrome
기준 "고급" → "localhost(안전하지 않음)로 이동" 클릭하면 넘어갈 수 있다. 이 경고는 "이 인증서를 내가
발급한 게 아니라 아무개가 임의로 서명한 것"이라는 뜻이지, TLS 암호화 자체가 작동하지 않는다는 뜻이
아니다 — 실제로 암호화되고 있다는 것은 001-03 2-3장에서 `openssl s_client`로 확인해뒀다.

------------------------------------------------------------------------
## 4. 개발자도구 Network 탭에는 왜 여전히 평문으로 보이나
------------------------------------------------------------------------
HTTPS를 켜도 브라우저 개발자도구의 Request Payload에는 비밀번호가 여전히 읽을 수 있는 형태로 보인다.
이건 정상이다 — 개발자도구는 "내 브라우저가 암호화하기 직전의 내 요청 내용"을 보여주는 디버깅 도구이지,
네트워크 위를 흐르는 실제 바이트를 보여주는 게 아니다(001-01 "먼저 짚어야 할 것" 참고). 진짜 확인하려면
Wireshark 같은 패킷 캡처 도구로 8443 포트의 트래픽을 봐야 하는데, TLS로 암호화된 패킷은 거기서도 알아볼
수 없는 바이트로 보인다(HTTP였다면 그 도구에서 비밀번호 문자열이 그대로 보였을 것).

------------------------------------------------------------------------
## 5. 테스트 페이지에서 그대로 사용 가능
------------------------------------------------------------------------
`mypage-test.html`, `foodbti-test.html`, `tmp-map-test.html`, `recommend-test.html` 등 기존 정적 테스트
페이지는 코드 수정 없이 그대로 `https://localhost:8443/{페이지명}`으로 열어도 정상 동작한다 — 전부 상대
경로(`API_BASE = ''`)로 API를 호출하고 있어서 페이지를 연 프로토콜(http/https)을 자동으로 따라간다(001-02
5장).

------------------------------------------------------------------------
## 6. 설정값 요약
------------------------------------------------------------------------
| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `HTTPS_CONNECTOR_ENABLED` | `false` | HTTPS 커넥터 켜기/끄기 |
| `HTTPS_CONNECTOR_PORT` | `8443` | HTTPS 포트 |
| `SSL_KEY_STORE` | `./keystore/localhost.p12` | keystore 파일 경로 |
| `SSL_KEY_STORE_PASSWORD` | (없음, 필수) | keystore 비밀번호 |
| `SSL_KEY_STORE_TYPE` | `PKCS12` | keystore 형식 |
| `SSL_KEY_ALIAS` | `localhost` | 인증서 별칭 |
