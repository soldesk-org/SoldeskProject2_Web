## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
  - ※ 8080이 아니라 **8081**입니다 (로컬 환경에 다른 프로세스가 8080을 점유하고 있어 변경됨)
- Base path: `/api`
- 아직 인증(JWT/세션) 붙기 전이라 별도 헤더 없이 호출하면 됩니다. `Content-Type: application/json` 필수.

------------------------------------------------------------------------
## 2. 회원가입 흐름 (호출 순서)
------------------------------------------------------------------------
1. `POST /api/mail/send-code` — 이메일 입력 후 인증번호 발송
2. `POST /api/mail/verify-code` — 사용자가 받은 인증번호 6자리 입력 → 확인
3. `POST /api/phone/send-code` — (2026-07-18 추가) 전화번호 입력 후 SMS 인증번호 발송. 2번에서 이메일 인증이 완료된 상태여야 호출 가능
4. `POST /api/phone/verify-code` — 사용자가 받은 SMS 인증번호 6자리 입력 → 확인
5. `POST /api/members/signup` — 나머지 정보(비밀번호/닉네임) 입력 후 최종 가입

5번은 2번(이메일 인증)과 4번(전화번호 인증)이 **둘 다** 완료된 상태여야 성공합니다. 특히 4번에서 인증한 전화번호와 5번에 실어 보내는 `phone`이 정확히 같아야 합니다(다르면 인증 안 한 것으로 처리됨).

> **(2026-07-18 기준) 3~4번은 아직 실제로 동작하지 않습니다.** SMS 발송 대행사(뿌리오) 계정 발급이 완료되지 않아, 지금 호출하면 서버에서 `SMS_SEND_FAIL`로 실패합니다. 프론트 개발/화면 작업은 API 스펙(3장) 기준으로 진행하시되, 실제 연동 테스트는 계정 발급 완료 안내가 갈 때까지 보류해주세요.

### 2-1. 사업자 회원가입 (2026-07-19 추가, 별도 화면)
"일반 회원가입"과 "사업자 회원가입"은 화면/엔드포인트가 다릅니다. 사업자는 위 1~4번(이메일/전화번호 인증)까지 **완전히 동일하게** 거친 다음, 5번 자리에 아래 엔드포인트가 대신 들어갑니다.

5-비즈) `POST /api/members/signup/business` — 비밀번호/닉네임 + **사업자등록증명원 파일**을 함께 업로드해서 최종 가입 (자세한 스펙은 3-6장)

> **이 API도 현재 실제로 동작하지 않습니다.** 사업자등록증명원을 검증(OCR+원본확인+진위확인)하는 별도 서버가 아직 이 환경에 기동되어 있지 않아, 이메일/전화번호 인증까지 다 통과해도 마지막 단계에서 `BUSINESS_VERIFY_SERVICE_UNAVAILABLE`로 실패합니다. 화면 작업은 아래 스펙 기준으로 진행하시고, 실제 연동 테스트는 별도 안내 때까지 보류해주세요.

### 2-2. 프로필 사진 등록 (2026-07-19 추가)
회원가입 API(위 5번, 5-비즈 둘 다)에는 사진을 함께 보낼 수 없습니다 — **가입 화면에서 사진을 고른 경우, 가입(5번) → 로그인(`POST /api/members/login`)까지 마친 뒤 그 `accessToken`으로 [005.회원정보수정의 프로필 사진 업로드 API](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md#3-8-프로필-사진-등록변경-2026-07-19-추가)(`POST /api/members/me/profile-image`)를 한 번 더 호출**해주세요. 사진은 선택 항목이라 안 골라도 가입에는 지장 없습니다.

## 3. API 상세
------------------------------------------------------------------------
### 3-1. 이메일 인증번호 발송
```
POST http://localhost:8081/api/mail/send-code
Content-Type: application/json

{
  "email": "user@example.com"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "인증번호가 발송되었습니다." }
```

### 3-2. 이메일 인증번호 확인
```
POST http://localhost:8081/api/mail/verify-code
Content-Type: application/json

{
  "email": "user@example.com",
  "code": "123456"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "이메일 인증이 완료되었습니다." }
```

### 3-3. 전화번호 SMS 인증번호 발송 (2026-07-18 추가, 현재 실제 발송 불가 — 2장 참고)
```
POST http://localhost:8081/api/phone/send-code
Content-Type: application/json

{
  "email": "user@example.com",
  "phone": "010-1234-5678"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "인증번호가 발송되었습니다." }
```
`email`은 3-2에서 이메일 인증을 완료한 그 이메일이어야 합니다(아니면 `EMAIL_NOT_VERIFIED`).

### 3-4. 전화번호 SMS 인증번호 확인
```
POST http://localhost:8081/api/phone/verify-code
Content-Type: application/json

{
  "email": "user@example.com",
  "phone": "010-1234-5678",
  "code": "123456"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "전화번호 인증이 완료되었습니다." }
```

### 3-5. 회원가입
```
POST http://localhost:8081/api/members/signup
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "P@ssw0rd1",
  "passwordConfirm": "P@ssw0rd1",
  "nickname": "홍길동",
  "phone": "010-1234-5678"
}
```
성공 응답 (200)
```json
{ "success": true, "message": "회원가입이 완료되었습니다.", "memberId": 1 }
```
`phone`은 3-4에서 인증에 성공한 그 전화번호와 정확히 같아야 합니다(다르면 `PHONE_NOT_VERIFIED`).
`passwordConfirm`(2026-07-19 추가)은 `password`와 정확히 같은 값이어야 합니다(다르면 `PASSWORD_CONFIRM_MISMATCH`) — 화면에 "비밀번호 확인" 입력칸을 하나 더 두고, 두 값을 그대로 각 필드에 실어 보내면 됩니다.

### 3-6. 사업자 회원가입 (2026-07-19 추가, 현재 실제 동작 불가 — 2-1장 참고)
일반 회원가입(3-5)과 달리 **JSON이 아니라 `multipart/form-data`**로 보내야 합니다(파일을 같이 실어야 하므로).
```
POST http://localhost:8081/api/members/signup/business
Content-Type: multipart/form-data

email: user@example.com
password: P@ssw0rd1
passwordConfirm: P@ssw0rd1
nickname: 홍길동상회
phone: 010-1234-5678
businessLicenseFile: (사업자등록증명원 파일, PDF 또는 이미지)
```
성공 응답 (200) — 일반 회원가입과 동일한 응답 형식
```json
{ "success": true, "message": "사업자 회원가입이 완료되었습니다.", "memberId": 1 }
```
- `email`/`phone`은 2-1장의 이메일·전화번호 인증 단계에서 사용한 값과 정확히 같아야 합니다(일반 회원가입과 동일한 규칙).
- `businessLicenseFile`은 필수입니다. 빠뜨리면 `INVALID_INPUT`이 납니다.
- 각 브라우저의 `FormData`로 이 필드들을 채워서 보내면 됩니다(파일 입력 `<input type="file">` 값을 `businessLicenseFile` 키로 append).

## 4. 입력값 검증 규칙 (프론트 단에서도 동일하게 미리 검증 추천)
------------------------------------------------------------------------
| 필드 | 규칙 |
|---|---|
| email | 이메일 형식, 최대 100자 |
| password | 8~20자, 영문+숫자+특수문자 모두 포함 |
| passwordConfirm (2026-07-19 추가) | 필수값, `password`와 정확히 일치해야 함 |
| nickname | 한글/영문/숫자 2~10자 (특수문자 불가) |
| phone | `010-XXXX-XXXX` 형식 (하이픈 포함해서 그대로 전송) |
| code | 숫자 6자리 |
| businessLicenseFile (사업자 회원가입, 2026-07-19 추가) | 필수, PDF 또는 이미지 파일. 서버 쪽 업로드 용량 제한은 10MB |

## 5. 에러 응답 형식
------------------------------------------------------------------------
모든 에러는 아래 형식으로 내려옵니다. HTTP status와 `code`로 분기 처리하면 됩니다.
```json
{ "success": false, "code": "DUPLICATE_EMAIL", "message": "이미 가입된 이메일입니다." }
```

| code | 상황 | HTTP Status |
|---|---|---|
| INVALID_INPUT | 입력값 형식 오류 (검증 실패한 첫 필드명이 message에 포함됨) | 400 |
| EMAIL_NOT_FOUND | 인증번호 발송 이력이 없는 이메일로 확인/가입 요청 | 400 |
| EMAIL_NOT_VERIFIED | 이메일 인증 미완료 상태로 가입 시도 | 400 |
| INVALID_CODE | 인증번호 불일치 | 400 |
| EXPIRED_CODE | 인증번호 만료 (발급 후 5분) | 400 |
| PHONE_NOT_FOUND | SMS 발송 이력이 없거나, 발송했던 것과 다른 전화번호로 확인 요청 (2026-07-18 추가) | 400 |
| PHONE_NOT_VERIFIED | 전화번호 인증 미완료 상태로 가입 시도 (2026-07-18 추가) | 400 |
| PASSWORD_CONFIRM_MISMATCH | 비밀번호와 비밀번호 확인이 다름 (2026-07-19 추가) | 400 |
| DUPLICATE_EMAIL | 이메일 중복 (이미 가입됐거나 인증 진행 중) | 409 |
| DUPLICATE_NICKNAME | 닉네임 중복 | 409 |
| DUPLICATE_PHONE | 전화번호 중복 | 409 |
| ALREADY_SIGNED_UP | 이미 가입 완료된 회원(재가입 시도) | 409 |
| DUPLICATE_BUSINESS_NUMBER (2026-07-19 추가) | 이미 등록된 사업자등록번호 (사업자 회원가입) | 409 |
| BUSINESS_VERIFICATION_FAILED (2026-07-19 추가) | 사업자등록증명원 검증 실패 (OCR 인식 실패/원본 아님/진위확인 실패 등, `message`에 구체적 사유가 담김) | 400 |
| MAIL_SEND_FAIL | 메일 발송 실패 (서버 측 문제, 재시도 안내 필요) | 500 |
| SMS_SEND_FAIL | SMS 발송 실패 (2026-07-18 추가, 현재 뿌리오 계정 미발급으로 인해 항상 이 에러가 남) | 500 |
| BUSINESS_VERIFY_SERVICE_UNAVAILABLE (2026-07-19 추가) | 사업자 인증 서버와 통신 불가 (현재 서버 미기동으로 인해 항상 이 에러가 남, 사업자 회원가입) | 500 |

## 6. 참고 / 주의사항
------------------------------------------------------------------------
- 인증번호는 발급 후 **5분간만 유효**합니다. 프론트에서 타이머 UI를 넣는다면 5분 기준으로 맞춰주세요.
- `send-code`를 같은 이메일로 여러 번 호출하면, 이미 가입 완료된 이메일인 경우 매번 `DUPLICATE_EMAIL`이 납니다.
  (아직 가입 완료 전 = 인증만 반복 요청하는 경우는 재발송이 정상 동작합니다.)
- 현재 CORS 설정은 별도로 열려있지 않습니다. 프론트 개발 서버 주소가 정해지면 알려주시면 CORS 허용 처리하겠습니다.
- 메일 발신자는 `Eattyway <eattyway@daum.net>` 으로 표시됩니다. (2026-07-18: 기존 Gmail 계정이 정지되어 Daum 메일로 교체됨)
- **(2026-07-18 추가) `phone`은 서버에 저장될 때 AES-256-GCM으로 암호화됩니다.** 요청/응답 스펙(3-5장)은 변경 없음 — 프론트는 지금까지처럼 하이픈 포함 평문(`010-1234-5678`)을 그대로 보내면 됩니다. 서버 내부적으로만 암호화 저장되며, 현재 응답에 `phone`을 그대로 되돌려주는 API는 없으므로 프론트에서 추가로 처리할 것은 없습니다.
- **(2026-07-18 추가) `INVALID_CODE`/`EXPIRED_CODE`는 이메일 인증(3-2)과 전화번호 인증(3-4) 양쪽에서 공통으로 사용됩니다.** 어느 단계에서 난 에러인지는 호출한 API로 구분하면 됩니다(에러 코드 자체는 채널을 구분하지 않음).
- **(2026-07-18 추가) 전화번호 SMS 인증(3-3, 3-4)은 현재 실제로 동작하지 않습니다.** SMS 발송 대행사(뿌리오) 계정 발급이 아직 완료되지 않았습니다. 계정이 준비되는 대로 별도로 안내드리겠습니다.
- **(2026-07-19 추가) 회원가입에 "비밀번호 확인" 입력칸이 새로 필요합니다.** `POST /api/members/signup` 요청에 `passwordConfirm` 필드가 추가되었습니다(3-5장). 화면에 비밀번호 입력칸이 하나뿐이었다면 하나 더 추가해서, 두 값이 다를 때 `PASSWORD_CONFIRM_MISMATCH` 에러를 안내해주세요.
- **(2026-07-19 추가) 일반 회원가입과 사업자 회원가입은 별도 화면/별도 API입니다.** 사업자는 이메일/닉네임/전화번호/비밀번호(+확인)에 더해 사업자등록증명원 업로드가 추가로 필요하고, 요청 자체가 JSON이 아니라 `multipart/form-data`입니다(3-6장). 가입 화면 진입 시 "일반 회원"/"사업자 회원" 중 선택하게 해주시면 됩니다.
- **(2026-07-19 추가) 프로필 사진은 회원가입 API에 포함되지 않습니다.** 2-2장 참고 — 가입+로그인이 끝난 뒤 별도 API를 한 번 더 호출해야 합니다.
- **(2026-07-19 추가) 사업자 회원가입은 현재 실제로 동작하지 않습니다.** 사업자등록증명원 검증(OCR+원본확인+진위확인)을 담당하는 별도 서버가 아직 이 환경에 기동되어 있지 않습니다. 화면/연동 코드는 3-6장 스펙 기준으로 준비해두시고, 실제 테스트는 별도 안내 때까지 보류해주세요.
- **(2026-07-19 추가) 로그인은 일반/사업자 회원이 완전히 같은 API를 씁니다.** `POST /api/members/login` 요청/응답 형식에 차이가 없습니다. 프론트에서 회원 유형을 구분해서 보여줄 일이 있다면, 로그인 응답의 `accessToken`(JWT)을 디코딩해 `role` 클레임(`"USER"` 또는 `"BUSINESS"`)을 확인하면 됩니다.
