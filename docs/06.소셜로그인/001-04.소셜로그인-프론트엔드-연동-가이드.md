# 소셜로그인 - 프론트엔드 연동 가이드
------------------------------------------------------------------------
프론트엔드 전달용 API 요청 URL/스펙 정리 문서

## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- 로그인 시작(1개)과 연동 해제(1개, 로그인 필요)만 `/api` 프리픽스를 쓰고, **콜백 2개(`/oauth/{provider}`, `/api/auth/naver/unlink-callback`)는 프론트가 직접 호출하는 API가 아니라 카카오/네이버/구글이 우리 서버로 호출하는 경로**라 신경 쓸 필요 없음(2장 참고)
- 연동 해제만 `Authorization: Bearer {accessToken}` 필요, 나머지는 로그인 전 단계라 필요 없음

------------------------------------------------------------------------
## 2. 전체 연동 흐름 (프론트가 실제로 할 일은 딱 하나 — 버튼 클릭 시 페이지 이동)
------------------------------------------------------------------------
1. 사용자가 "카카오로 로그인"/"네이버로 로그인"/"구글로 로그인" 버튼을 클릭하면, 프론트는 그 버튼에서 **브라우저를 아래 주소로 그대로 이동시키면 끝**입니다(fetch/axios 호출 아님 — `<a href>` 또는 `window.location.href = ...`).
   ```
   http://localhost:8081/api/auth/kakao/authorize
   http://localhost:8081/api/auth/naver/authorize
   http://localhost:8081/api/auth/google/authorize
   ```
2. 서버가 그 플랫폼의 로그인/동의 화면으로 다시 리다이렉트합니다. 사용자가 로그인하고 정보 제공에 동의합니다.
3. 플랫폼이 우리 서버의 콜백(`/oauth/{provider}`)으로 사용자를 돌려보내고, 서버가 로그인/회원가입 처리 후 **JSON으로 로그인 결과(`accessToken`/`refreshToken` 포함)를 응답**합니다.
4. **현재는 3번 응답이 JSON 그대로 브라우저에 표시됩니다.** 실제 서비스에서는 이 시점에 프론트 페이지로 다시 리다이렉트하면서 토큰을 안전하게 전달하는 방식이 필요한데, 이번 구현은 "프론트 연결 없이 API만 개발"이 요구사항이라 그 부분은 아직 반영되지 않았습니다. **프론트 라우팅이 정해지면 알려주세요** — 서버가 `/oauth/{provider}` 처리 마지막 단계에서 `{프론트주소}?accessToken=...&refreshToken=...` 같은 형태로 리다이렉트하도록 바꿔야 합니다(5장 참고).
5. 이후 발급받은 `accessToken`/`refreshToken`은 기존 [로그인](../02.로그인/001-04.프론트엔드-연동-가이드.md)/[회원정보수정](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md)과 **완전히 동일하게** 사용하면 됩니다 — 소셜로그인으로 로그인했다는 사실이 토큰 사용법에 아무 영향을 주지 않습니다.

## 3. API 상세
------------------------------------------------------------------------
### 3-1. 로그인 시작
```
GET http://localhost:8081/api/auth/kakao/authorize
GET http://localhost:8081/api/auth/naver/authorize
GET http://localhost:8081/api/auth/google/authorize
```
브라우저를 이 주소로 이동시키면 302로 그 플랫폼의 로그인 화면으로 자동으로 넘어갑니다. 프론트에서 응답 바디를 읽거나 처리할 필요가 없습니다.

### 3-2. 콜백 (프론트가 직접 호출하지 않음 — 참고용)
```
GET http://localhost:8081/oauth/kakao?code=...&state=...
GET http://localhost:8081/oauth/naver?code=...&state=...
GET http://localhost:8081/oauth/google?code=...&state=...
```
성공 응답(200, 기존 로그인 응답과 동일한 형식)
```json
{ "success": true, "message": "로그인에 성공하였습니다.", "memberId": 123, "accessToken": "...", "refreshToken": "..." }
```
실패 응답 예시(409, 이미 일반 계정으로 가입된 이메일)
```json
{ "success": false, "code": "EMAIL_ALREADY_REGISTERED", "message": "이미 가입된 계정이 있습니다. 이메일/비밀번호로 로그인해주세요." }
```

### 3-3. 연동 해제
```
DELETE http://localhost:8081/api/auth/{provider}/unlink
Authorization: Bearer {accessToken}
```
`{provider}`: `kakao` | `naver` | `google`
성공 응답(200): `{ "success": true, "message": "연동이 해제되었습니다." }`

마이페이지 등에서 "카카오 연동 해제" 같은 버튼을 만들 때 사용하면 됩니다. 이 계정으로 로그인한 소셜 플랫폼이 여러 개면(예: 카카오+구글 둘 다 연동) 각각 따로 해제할 수 있습니다.

## 4. 화면 구성 시 참고할 검증/에러 처리
------------------------------------------------------------------------
| code | 상황 | 발생 API | HTTP Status | 프론트 처리 가이드 |
|---|---|---|---|---|
| EMAIL_ALREADY_REGISTERED | 소셜 로그인 이메일이 이미 일반(비밀번호) 회원과 겹침 | /oauth/{provider} | 409 | "이미 가입된 계정이 있습니다. 이메일/비밀번호로 로그인해주세요" 안내 후 일반 로그인 화면으로 이동 |
| SOCIAL_LOGIN_FAILED | 플랫폼과의 통신 오류(코드 만료 등) | /oauth/{provider} | 500 | "로그인에 실패했습니다. 다시 시도해주세요" + 3-1의 로그인 버튼으로 재시도 유도 |
| ACCOUNT_SUSPENDED / ACCOUNT_WITHDRAWN | 정지/탈퇴된 계정으로 소셜 로그인 시도 | /oauth/{provider} | 403 | 기존 [로그인 가이드](../02.로그인/001-04.프론트엔드-연동-가이드.md)와 동일하게 처리 |
| NOT_LOGGED_IN | 연동 해제 시 Authorization 헤더 없음/무효 | /api/auth/{provider}/unlink | 401 | 로그인 페이지로 리다이렉트 |
| SOCIAL_ACCOUNT_NOT_LINKED | 연동돼 있지 않은 플랫폼을 해제 시도 | /api/auth/{provider}/unlink | 404 | 마이페이지의 연동 목록을 새로고침(이미 해제된 상태일 가능성) |
| SOCIAL_UNLINK_FAILED | 연동 해제 API 통신 오류 | /api/auth/{provider}/unlink | 500 | "연동 해제에 실패했습니다. 잠시 후 다시 시도해주세요" |

추가로, **회원정보수정 화면에서 비밀번호 변경 폼을 소셜 로그인 계정에는 아예 보여주지 않는 것을 권장**합니다. 소셜 계정으로 비밀번호 변경을 시도하면 서버가 `403 SOCIAL_ACCOUNT_PASSWORD_CHANGE_NOT_ALLOWED`로 거부하지만, 애초에 그 계정이 소셜 로그인인지는 [내 정보 조회](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md#3-1-내-정보-조회-자동-채움용) 응답만으로는 알 수 없습니다(5장 참고).

## 5. 참고 / 주의사항 (현재 미완성 상태, 프론트 개발 시 꼭 확인)
------------------------------------------------------------------------
- ~~콜백 이후 프론트로 리다이렉트하는 로직이 아직 없습니다~~ → **(2026-07-21 구현 완료)** `/oauth/{provider}`
  콜백이 이제 JSON을 직접 응답하지 않고, 성공/실패 관계없이 `oauth.frontend-redirect-url`(`.env`의
  `OAUTH_FRONTEND_REDIRECT_URL`)로 302 리다이렉트한다. 성공 시
  `{프론트주소}?accessToken=...&refreshToken=...&memberId=...`, 실패 시
  `{프론트주소}?error={ErrorCode}&errorMessage=...`. 실제 프론트 주소가 아직 정해지지 않아, 정해지기 전까지는
  임시로 지도 테스트 페이지(`tmp-map-test.html`)를 기본값으로 사용 중 — 실제 프론트 주소가 정해지면
  `OAUTH_FRONTEND_REDIRECT_URL` 값만 바꾸면 된다(코드 변경 불필요). 이 페이지는 로드 시 쿼리 파라미터를
  읽어 로그인 상태로 반영하고 URL을 정리하는 로직이 있어(`handleOAuthRedirectParams()`), 실제 프론트도
  같은 패턴으로 구현하면 된다. `fakecode`로 콜백을 직접 호출해 실패 경로(302 + `error=INVALID_OAUTH_STATE`)
  까지 실데이터로 확인함 — 성공 경로는 실제 소셜 로그인으로 사람이 직접 완료해야 확인 가능(1개 항목 아래
  참고).
- **"이 계정이 소셜 로그인 계정인지" 프론트가 알 수 있는 API가 아직 없습니다.** [내 정보 조회](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md) 응답에는 이메일/닉네임만 있고 소셜 연동 여부/플랫폼 목록이 없습니다. 마이페이지에 "카카오 연동됨" 같은 표시나 비밀번호 변경 폼 노출 여부를 정하려면 이 정보가 필요한데, 별도 조회 API가 아직 만들어지지 않았습니다 — 필요하시면 말씀해주세요(예: `GET /api/auth/me/linked-providers` 같은 API 추가 가능).
- **카카오 로그인은 실사용자 계정으로 끝까지(신규가입 + 토큰 발급까지) 정상 동작을 확인했습니다(2026-07-19).** 처음 발견됐던 `client_secret` 문제를 코드에 반영한 뒤([001-03 3장](001-03.소셜로그인-구현-테스트.md#3-카카오-invalid_client-오류-원인-확인-및-수정-2026-07-19)), 실제 브라우저로 `http://localhost:8081/api/auth/kakao/authorize`에 접속해 카카오 로그인부터 우리 서버의 `accessToken`/`refreshToken` 발급까지 전부 확인했습니다([001-03 2-4장](001-03.소셜로그인-구현-테스트.md#2-4-카카오-실사용자-로그인-수동-검증-2026-07-19-happy-path-최초-확인)). **네이버/구글은 아직 이 수준의 실사용자 확인이 되지 않았습니다** — 실사용자 테스트 계정이 준비되면 카카오와 같은 방식으로 한 번씩 확인이 필요합니다.
- **소셜 신규가입은 이메일/전화번호 재인증이 없습니다.** 일반 회원가입과 달리 플랫폼이 이미 인증한 정보를 그대로 신뢰해 즉시 로그인 처리되므로, 인증번호 입력 화면 자체가 필요 없습니다.
- **전화번호는 네이버 로그인에서만 자동으로 채워집니다.** 카카오/구글로 가입한 계정은 전화번호가 비어 있는 상태이며, 필요하면 [회원정보수정](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md)에서 인증 후 등록해야 합니다.
- **닉네임이 자동으로 다듬어질 수 있습니다.** 플랫폼이 준 닉네임에 특수문자가 있거나 10자를 넘으면 서버가 임의로 다듬고, 이미 다른 회원이 쓰는 닉네임이면 뒤에 숫자를 붙입니다 — 로그인 응답에는 최종 닉네임이 나오지 않으니(3-2장 응답 형식 참고), 필요하면 로그인 직후 [내 정보 조회](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md#3-1-내-정보-조회-자동-채움용) API로 확인해 사용자에게 보여주는 것을 권장합니다.
- **(2026-07-19 추가) 프로필 사진도 가입 시점에 자동으로 채워질 수 있습니다.** 카카오/네이버/구글이 제공하는 프로필 사진 URL을 그대로 저장합니다(구글은 사실상 항상 제공, 카카오/네이버는 계정 설정에 따라 없을 수 있음). 이것도 로그인 응답(3-2장)에는 안 나오니, 로그인 직후 [내 정보 조회](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md#3-1-내-정보-조회-자동-채움용)의 `profileImageUrl`로 확인하세요. **이후 그 회원이 소셜 플랫폼에서 사진을 바꿔도 재로그인 시 자동으로 갱신되지 않습니다**(최초 가입 시점 값 유지) — 사용자가 사진을 바꾸고 싶으면 [회원정보수정의 프로필 사진 등록/변경 API](../05.회원정보수정/001-04.회원정보수정-프론트엔드-연동-가이드.md#3-8-프로필-사진-등록변경-2026-07-19-추가)를 직접 호출해야 합니다.
- 현재 CORS 설정은 별도로 열려있지 않습니다. 프론트 개발 서버 주소가 정해지면 알려주시면 CORS 허용 처리하겠습니다.
