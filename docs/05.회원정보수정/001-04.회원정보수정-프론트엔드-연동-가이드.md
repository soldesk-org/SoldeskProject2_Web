## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- Base path: `/api`
- 이 문서의 API는 전부 **로그인이 필요**합니다. 로그인(`POST /api/members/login`) 응답으로 받은 `accessToken`을 모든 요청의 `Authorization` 헤더에 실어 보내야 합니다.
  ```
  Authorization: Bearer {accessToken}
  ```
- `Content-Type: application/json` 필수 (`GET`, `DELETE` 요청도 바디가 있으므로 동일하게 붙여주세요).
- `accessToken`이 없거나, 형식이 잘못됐거나, 만료됐거나, 이미 로그아웃/탈퇴 처리된 토큰이면 전부 동일하게 아래 형식의 `401 NOT_LOGGED_IN`으로 응답합니다.
  ```json
  { "success": false, "code": "NOT_LOGGED_IN", "message": "로그인 상태가 아닙니다." }
  ```
  이 경우 프론트에서는 로그인 페이지로 리다이렉트 처리하시면 됩니다.

## 2. 기능별 호출 흐름
------------------------------------------------------------------------
### 2-1. 회원정보수정 페이지 진입 (자동 채움)
1. 페이지 진입 시 `GET /api/members/me` 호출
2. 응답의 `email`, `nickname`으로 입력 필드를 채웁니다. **비밀번호와 전화번호는 응답에 포함되지 않으므로 빈 값으로 둡니다** — 사용자가 값을 바꾸고 싶을 때만 새로 입력하고, 바꾸지 않을 필드는 그냥 비워둔 채 저장 요청을 보내면 됩니다(2-4장 참고).

### 2-2. 이메일 변경 (값을 실제로 바꿀 때만)
1. 사용자가 새 이메일을 입력하면 `POST /api/members/me/email/send-code`로 인증번호 발송
2. 사용자가 받은 인증번호를 입력하면 `POST /api/members/me/email/verify-code`로 확인
3. 인증이 완료된 이메일로만 4장의 저장(`PATCH`) 요청에 포함시켜야 저장됩니다. 인증 없이 저장을 시도하면 `EMAIL_NOT_VERIFIED`가 납니다.
4. 현재 이메일과 동일한 값이면 send-code를 호출할 필요 없이 그냥 저장 요청에서 `email` 필드를 생략(또는 기존 값 그대로 전송)하면 됩니다 — 값이 그대로면 재인증을 요구하지 않습니다.

### 2-3. 전화번호 변경 (제출한 경우에만)
1. 사용자가 새 전화번호를 입력하면 `POST /api/members/me/phone/send-code`로 SMS 인증번호 발송
2. 사용자가 받은 인증번호를 입력하면 `POST /api/members/me/phone/verify-code`로 확인
3. 인증이 완료된 전화번호로만 4장의 저장 요청에 포함시켜야 합니다. 미인증 상태로 저장을 시도하면 `PHONE_NOT_VERIFIED`가 납니다.
> 현재 SMS 발송 대행사(뿌리오) 계정이 아직 발급되지 않아 `send-code` 호출 시 실제로는 발송되지 않고 `500 SMS_SEND_FAIL`이 납니다. 화면/연동 코드는 아래 스펙 기준으로 준비해두시고, 실제 동작 테스트는 계정 발급 완료 안내가 갈 때까지 보류해주세요.

### 2-4. 회원정보 저장
1. 닉네임(필수) + 값을 바꾼 항목(이메일/전화번호/비밀번호)만 담아 `PATCH /api/members/me` 호출
2. **바꾸지 않는 항목은 아예 필드를 보내지 않으면 됩니다** — 닉네임만 필수이고 나머지는 전부 선택 필드입니다.
3. 비밀번호를 바꾸는 경우에만 `password`+`passwordConfirm`을 함께 보내세요(회원가입과 동일하게 두 값이 일치해야 함).

### 2-5. 회원 탈퇴 (2026-07-19 추가)
1. 탈퇴 버튼 클릭 시 프론트에서 "정말 탈퇴하시겠습니까?" 확인 모달과 함께 **현재 비밀번호 입력창**을 보여줍니다(서버가 재인증을 요구함 — 3-7장 참고).
2. 입력한 비밀번호로 `DELETE /api/members/me` 호출
3. 성공하면 로컬에 저장해둔 `accessToken`/`refreshToken`을 삭제하고 로그인 페이지 등으로 이동시킵니다. **서버에서도 즉시 해당 세션을 무효화**하므로, 같은 `accessToken`으로 다른 API를 다시 호출하면 이후 전부 `401 NOT_LOGGED_IN`이 납니다(직접 로그아웃 처리를 호출할 필요는 없습니다).
> 소셜 로그인 회원의 탈퇴 제한은 아직 반영되어 있지 않습니다(소셜 로그인 기능 자체가 없음) — 현재는 모든 회원이 이 API로 탈퇴할 수 있습니다.

### 2-6. 프로필 사진 등록/변경/삭제 (2026-07-19 추가)
1. 사용자가 이미지 파일을 고르면 `POST /api/members/me/profile-image`로 즉시 업로드(파일 선택과 동시에 업로드하는 방식을 권장 — 별도의 "저장" 버튼 없이 업로드 성공 시점에 바로 반영됩니다)
2. 이미 사진이 등록돼 있는 상태에서 다시 업로드하면 자동으로 교체됩니다(별도 삭제 필요 없음)
3. "사진 삭제" 버튼은 `DELETE /api/members/me/profile-image` 호출 — 사진이 없는 상태에서 눌러도 에러 없이 성공합니다
4. **회원가입 화면에서 사진을 고르는 경우**: 가입 API(`POST /api/members/signup`) 자체에는 사진을 포함할 수 없습니다. 가입 완료 → 로그인까지 마친 뒤, 그 `accessToken`으로 이 절의 업로드 API를 한 번 더 호출해서 반영해주세요(회원가입/로그인 모두 이미 JSON 계약으로 확정돼 있어 이번에 사진 필드를 끼워 넣지 않았습니다 — [001-03 4-2장](001-03.회원정보수정-구현-테스트.md#4-2-설계-대비-실제-구현-확정-사항) 참고).

## 3. API 상세
------------------------------------------------------------------------
### 3-1. 내 정보 조회 (자동 채움용)
```
GET http://localhost:8081/api/members/me
Authorization: Bearer {accessToken}
```
성공 응답 (200)
```json
{ "success": true, "email": "user@example.com", "nickname": "홍길동", "profileImageUrl": "http://localhost:8081/profile-images/xxxx.png", "phone": "010-1234-5678", "foodBti": null, "social": false }
```
비밀번호는 응답에 포함되지 않습니다(보안). `profileImageUrl`은 회원이 사진을 등록한 적이 없으면 `null`입니다 — **이 경우 서버가 기본 이미지를 내려주지 않으니, 프론트에서 `nickname`의 첫 글자를 대문자 원형 배지로 렌더링해주세요**(2026-07-19 확정, 6장 참고). 서버가 별도 기본 이미지 URL을 내려주는 방식이 아니라서 이 로직은 항상 프론트 담당입니다.

> **(2026-07-22 갱신)** `phone`/`foodBti`/`social` 필드가 새로 추가됐습니다 — 마이페이지(`docs/11.마이페이지`) 기능
> 추가 때 이 응답에 함께 얹었습니다(예전엔 전화번호를 의도적으로 뺐었는데, 본인 정보를 보여주는 화면이라
> 굳이 뺄 이유가 없다고 판단). `phone`은 등록 안 했으면 `null`, `foodBti`는 아직 값을 채우는 기능 자체가
> 없어 항상 `null`입니다(다른 팀원이 별도로 채울 예정). **`social`은 이 계정이 소셜로그인 계정이면 `true`**
> — 이 값이 `true`면 화면에서 비밀번호 입력란(수정 폼, 아래 3-11장 재확인 게이트 포함)을 아예 숨겨주세요.
> 실제 차단(`SOCIAL_ACCOUNT_PASSWORD_CHANGE_NOT_ALLOWED`)은 이 필드와 무관하게 서버가 항상 하고 있으니,
> 이 필드는 순수하게 UX용입니다.

```

{
  "nickname": "새닉네임",
  "email": "new-user@example.com",

`nickname`만 필수이고 `email`/`phone`/`password`+`passwordConfirm`은 전부 선택 필드입니다 — 값을 바꾸지 않는 항목은 필드 자체를 보내지 마세요.

```
실패 응답 예시 (400, 이메일 미인증 상태로 저장 시도)
```json
{ "success": false, "code": "EMAIL_NOT_VERIFIED", "message": "이메일 인증이 완료되지 않았습니다." }
```

### 3-8. 프로필 사진 등록/변경 (2026-07-19 추가)
```
POST http://localhost:8081/api/members/me/profile-image
Authorization: Bearer {accessToken}
Content-Type: multipart/form-data

profileImage: (파일)
```
이 API만 `Content-Type: application/json`이 아니라 `multipart/form-data`입니다 — 프론트에서 `FormData`로 보내주세요. 필드명은 반드시 `profileImage`.

성공 응답 (200)
```json
{ "success": true, "message": "프로필 사진이 등록되었습니다.", "profileImageUrl": "http://localhost:8081/profile-images/xxxx.png" }
```
실패 응답 예시 (400, 지원하지 않는 형식이거나 5MB 초과)
```json
{ "success": false, "code": "INVALID_PROFILE_IMAGE", "message": "지원하지 않는 이미지 형식이거나 용량이 너무 큽니다." }
```
지원 형식: jpg/png/gif/webp, 최대 5MB.

### 3-11. 비밀번호 재확인 (2026-07-22 추가)
```
POST http://localhost:8081/api/members/me/verify-password
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "password": "P@ssw0rd1" }
```
성공 응답 (200): `{ "success": true, "message": "비밀번호가 확인되었습니다." }` — 상태를 바꾸지 않고 확인만 합니다.
실패 응답 (401): `{ "success": false, "code": "INVALID_CREDENTIALS", "message": "..." }`

마이페이지에서 "프로필 수정 화면에 들어갈 때마다 비밀번호를 먼저 입력해야 수정 폼이 열리는" 게이트에 씁니다
(참고 구현: `mypage-test.html`의 `#profileEditGate` — 페이지를 다시 열 때마다 게이트가 잠긴 상태로 초기화되고,
이 API로 확인에 성공해야 그 아래 수정 필드들이 보입니다). **소셜 계정(`social: true`)은 이 게이트 자체를
건너뛰세요** — 비밀번호가 없는 계정이라 확인할 대상이 없습니다.

## 4. 입력값 검증 규칙 (프론트 단에서도 동일하게 미리 검증 추천)
------------------------------------------------------------------------
| 필드 | 규칙 |
|---|---|
| nickname | 한글/영문/숫자 2~10자 (특수문자 불가) — 회원가입과 동일, 저장(3-6) 시 필수 |
| email | 이메일 형식, 최대 100자 |
| phone | `010-XXXX-XXXX` 형식 (하이픈 포함해서 그대로 전송) |
| password / passwordConfirm (정보수정) | 8~20자, 영문+숫자+특수문자 모두 포함, 둘 다 서로 동일해야 함 — 값을 바꿀 때만 전송 |
| password (탈퇴 확인) | 별도 형식 검증 없음(빈 값만 아니면 됨) — 실제 비밀번호와 일치하는지만 서버에서 확인 |
| code (이메일/전화번호 인증 확인) | 숫자 6자리 |
| profileImage | jpg/png/gif/webp만 가능, 최대 5MB |

## 5. 에러 응답 형식
------------------------------------------------------------------------
모든 에러는 아래 형식으로 내려옵니다. HTTP status와 `code`로 분기 처리하면 됩니다.
```json
{ "success": false, "code": "EMAIL_NOT_VERIFIED", "message": "이메일 인증이 완료되지 않았습니다." }
```

| code | 상황 | 발생 API | HTTP Status |
|---|---|---|---|
| NOT_LOGGED_IN | Authorization 헤더 없음/형식 오류/토큰 무효/세션 만료(로그아웃·탈퇴된 토큰 포함) | 전체 API 공통 | 401 |
| INVALID_INPUT | 입력값 형식 오류 | 전체 API 공통 | 400 |
| PASSWORD_CONFIRM_MISMATCH | 새 비밀번호와 새 비밀번호 확인이 다름 | PATCH /me | 400 |
| EMAIL_NOT_VERIFIED | 저장하려는 새 이메일이 인증 미완료 상태 | PATCH /me | 400 |
| PHONE_NOT_VERIFIED | 저장하려는 새 전화번호가 인증 미완료 상태 | PATCH /me | 400 |

## 6. 참고 / 주의사항
------------------------------------------------------------------------
- **본인이 지금 쓰고 있는 값을 그대로 다시 제출해도 문제 없습니다**: 닉네임/이메일/전화번호가 기존 값과 동일하면 서버가 "변경 없음"으로 판단해 중복확인/재인증 없이 그냥 통과시킵니다.
- **`GET /api/members/me`가 전화번호를 내려주지 않는 이유**: 요구사항에 따라 의도적으로 응답에서 제외했습니다. 전화번호 수정 화면에서는 빈 입력창을 그대로 보여주시면 됩니다.
- **(2026-07-18 이전부터 지속) SMS 발송(2-3장, 3-4~3-5장)은 현재 실제로 동작하지 않습니다.** SMS 발송 대행사(뿌리오) 계정 발급이 아직 완료되지 않았습니다. 화면/연동 코드는 API 스펙 기준으로 준비해두시고, 실제 연동 테스트는 계정 발급 완료 안내가 갈 때까지 보류해주세요.
- **이메일 발송(3-2장)은 실제로 정상 동작합니다** — Daum 메일 계정(`eattyway@daum.net`)이 이미 설정되어 있고, 실제 이메일 주소로 확인해본 결과 정상적으로 발송됩니다. 다만 테스트 코드에서 관례적으로 쓰는 `@example.com`(RFC 2606 예약 도메인, 실제로 메일을 수신하지 않음) 같은 가짜 주소로 보내면 서버가 아니라 메일 서버 쪽에서 반송되어 `MAIL_SEND_FAIL`이 납니다 — 실제 사용자 이메일 주소라면 이 문제가 발생하지 않습니다.
- **탈퇴는 되돌릴 수 없습니다.** 현재 서버에는 탈퇴 취소/재가입 관련 API가 없습니다. 탈퇴 확인 모달의 문구에 이 점을 명확히 안내해주세요.
- **탈퇴 후에도 닉네임/이메일/전화번호는 즉시 재사용할 수 없습니다.** 탈퇴 처리는 계정 상태만 바꾸고 데이터를 지우지 않기 때문에, 같은 이메일/전화번호로 재가입을 시도하면 여전히 "이미 사용 중" 에러가 납니다(추후 정책이 정해지면 서버 쪽에서 개선 예정, 001-03 5장 참고). 탈퇴 안내 문구에 이 부분도 참고해주시면 좋습니다.
- **(2026-07-19 확정) 기본 프로필은 "닉네임 첫 글자 이니셔널 원형 배지" 방식입니다.** 사진을 등록하지 않은 회원은 `profileImageUrl`이 `null`로 내려가고, 서버는 대체 이미지 파일을 제공하지 않습니다. 프론트에서 아래처럼 처리해주세요(예시, 실제 컴포넌트 구조는 자유):
  ```jsx
  function Avatar({ nickname, profileImageUrl }) {
    if (profileImageUrl) {
      return <img src={profileImageUrl} alt={nickname} className="avatar" />;
    }
    const initial = nickname?.[0]?.toUpperCase() ?? '?';
    return <div className="avatar avatar-initial">{initial}</div>;
  }
  ```
  ```css
  .avatar { width: 36px; height: 36px; border-radius: 9999px; }
  .avatar-initial {
    display: flex; align-items: center; justify-content: center;
    background: var(--brand-color, #6b5bd6); /* 서비스 브랜드 컬러로 교체 */
    color: #fff; font-weight: 600; font-size: 14px;
  }
  ```
  닉네임이 아닌 이메일 첫 글자를 쓰고 싶다면 `nickname` 대신 `email`을 쓰셔도 됩니다(둘 다 `GET /api/members/me` 응답에 있음, 3-1장). 서버가 별도 기본 이미지 URL을 내려주는 방식이 아니므로, 이 로직은 프론트에서 프로필 사진이 쓰이는 모든 화면(마이페이지, 헤더 등)에 공통 컴포넌트로 만들어두시는 걸 권장합니다.
- **(2026-07-19 추가) 소셜로그인으로 가입한 회원은 사진이 자동으로 채워질 수 있습니다.** 플랫폼(카카오/네이버/구글)이 제공하는 프로필 사진 URL을 가입 시점에 그대로 저장합니다 — 다만 이후 그 회원이 소셜 플랫폼에서 사진을 바꿔도 재로그인 시 자동으로 갱신되지는 않습니다(최초 가입 시점 값 유지). 자세한 내용은 [006.소셜로그인 연동 가이드](../06.소셜로그인/001-04.소셜로그인-프론트엔드-연동-가이드.md) 참고.
- 현재 CORS 설정은 별도로 열려있지 않습니다. 프론트 개발 서버 주소가 정해지면 알려주시면 CORS 허용 처리하겠습니다.
