> 재확인 완료(001-03 2-3장).

## 1. 서버 접속 정보
------------------------------------------------------------------------
- 로컬 개발 서버: `http://localhost:8081`
- 질문 조회(`GET /api/food-bti/questions`)는 로그인 불필요.
- 결과 계산(`POST /api/food-bti/result`)은 **로그인이 선택**이다 — `Authorization: Bearer {accessToken}`을
  실어 보내면 결과가 그 계정에 저장되고, 안 보내면 결과만 계산되고 저장되지 않는다. 다른 대부분의 API처럼
  "안 보내면 401"이 아니다.

------------------------------------------------------------------------
## 2. 기능별 호출 흐름
------------------------------------------------------------------------
### 2-1. 퀴즈 시작
1. 화면 진입 시 `GET /api/food-bti/questions` 호출 — 질문 12개를 배열로 받는다(`questionNo` 순서대로 이미
   정렬되어 있음)
2. 한 번에 한 문항씩 보여주고, 두 선택지(`choiceA`/`choiceB`) 중 하나를 고르면 다음 문항으로 넘어가는 방식을
   권장(참고 구현: `foodbti-test.html`)
3. 각 선택지의 `score`(`L`/`S`/`F`/`N`/`A`/`T`/`P`/`I` 중 하나) 값을 그 문항의 답변으로 기록해둔다 —
   화면에 보이는 텍스트(`text`)가 아니라 이 `score` 값을 서버에 보내야 한다

### 2-2. 결과 제출
1. 12문항 모두 답했으면 `POST /api/food-bti/result`에 `answers: string[]`(12개, 질문 순서와 1:1 대응)를
   보낸다
2. 로그인 상태(accessToken 있음)면 헤더에 그대로 실어 보낸다 — 그러면 서버가 결과를 그 계정의
   `members.food_bti`에 저장한다(응답의 `saved: true`로 확인 가능)
3. 비로그인이면 헤더 없이 호출해도 결과는 정상적으로 나온다(단 `saved: false`) — "로그인 안 해도 일단
   테스트해볼 수 있는" 흐름을 프론트도 그대로 지원하는 것을 권장(로그인 유도는 결과 화면에서 "로그인하면
   저장돼요" 안내 정도로 충분)
4. 결과 화면에서 유형 코드(`resultType`)/이름/설명/추천 음식/성향별 점수(`score`)를 보여준다

### 2-3. 마이페이지에서 음BTI 표시
`GET /api/members/me`(05/11에서 이미 쓰던 그 API)의 `foodBti` 필드가 이 기능으로 채워진다 — 마이페이지
화면에서 값이 있으면 그대로 표시하고, `null`이면 "음BTI 미설정" 같은 플레이스홀더와 함께 이 퀴즈 화면으로
연결하는 버튼을 두는 것을 권장(단, 그 버튼 자체를 마이페이지 화면에 붙이는 UX 통합은 001-02 8장에서 아직
미착수로 남겨둔 부분이라 프론트 판단으로 진행해도 된다).

## 3. API 상세
------------------------------------------------------------------------
### 3-1. 질문 목록 조회
```
GET http://localhost:8081/api/food-bti/questions
```
성공 응답(200):
```json
[
  {
    "questionNo": 1,
    "question": "음식을 먹을 때 더 끌리는 맛은?",
    "choiceA": { "text": "재료 본연의 담백하고 깔끔한 맛.", "score": "L" },
    "choiceB": { "text": "맵고 짜고 양념이 강한 자극적인 맛.", "score": "S" }
  }
]
```
12개 전부 이 형식. 순서는 항상 동일(질문 콘텐츠를 서버 코드 상수로 관리, 001-02 2-4장).

### 3-2. 결과 계산
```
POST http://localhost:8081/api/food-bti/result
Authorization: Bearer {accessToken}   (선택 — 있으면 저장까지 됨)
Content-Type: application/json

{ "answers": ["S","S","L","F","N","F","A","A","A","I","I","I"] }
```
`answers`는 정확히 12개, 각 값은 `L/S/F/N/A/T/P/I` 중 하나(질문 순서와 1:1 대응).

성공 응답(200, 2026-07-23 실 서버 라이브 검증으로 확인한 실제 응답):
```json
{
  "resultType": "SFAI",
  "resultName": "강렬한 단골 미식가",
  "resultText": "자극적이고 강한 맛을 좋아하고, 익숙하고 검증된 음식을 선호하며, 혼자 편안하게 먹는 것을 좋아하고, 기분에 따라 즉흥적으로 메뉴를 고르는 타입입니다.",
  "food": ["떡볶이", "마라탕", "단골집 대표 메뉴", "덮밥", "오늘 생각난 메뉴"],
  "score": { "l": 1, "s": 2, "f": 2, "n": 1, "a": 3, "t": 0, "p": 0, "i": 3 },
  "saved": true
}
```
`saved`는 `Authorization` 헤더가 유효했을 때만 `true` — 비로그인이거나 토큰이 무효하면 나머지 필드는 정상
계산되어 내려오고 `saved`만 `false`다(에러가 아님).

실패 응답(400, 답변 개수/값 오류):
```json
{ "success": false, "code": "INVALID_INPUT", "message": "..." }
```

------------------------------------------------------------------------
## 4. 에러 응답 형식
------------------------------------------------------------------------
| code | 상황 | 발생 API | HTTP Status |
|---|---|---|---|
| INVALID_INPUT | `answers`가 12개가 아니거나 허용되지 않은 값 포함 | POST /result | 400 |
