# 음BTI(음식 취향 MBTI) 연동
------------------------------------------------------------------------
> **작성 방식에 대한 안내**: 이 기능은 01~11과 달리 이 프로젝트(`SoldeskProject2_Web`) 안에서 처음부터
> 개발된 게 아니다. 다른 팀원이 별도 로컬 저장소(`SoldeskProject2_Web_MBTI`, 같은 GitHub 원격
> `soldesk-org/SoldeskProject2_Web`의 `feature/web-map-responsive` 브랜치를 체크아웃한 것)에서 질문/채점
> 로직을 먼저 만들어뒀고, 이번 작업은 그 로직을 이 프로젝트의 실제 회원 도메인(`members.food_bti`)에
> **연동**한 것이다. "왜 이렇게 만들었는가"의 설계 판단은 연동 시점(2026-07-23)의 것이고, 채점 로직
> 자체(질문 문구, 성향 4축, 점수 계산 방식)는 원본을 그대로 포팅했다.

## 배경
------------------------------------------------------------------------
`members.food_bti` 컬럼은 11(마이페이지) 작업 때 이미 추가되어 있었다(`docs/11.마이페이지/001-01` "확인된
사항" — "음BTI: 다른 팀원이 담당 — 이번엔 필드(컬럼)만 만들어두고, 값을 채우는 퀴즈/자동계산 로직과 값을
설정하는 API는 이번 범위에 포함하지 않는다. 항상 `null`로 시작"). 그 담당 팀원이 만들어둔 로직을 이번에
실제로 연동해서, 그 "항상 `null`" 상태를 해소했다.

## 요청사항 원문 요약
------------------------------------------------------------------------
- `SoldeskProject2_Web_MBTI`에 있는 음BTI(MBTI와 비슷한 개념) 로직을 이 프로젝트 백엔드에 연동할 것
- 연동 내용을 문서화할 것
- 연동 후 백엔드 동작을 테스트할 수 있는 페이지를 만들 것

## 원본 로직 확인 결과
------------------------------------------------------------------------
`SoldeskProject2_Web_MBTI/Project2/src/main/java/com/foodtrip/foodsearch/`에서 확인한 원본 구성:

- `controller/FoodBtiAPIController` — `GET /api/food-bti/questions`(질문 목록), `POST
  /api/food-bti/result`(결과 계산). 둘 다 인증 없음, DB 접근 없음(순수 계산)
- `service/FoodBtiService` — 질문 12개(성향 4축 × 3문항)를 하드코딩으로 반환, 답변 12개를 받아 각 축의
  우세한 성향을 골라 4글자 결과 코드(예: `SFAI`)를 만들고, 결과 코드에 따라 이름/설명/추천 음식을 생성
- `dto/FoodBtiQuestionDTO`, `FoodBtiChoiceDTO`, `FoodBtiAnswerDTO`, `FoodBtiResultDTO`, `ScoreDTO` — 전부
  순수 데이터 클래스, 영속성(JPA) 어노테이션 없음
- `FoodBtiServiceTest`(main 메서드) — DB/Spring 없이 로직만 확인하는 임시 테스트 클래스

**DB 저장은 원본에 전혀 없었다** — 원본은 질문을 보여주고 결과를 계산해서 응답하는 것까지만 하고, 그
결과를 회원 정보에 반영하는 부분은 이 저장소(`SoldeskProject2_Web`)의 `members.food_bti` 컬럼과 연결하는
몫이라 이번 작업에서 새로 추가했다. 상세 설계는 [001-02.음BTI-분석-설계.md](001-02.음BTI-분석-설계.md) 참고.

## 이번 범위 정리
------------------------------------------------------------------------
- 질문 12개 조회, 결과 계산 로직 — 원본 그대로 포팅(문항 문구/성향 축/채점 방식 변경 없음)
- 로그인 상태로 결과를 계산하면 그 계정의 `members.food_bti`에 실제로 저장
- 비로그인으로도 결과 계산까지는 가능(저장만 안 됨) — 로그인 없이도 테스트해볼 수 있어야 하므로
- 연동 검증용 테스트 페이지(`foodbti-test.html`) 신규 제작

------------------------------------------------------------------------
## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- 결과 코드 16종 중 2종(`SNTP`, `LFAI`)만 원본에 상세 이름/설명/추천 음식이 있고, 나머지 14종은 원본의
  "성향 조합으로 기본값 생성" 방식 그대로 — 16종 전체에 대한 고유 콘텐츠 제작은 이번 범위 아님(원본 로직
  그대로 포팅했으므로 이 프로젝트가 새로 만든 제약이 아님)
- 결과 이력 저장(퀴즈를 몇 번 풀었는지, 이전 결과가 뭐였는지 등) — `members.food_bti`는 최신 결과 1개만
  덮어쓰기 저장, 별도 이력 테이블 없음
- 마이페이지 화면에서 퀴즈로 바로 연결하는 "음BTI 다시 하기" 버튼 등 UX 통합 — 이번엔 독립된 테스트
  페이지로만 제공(11.마이페이지의 실제 화면과는 아직 연결 안 됨, 8장 참고)

상세 구현은 [001-02.음BTI-분석-설계.md](001-02.음BTI-분석-설계.md), [001-03.음BTI-구현-테스트.md](001-03.음BTI-구현-테스트.md) 참고.
