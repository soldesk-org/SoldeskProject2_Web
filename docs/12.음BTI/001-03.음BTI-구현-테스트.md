## 2. 검증
------------------------------------------------------------------------
### 2-1. 컴파일 확인
`./mvnw.cmd compile` 정상 통과(경고/에러 없음) — 신규 패키지, `Member.updateFoodBti()` 추가가 기존 코드와
충돌 없음을 확인.

### 2-2. 채점 로직 단독 실행 검증 (Spring/DB 없이)
2-3장의 이유로 서버를 기동해 실제 DB 연동까지 검증하지 못해, 원본의 `FoodBtiServiceTest`(main 메서드 방식)와
같은 접근으로 `FoodBtiServiceImpl`을 Spring 컨텍스트 없이 직접 인스턴스화(의존성 3개는 어차피 비로그인
호출에서는 안 쓰이므로 `null`로 주입)해서 로직만 단독 실행:

- `getQuestions()` → 12개 정상 반환, 1번 질문 문구가 원본과 동일함 확인
- 답변 `["S","S","L","F","N","F","A","A","A","I","I","I"]`(원본 `FoodBtiServiceTest`와 다른 조합으로
  임의 선택)로 `calculateResult(null, ...)` 호출
  → `resultType = "SFAI"` (L=1/S=2 → S, F=2/N=1 → F, A=3/T=0 → A, P=0/I=3 → I — 채점 로직이 정확히
  원본 규칙대로 동작함을 손으로 재계산해 대조 확인)
  → `resultName`/`food` 정상 생성(`SFAI`는 상세 콘텐츠가 없는 14종 중 하나라 조합 생성 로직 경로 확인됨,
  001-02 2-4장/8장)
  → `saved = false`(Authorization 없이 호출했으므로 정확히 설계대로 저장 안 됨을 확인, 001-02 2-2장)
- 답변 1개짜리 잘못된 요청은 서비스 메서드를 직접 호출하는 이 단독 테스트에서는 예외가 나지 않음 —
  `@Size(min=12,max=12)` 검증은 Jakarta Bean Validation이 `@Valid`를 통해 컨트롤러 계층에서 수행하는 것이라
  (`FoodBtiController.calculateResult()`), 서비스 메서드를 직접 호출하는 이 단독 테스트에는 그 계층이 없어
  검증되지 않음. **실제 컨트롤러 경유 검증은 2-3장 사유로 아직 못 함.**

### 2-3. 실 서버(DB 연동) 라이브 검증 (2026-07-23, VM 복구 후 완료)
최초 연동 작업 시점엔 Azure VM(`72.155.72.187`, DB/Redis가 있는 그 VM)에 `ping`도 안 되고 3306/6379 포트
모두 연결 시간 초과가 나서 서버 기동 자체가 안 됐었다(`HikariPool` 초기화 단계에서 `SocketException:
Connection timed out`). VM이 복구된 뒤 서버를 다시 기동해서 Node `fetch` 기반 스크립트로 실제 API를
호출해 재확인:

- `test@naver.com`(2026-07-22 세션에서 만든 테스트 계정) 로그인 → `GET /api/members/me`로 `foodBti: null`
  확인(퀴즈를 아직 안 푼 상태)
- 답변 `["S","S","L","F","N","F","A","A","A","I","I","I"]`로 로그인 토큰과 함께 `POST /api/food-bti/result`
  호출 → `{"resultType":"SFAI", "resultName":"강렬한 단골 미식가", ..., "saved":true}` 정상 응답(단독 실행
  검증 때와 동일한 `resultType`이 나옴을 재확인 — 2-2장의 손계산과 일치)
- 곧바로 `GET /api/members/me` 재조회 → `foodBti: "SFAI"`로 실제 DB에 반영됨을 확인(**핵심 목표였던
  "로그인 상태로 결과를 계산하면 계정에 저장된다"가 실제로 동작함**)
- `Authorization` 헤더 없이 다른 답변으로 `POST /api/food-bti/result` 호출 → 결과는 정상 계산되고
  `saved: false`로 응답(비로그인 저장 안 함 정책이 실제로 동작함)
- 답변 1개짜리 요청 → `400 INVALID_INPUT`(`"answers: 12개 질문에 모두 답변해야 합니다."`) 정상 응답
  (`@Valid`+`@Size(min=12,max=12)` 검증이 컨트롤러 계층에서 실제로 동작함을 확인)
- **문서 오류 발견 및 수정**: 001-04(프론트 연동 가이드)의 예시 응답에 `resultName: "강렬한 음식 탐험가"`,
  `food`에 `"이색 퓨전 음식"`을 적어뒀었는데, 실제 코드(`createDefaultName`/`createDefaultFoods`)는
  `resultType.charAt(1) == 'N'`일 때만 그 값을 쓴다 — `SFAI`는 두 번째 글자가 `F`라 조건이 거짓이므로
  실제로는 `"강렬한 단골 미식가"`/`"단골집 대표 메뉴"`가 맞다. 이번 라이브 검증으로 실제 응답을 직접
  받아보고서야 발견한 문서-코드 불일치였음 — 001-04를 실제 응답으로 정정함.

검증에 쓴 테스트 계정(`test@naver.com`)의 `food_bti` 값(`SFAI`)은 계속 남겨둠 — 이후 이 계정으로 재검증할
때 초기 상태(`null`)가 아님에 유의.
