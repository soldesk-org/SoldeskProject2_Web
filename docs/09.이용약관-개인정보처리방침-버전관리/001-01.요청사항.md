# 09. 이용약관/개인정보처리방침 버전관리 — 요청사항

## 1. 배경

기존 `terms-service.html`/`terms-privacy.html`은 순수 정적 페이지였다(DB 백엹 없음, 버전 개념 없음).
학교 캡스톤 프로젝트의 컴플라이언스(법무) 과제로, 실제 서비스처럼 약관 개정 이력을 관리하고 사전 고지
절차를 갖추라는 팀원 요청이 있었다. 이 문서는 그 요청을 그대로 옮겨 적은 것이다.

## 2. 요청 내용(원문 요지)

- 이용약관/개인정보처리방침 각각 **목차는 상단에** 있어야 한다.
- **전버전도 볼 수 있게**, 하단에 select(드롭다운)로 과거 버전을 골라서 볼 수 있어야 한다.
- 약관이 바뀌면 미리 안내해야 한다. **"작은 거"는 시행 14일 전**, **"큰 거"는 시행 30일 전**까지
  게시판(공지)에 시행일자를 명시해서 올려야 한다.
- 관리자 페이지에서 이 공지를 올릴 수 있어야 한다(관리자 전용 공지 등록 기능).
- 그 공지를 회원이 눌러서 들어가면, **그 버전 변경의 변경 전/변경 후를 비교해서 볼 수 있어야** 한다.
- (팀원이 함께 언급한 맥락) 개인정보 유출 시 "수익금의 10%"에 달하는 과징금 위험이 있다 — 이건 이번
  기능이 왜 중요한지에 대한 배경 설명일 뿐, 과징금/벌금 계산 기능을 만들어달라는 요청이 아니다. 그래서
  이 프로젝트에서는 과징금 관련 기능을 전혀 만들지 않았다.

## 3. 보류 항목(이번 범위에서 구현하지 않음)

팀원이 "이건 일단 보류로 해놔"라고 명시적으로 지시한 두 항목이다. **잊어버린 게 아니라 의도적으로
미룬 것**이므로, 이 프로젝트를 이어받는 다음 세션이 "왜 안 만들었지?"라고 혼란스러워하지 않도록 여기에
남겨둔다.

1. **휴면계정(장기 미접속 계정) 처리** — 예: N년 이상 로그인이 없는 계정을 자동으로 잠그는 것 같은,
   한국 개인정보보호법(PIPA) 준수 사이트에서 흔히 쓰는 모범 사례. 이번 범위에서 관련 배치/스케줄러/DB
   컬럼을 전혀 만들지 않았다. **보류 사유**: 팀원의 명시적 지시.
2. **개인정보 보관기간 명시 문구/정책** — "회원 정보는 탈퇴 후 N년간 보관됩니다" 같은 구체적인 보유기간
   고지 조항과 그에 따른 실제 삭제 로직. 이번 시드 콘텐츠(제3조/제3조 개인정보 보유기간)에는 기존 정적
   페이지에 있던 수준의 문구만 그대로 남겨뒀고, 새로운 "N년" 식의 구체적 보관기간 문구나 삭제 배치는
   추가하지 않았다. `member.cleanup.cron`(05.회원정보수정에서 이미 존재하는, 탈퇴 처리와 관련된 기존
   스케줄러)은 이번 작업과 무관한 별개 기능이라 건드리지 않았다. **보류 사유**: 팀원의 명시적 지시(위와
   같은 맥락에서 함께 보류로 지정됨).

## 4. 이번 범위에 포함된 것

- 약관/개인정보처리방침 DB 버전 관리(테이블 신설, ddl-auto=update로 자동 반영)
- 공개 API: 현재 버전 조회, 과거 버전 목록/조회
- 공개 공지 게시판(회원 개인별 알림 벨과는 무관한 별도 게시판) + 공지 상세(변경 전/후 비교)
- 관리자: 새 버전 등록(14/30일 사전고지 규칙 서버 검증 포함) + 공지 게시(한 액션으로 묶음)
- 프론트: 두 정적 페이지를 동적 렌더링(목차 자동 생성, 버전 select)으로 전환, 공지 목록/상세 페이지 신규,
  관리자 페이지에 "약관 관리" 탭 신규
