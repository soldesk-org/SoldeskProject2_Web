# AI 추천 후속 코스 (밥 먹고 산책/카페 어때요?)
------------------------------------------------------------------------

------------------------------------------------------------------------
## 실행 환경
------------------------------------------------------------------------
사용하는 툴
- STS, VS Code
사용하는 코드
- Spring Boot(백엔드), 팀원의 Python(FastAPI) 추천 서버(AI 분석 단계만 재사용)
작업 영역
- Project2 (recommendation 패키지)

------------------------------------------------------------------------
## 요청사항 원문 요약
------------------------------------------------------------------------
"AI 추천 탭에서 추천 후 또는 추천 검색에서 밥 먹고 둘러 산책할 코스나 그런 지도에서 코스 형태로 나타나게
해서 그거도 그 추천한 주변에서의 공원이나 주변 카페 그런거도 추천해줄수 있도록 랜덤하게"라는 요청 —
AI 추천(18.추천-피드백)이 끝난 뒤, 방금 추천된 음식점 주변의 공원(산책 코스) 또는 카페를 추가로 제안해달라는
것. 구체적으로:

- 추천이 끝나면 화면 아래에 "밥 먹고 산책 어때요? AI가 추천해드릴게요" 또는 "밥 먹고 카페 어때요? AI가
  추천해드릴게요" 둘 중 하나를 **랜덤**으로 보여준다
- "괜찮아요" 버튼을 누르면, **방금 추천된 음식점 근처**의 공원(또는 카페)을 여러 개 찾아서 보여준다
- "이거 그냥 지도에서 카페 검색해서 보여주는게 아니라 AI 학습으로 하게 해줘 지금 있는 AI 학습 서버 그거로
  해줘" — 단순 지도 카테고리 검색이 아니라, 이미 있는 AI 추천 서버(팀원이 만든 LLM 기반 서버)를 활용해달라는
  요청.

------------------------------------------------------------------------
## 조사 결과 및 설계 방향 확정 과정
------------------------------------------------------------------------
팀원이 만든 AI 추천 서버(`recommendation_api.py`)의 실제 코드를 확인한 결과, 카카오 로컬 API를 호출하는
부분이 `category_group_code: "FD6"`(음식점)로 **하드코딩**되어 있어서, 그 서버의 `/api/recommend`에
"카페 추천해줘"/"공원 추천해줘" 같은 문장을 그대로 보내도 카페(CE7)나 공원은 카카오 쪽에서 애초에 걸러져
결과가 거의 안 나온다는 걸 확인했다.

사용자에게 이 제약을 설명하고 두 가지 선택지를 제시:
1. 그 서버의 순수 키워드 분석 엔드포인트(`/api/keywords`, 카카오 호출 없음)만 재사용하고, 실제 장소 검색은
   우리 쪽 Kakao 클라이언트로 직접 하기
2. 팀원의 `recommendation_api.py` 자체를 수정해서 category_group_code를 파라미터로 받게 하기

사용자가 "아니면 다른 모델 설치해도 괜찮은데 어떻게 할래?"로 되물어서, "새 모델을 설치할 필요는 없다 -
문제는 모델 성능이 아니라 코드에서 카테고리를 못박아둔 것뿐"이라고 설명하고 **1안**(팀원 코드는 안 건드리고,
AI 분석만 재사용 + 실제 검색은 우리 쪽 Kakao 클라이언트)으로 확정.

## 이번 범위 정리
------------------------------------------------------------------------
- 추천 결과가 나온 뒤, PARK(공원/산책)과 CAFE(카페) 중 하나를 랜덤으로 골라 안내 문구 + "괜찮아요" 버튼 표시
- "괜찮아요"를 누르면 방금 추천된 음식점(1위 결과) 좌표를 기준으로 반경 내 공원/카페를 최대 5곳 검색
- AI 분석은 팀원 서버의 `/api/keywords`(카카오 호출 없는 순수 LLM 문장 분석)를 그대로 재사용해서 안내
  문구에 반영, 실제 장소 검색은 우리 쪽에서 만든 신규 Kakao 클라이언트로 수행
- `recommend-test.html`에 후속 추천 UI(랜덤 프롬프트, 결과 카드, 지도 마커) 추가

------------------------------------------------------------------------
## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- "지도에서 코스 형태로" 시각화(경로선 연결 등) — 이번엔 각 장소를 마커로 찍어서 보여주는 것까지만 하고,
  음식점→공원/카페를 잇는 실제 경로선(도보 경로 API 연동 등)은 범위 밖
- 팀원의 `recommendation_api.py` 수정 — 카테고리 하드코딩 문제를 그 서버 자체를 고쳐서 해결하는 방법은
  이번엔 선택하지 않음(1안 확정, 위 "조사 결과" 참고)
- 로그인 연동/이력 저장 — 18(추천-피드백)의 `recommendation_histories`처럼 이 후속 추천도 이력을 남기는
  것은 이번 범위 밖(비로그인도 동작하는 단순 조회 기능)
- 카페/공원 자체에 대한 리뷰 기반 랭킹 — 카카오 검색 결과를 거리순으로만 보여주고, 10(리뷰)의 리뷰 태그
  기반 순위는 적용하지 않음(카페/공원은 우리 리뷰 시스템의 대상이 아님)
