
------------------------------------------------------------------------
# 노션 개발일지 작성 템플릿
------------------------------------------------------------------------
사용자가 "노션 정리용으로", "노션에 올릴 거니까" 등으로 하루 작업 요약을 요청하면 이 템플릿 형식을
그대로 따른다. 실제 저장 위치는 노션 워크스페이스 "SD부트캠프 프로젝트 1조" > 개발일지 > 2차프로젝트 >
오주혁 > (날짜) 페이지 — 보통 해당 날짜의 빈 페이지가 이미 만들어져 있으니 그 페이지에 내용을 채운다.

**로컬 `.md` 파일 저장 위치(2026-07-30 확정)**: `docs/00.공통/개발일지/` 폴더 안에
`001-NN.개발일지-{YYYY-MM-DD}.md` 형식으로 저장한다(`NN`은 날짜 순서대로 이어지는 일련번호,
예: `001-01.개발일지-2026-07-27.md`, `001-02.개발일지-2026-07-29.md`). 다른 기능 폴더(`22.길찾기` 등)의
`001-01.요청사항`/`001-02.분석-설계` 같은 번호 체계와 같은 패턴 — `개발일지` 폴더 자체가 하나의 "기능
폴더"처럼 취급되고, 그 안의 각 날짜 로그가 순번이 매겨진 문서 하나씩이라고 보면 된다.

------------------------------------------------------------------------
## 형식 규칙
------------------------------------------------------------------------
- 최상단은 `# {날짜} 작업 정리` 형태의 H1으로 시작
- H1 바로 다음 줄에 구분선(`---`) 하나
- 이후 각 작업 항목을 `## N. {제목}` H2로 나열, 그 아래 `-` 불릿으로 핵심 내용을 간단하면서도
  구체적으로 정리(길게 늘어놓지 않고 한 줄~두 줄짜리 불릿 여러 개)
- **각 `## N.` 섹션 사이마다 구분선(`---`)을 반드시 넣는다** — 섹션이 끝나고 다음 섹션 제목 사이,
  그리고 마지막 섹션 뒤에도 구분선으로 마무리
- 문체는 반말/개조식(음슴체 아님, "~함", "~했음"이 아니라 자연스러운 개조식 명사형/서술형 혼용) —
  실제 대화에서 쓰던 톤 그대로, 과하게 격식 차리지 않음
- 세부 기술 용어(API 경로, 에러코드, 클래스명 등)는 필요할 때만 백틱으로 넣고, 전체적으로는 "무엇을
  왜 했는지"가 한눈에 들어오게 요약 — docs의 구현-테스트 문서처럼 세세하게 쓰지 않음

------------------------------------------------------------------------
## 예시 (2026-07-23 작업 정리, 실제 사용된 형식)
------------------------------------------------------------------------
```markdown
# 2026-07-23 작업 정리
---
## 1. 관리자 페이지 + 권한 관리 (14.관리자-권한)
- 이 프로젝트 최초로 Spring Security 도입 — 단, `/api/admin/**` 경로에만 적용하고 나머지 API는 기존 방식 그대로 유지
- 회원 정지/정지해제, 리뷰 강제 삭제 기능 구현
- 관리자 대시보드 추가 — 전체/일반/사업자/관리자 회원 수, 작성된 리뷰 수, 신고된 리뷰 수를 한눈에 확인
---
## 2. 리뷰 신고 기능 (16.리뷰-신고, 신규 기능)
- 회원이 리뷰를 5가지 고정 사유로 신고 가능, 같은 리뷰 중복 신고는 차단
- 신고 처리 상태를 대기중 / 처리완료 / 반려(처리불가) 3가지로 구분
---
```
(전체 실제 예시는 노션 페이지 참고: 개발일지 > 2차프로젝트 > 오주혁 > 2026-07-24)

------------------------------------------------------------------------
## 참고
------------------------------------------------------------------------
- 이 형식은 사용자가 이미 쓰던 2026-07-21 페이지의 스타일(각 `##`/`###` 섹션마다 구분선)을 보고
  확정한 것 — 그 페이지는 `###` 소제목까지 매번 구분선을 넣었지만(더 세분화된 기술 문서였기 때문),
  이 프로젝트 요약본은 보통 `##` 레벨만 쓰므로 `##` 사이에만 구분선을 넣으면 충분하다.
- `.md` 파일로도 같이 만들어달라고 하면, 위 형식 그대로(구분선 포함) 로컬 파일로도 저장한다.
