# VM SSH 접속 가이드 (학원/집 등 여러 컴퓨터에서 접속하기)
------------------------------------------------------------------------
Azure VM(`SoldeskProject1`, `72.155.72.187`)에 학원/집 등 여러 컴퓨터에서 접속해야 하는데, 매번 새로 설정하지 않고 같은 방식으로 접속하기 위한 가이드.
※ 지금은 본인(eric7) 혼자만 이 VM에 SSH로 접속함 — 팀원 접속은 해당 없음.
관련 문서: [Redis-Docker-구축-가이드.md](Redis-Docker-구축-가이드.md)

------------------------------------------------------------------------
## 1. 이미 되어 있는 것
------------------------------------------------------------------------
- VM에는 `soldeskuser`라는 SSH 계정이 등록되어 있음 (2026-07-17, `az vm user update --ssh-key-value`로 생성)
- 이 계정은 **비밀번호 로그인이 막혀 있고 키 인증만 가능** — 비밀번호로 접속 시도하면 `Permission denied (publickey)` 발생
- 집 컴퓨터(`eric7`)에 이미 키가 있음:
  ```
  C:\Users\eric7\.ssh\soldesk_vm       (개인키)
  C:\Users\eric7\.ssh\soldesk_vm.pub   (공개키, VM의 soldeskuser 계정에 이미 등록됨)
  ```

------------------------------------------------------------------------
## 2. 다른 컴퓨터(학원 등)에서 접속하는 방법 — 같은 키 복사
------------------------------------------------------------------------
새로 키를 만들거나 VM 쪽 설정을 또 건드릴 필요 없이, **이미 만들어둔 키 파일 2개를 그대로 복사**하면 된다.

### 2-1. 키 파일 옮기기
아래 두 파일을 옮길 컴퓨터의 `C:\Users\<그 컴퓨터의 계정명>\.ssh\` 폴더로 복사한다.
```
C:\Users\eric7\.ssh\soldesk_vm       ← 개인키. 절대 단톡방/공개 채널에 올리지 말 것
C:\Users\eric7\.ssh\soldesk_vm.pub   ← 공개키. 유출돼도 큰 문제는 없음
```
옮기는 방법은 편한 대로: USB, 카카오톡 "나에게 보내기", 개인 구글드라이브 등. **본인만 접근 가능한 경로로만** 옮길 것 (공용 컴퓨터의 공유 폴더 등은 피하기).

`.ssh` 폴더가 없으면 만들어서 넣으면 된다:
```powershell
New-Item -ItemType Directory -Force -Path "$HOME\.ssh"
```

### 2-2. 접속
옮긴 컴퓨터의 PowerShell에서:
```powershell
ssh -i "$HOME\.ssh\soldesk_vm" soldeskuser@72.155.72.187
```
비밀번호를 묻지 않고 바로 접속되면 정상. (최초 1회는 `The authenticity of host ... can't be established. ... yes/no?` 확인이 뜰 수 있음 → `yes` 입력)

------------------------------------------------------------------------
## 3. 원래 학원 컴퓨터에 있던 다른 키를 쓰고 싶다면?
------------------------------------------------------------------------
가능은 하지만, 2장 방법보다 번거로워서 추천하지 않는다.

- 그 키가 **VM을 처음 만들 때 받은 관리자 키**라면 → 대응하는 SSH 계정명을 몰라서(원래 `soldeskuser`를 새로 만든 이유와 동일한 문제) 처음부터 다시 삽질해야 함
- 그 키가 **직접 만들어서 등록해둔 개인 키**라면 → 쓸 수는 있지만, 그 키의 공개키(`.pub`)를 다시 `soldeskuser` 계정에 추가로 등록하는 절차가 필요함:
  ```powershell
  az login
  az vm user update `
    --resource-group Soldesk `
    --name SoldeskProject1 `
    --username soldeskuser `
    --ssh-key-value "학원 키의 .pub 파일 내용"
  ```

결론: 특별한 이유가 없으면 2장처럼 지금 키를 복사해서 쓰는 게 제일 빠르다.

## 4. 자주 겪는 문제
------------------------------------------------------------------------
| 증상 | 원인/해결 |
|---|---|
| `Permission denied (publickey)` | 비밀번호로 접속을 시도했거나, `-i` 옵션으로 올바른 키 파일을 안 지정한 경우. 반드시 `-i "$HOME\.ssh\soldesk_vm"` 옵션 포함 |
| `ssh` 명령이 안 먹힘 (PowerShell에서 `<`, `>` 관련 에러) | 이 문서의 예시를 그대로 복붙하지 않고 `<계정명>` 같은 자리표시자를 문자 그대로 입력한 경우. 꺾쇠괄호 없이 실제 값으로 교체해서 입력할 것 |
| `az` 명령이 안 먹힘 | Azure CLI 설치(`winget install Microsoft.AzureCLI`) 직후에는 **새 PowerShell 창**을 열어야 PATH가 인식됨 |
| `az` 명령을 VM 안(SSH 세션)에서 실행해서 에러남 | `az` 관련 명령은 **로컬 PowerShell**에서, `docker`/`redis-cli` 등은 **SSH로 접속한 VM 안**에서 실행해야 함 — 지금 어느 쪽 터미널인지 프롬프트로 확인(`PS C:\...>`면 로컬, `$` 또는 `user@host:~$`면 VM 안) |
