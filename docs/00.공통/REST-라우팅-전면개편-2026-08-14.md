# REST 라우팅 전면 개편 (2026-08-14)

전체 API를 RESTful 컨벤션(복수 명사 컬렉션, URL에 동사 금지, HTTP 메서드로 동작 표현, 하이픈-케이스)에
맞춰 재작성. WebSocket 목적지(`/ws-chat`, `/app/**`, `/topic/**`)와 `/api/admin/**` 프리픽스 자체는 유지
(하위 세부 경로만 변경).

## 사용자가 직접 변경해야 하는 외부 설정

배포 전 아래 3개 콘솔에서 카카오/네이버/구글 로그인의 **Redirect URI(콜백 URL)** 값을 반드시 갱신해야
합니다. 코드가 `/oauth/{provider}` → `/api/oauth-providers/{provider}/callback` 으로 바뀌었기 때문에,
콘솔에 등록된 값을 그대로 두면 배포 즉시 소셜로그인이 전부 깨집니다.

현재 `application.yml`(133~148행)의 기본값 기준으로, 실제 운영 값은 `.env`의
`KAKAO_REDIRECT_URI` / `NAVER_REDIRECT_URI` / `GOOGLE_REDIRECT_URI`에 들어있습니다(로컬 기본값은
`http://localhost:8081/oauth/{provider}` 형태였음). 운영 도메인이 다르면 그 도메인 기준으로 동일하게
경로만 바꿔주면 됩니다.

- **Kakao Developers** (카카오 로그인 활성화 앱) → "카카오 로그인 > Redirect URI" 항목에서
  기존 `.../oauth/kakao` 로 등록된 값을 `.../api/oauth-providers/kakao/callback` 으로 변경.
- **Naver Developers** (네이버 로그인 애플리케이션) → "API 설정 > Callback URL" 항목에서
  기존 `.../oauth/naver` 를 `.../api/oauth-providers/naver/callback` 으로 변경.
  (연동해제 콜백인 `/api/auth/naver/unlink-callback` → `/api/oauth-providers/naver/unlink-callback` 도
  네이버 앱 설정에 별도로 등록돼 있다면 함께 갱신 필요 — "서비스 URL" 또는 "연동 해제 시 콜백 URL" 항목 확인.)
- **Google Cloud Console** (OAuth 2.0 클라이언트 ID) → "승인된 리디렉션 URI" 항목에서
  기존 `.../oauth/google` 을 `.../api/oauth-providers/google/callback` 으로 변경.
- **공공데이터포털(data.go.kr), NCP, 카카오 로컬/영수증 OCR 등 기타 외부 API** → 별도로 우리 서버의
  콜백 URL을 등록해서 쓰는 곳은 없음(모두 우리가 그쪽 API를 "호출"만 하는 구조). `/juso-callback` →
  `/api/juso-callbacks` 는 우리 프론트가 팝업을 열 때 매번 동적으로 조립해서 넘기는 값이라 외부 콘솔에
  등록된 게 없음 — 코드/프론트만 맞으면 됨. 변경 불필요.

`application.yml`의 `oauth.kakao.redirect-uri` 등 기본값도 코드와 함께 `/api/oauth-providers/{provider}/callback`
로 갱신해두었으니, 로컬에서 `.env`를 안 쓰는 팀원은 그 기본값이 자동 반영됩니다. 다만 실제 배포 서버의
`.env`에 명시적으로 `KAKAO_REDIRECT_URI` 등이 박혀 있다면 그 값도 함께 바꿔야 합니다(코드 기본값은 그
env var가 없을 때만 적용됨).
