## 2. Playwright 검증 (2026-07-22)
------------------------------------------------------------------------
테스트 회원을 `dbHelper.insertPendingMember` + `jwtHelper.mintAccessToken` + `redisHelper.activateAccessToken`으로
세션 발급(기존 `restaurant.spec.js`의 `loginMember()`와 같은 패턴)해서 실제 브라우저로 전체 플로우 검증.

**즐겨찾기 등록 → 목록 반영 → 해제**:
1. 검색 결과 첫 음식점(`16421356`, "농민백암순대 강남직영점") 상세 열기
2. 즐겨찾기 버튼 클릭 → 버튼이 `active` 상태(★)로 바뀜 확인
3. 마이페이지 열기 → 즐겨찾기 목록에 `"농민백암순대 강남직영점 - 서울 강남구 역삼로3길 20-4"`로 정상 표시됨
   확인(스냅샷 이름+주소가 실제로 저장/조회됨)
4. 마이페이지 프로필 영역에 `"닉네임 ... 이메일 ...(수정불가) 전화번호 - 음BTI 미설정"` 정상 표시 확인
   (전화번호 미등록 회원이라 `-`, `foodBti`는 설계대로 `null` → "미설정")
5. 즐겨찾기 버튼 다시 클릭(해제) → 버튼이 비활성(☆) 상태로 돌아옴 확인

**리뷰 작성 → 내 리뷰/방문기록 반영**:
1. 리뷰 내용 입력 후 제출 → 에러 없이 성공
2. 마이페이지 "내 리뷰"에 `"농민백암순대 강남직영점 - ★5 마이페이지 검증용 리뷰입니다"`로 정상 표시 확인
   (restaurantName 스냅샷이 리뷰에도 정상 저장됨)
3. "방문기록"은 `"없음"`으로 정상 확인 — 영수증 인증 없이 쓴 리뷰라 방문기록 조건(`receiptVerified=true`)에
   해당하지 않는 게 맞음(001-02 3-3장 설계대로 동작)

검증에 쓴 테스트 회원/Redis 세션은 확인 직후 정리(`deleteMemberByEmail`, `cleanupAccessKey`). 즐겨찾기/리뷰
데이터는 테스트 회원 삭제로 함께 정리됨(별도 FK 정리 불필요 — 소프트 삭제가 아니라 회원 자체를 지웠기
때문에 고아 데이터로 남지만, 다음 조회 시 존재하지 않는 memberId라 응답에 영향 없음. 다만 완전한 정리를
원하면 즐겨찾기/리뷰 행도 별도로 지워야 함 — 5장 참고).

## 5. 검증 후 정리 (참고용 기록, 1차 구현 검증분)
------------------------------------------------------------------------
테스트 중 검증에 쓴 즐겨찾기/리뷰 행은 회원 삭제만으로는 자동으로 지워지지 않는다(FK CASCADE 미설정) —
`deleteMemberByEmail`은 `members`/`member_credentials`/`email_verifications`/`phone_verifications`/
`social_accounts`만 지운다. 즐겨찾기는 검증 마지막에 해제해서 자동으로 지워졌고, 남아있던 리뷰 1건
(`review_id=3`, "마이페이지 검증용 리뷰입니다")은 검증 직후 수동으로 삭제 완료. 향후 비슷한 테스트를 할
때는 `favorites`/`reviews` 테이블도 테스트 `memberId` 기준으로 함께 정리하는 것을 권장.

### 6-3. Playwright 검증
테스트 회원 2명(작성자+타인)으로 실제 API 호출까지 확인:
- **리뷰 작성 → 수정** (`PATCH`): `{rating:2, content:"CRUD 테스트 수정됨"}` → `200`과 갱신된 값 정상 응답
- **소유권 검증**: 작성자가 아닌 다른 회원의 토큰으로 같은 리뷰 수정 시도 → `403 REVIEW_ACCESS_DENIED` 확인
- **리뷰 삭제** (`DELETE`): `204 No Content` → 이후 그 음식점 리뷰 목록 조회 시 삭제된 리뷰가 더 이상
  나오지 않음을 확인(소프트 삭제가 `deletedAt IS NULL` 조건에 정상 반영됨)
- **검색 기록 기록**: 로그인 상태로 `GET /api/restaurants/search?keyword=순대&...` 호출 → `GET
  /api/mypage/search-histories`에 `{"keyword":"순대", ...}` 행이 자동으로 생성됨을 확인(수동으로 기록 API를
  부른 적 없음 — 검색의 부수효과로 정상 기록됨, 001-02 3-5장 설계 검증)
- **검색 기록 개별 삭제**: `DELETE /api/mypage/search-histories/{id}` → `204`
- **검색 기록 전체 삭제**: `DELETE /api/mypage/search-histories` → `204` → 이후 목록 조회 시 `[]` 확인

검증에 쓴 테스트 회원 2명, 리뷰 행(이번에 만든 것 + 이전 세션에서 정리를 놓쳤던 리뷰 1건도 함께 발견)은
확인 직후 DB에서 직접 삭제해 정리함.

### 8-2. Playwright 검증
- 마이페이지 페이지 진입 시 프로필 수정 영역이 기본적으로 잠겨있고 게이트만 보이는 것 확인

- **Playwright 타이밍 오탐 1건**: 비밀번호 확인 직후 500ms만 대기하고 "필드가 여전히 안 보인다"고 판단해
