## 1. 구현 결과 (2026-07-27)
------------------------------------------------------------------------
### 1-1. 실제 구현 파일
```
com.foodtrip.foodsearch.directions (신규 패키지)
 ├─ client/NcpDirectionsClient
 ├─ dto/DirectionsResponseDto
 └─ controller/DirectionsController
```
`ErrorCode`에 `DIRECTIONS_SERVICE_UNAVAILABLE` 추가. `application.yml`에 `ncp-directions.base-url`/
`client-id`/`client-secret` 추가, `.env`에 `NCP_MAPS_CLIENT_ID`/`NCP_MAPS_CLIENT_SECRET` 추가(지도
렌더링용 `ncpKeyId`와 Client ID는 같은 값 `i99edc9due`, Secret만 이번에 새로 추가됨).

### 1-2. API 구현 목록
| API | 인증 | 설명 |
|---|---|---|
| GET /api/directions | 불필요 | 출발지→목적지 자동차 경로/거리/소요시간/요금 조회 |

### 1-3. 프론트 구현
`tmp-map-test.html` 음식점 상세 패널에 "🚗 길찾기" 섹션 추가:
- `currentDetailLat`/`currentDetailLng` 전역 변수(목적지 좌표, 상세 조회 성공 시 채워짐)
- `directionsPolyline` 전역 변수(이전 경로선 참조, 새로 그리기 전에 지우기 위함)
- "현재 위치에서 길찾기" 버튼 → `findDirections()`: `navigator.geolocation`으로 현재 위치를 받아
  `/api/directions` 호출 → 응답의 `path`(경도,위도)를 `naver.maps.LatLng(위도,경도)`로 뒤집어 변환 →
  `naver.maps.Polyline`으로 그리기 → `map.fitBounds()`로 경로 전체가 보이게 자동 확대/축소
- 상세 패널을 닫거나 다른 음식점을 열면 `clearDirectionsRoute()`로 경로선/좌표 상태 초기화(이전 가게의
  경로가 남아있지 않도록)

## 2. 검증 (2026-07-27, 실 서버)
------------------------------------------------------------------------
### 2-1. NCP Direction 5 원본 응답 직접 확인
서버를 거치지 않고 `curl`로 강남역→역삼동 인근 좌표 직접 호출:
```
curl "https://maps.apigw.ntruss.com/map-direction/v1/driving?start=127.0276,37.4979&goal=127.0362,37.5030" \
  -H "X-NCP-APIGW-API-KEY-ID: {client-id}" -H "X-NCP-APIGW-API-KEY: {client-secret}"
```
`code:0`, `route.traoptimal[0].summary`에 distance/duration/tollFare/taxiFare/fuelPrice, `path`에
좌표 배열이 정상적으로 옴을 확인 — 이 실제 응답 구조를 그대로 `NcpDirectionsClient` 구현에 반영(추정 없이
바로 정확하게 구현, 15/17처럼 나중에 파싱 버그를 겪지 않음).

### 2-2. 백엔드 API 직접 호출
서버 컴파일/재기동 후:
```
curl "http://localhost:8081/api/directions?startLat=37.4979&startLng=127.0276&goalLat=37.5030&goalLng=127.0362"
```
`{"distanceM":1314,"durationMs":407379,"tollFare":0,"taxiFare":4800,"fuelPrice":175,"path":[...]}` 정상
응답 확인.

### 2-3. 프론트 종단 검증 (Playwright, geolocation 모킹)
`context.geolocation`을 강남역 좌표(37.4979, 127.0276)로 모킹하고 실제 브라우저로 전체 플로우 검증:
1. "스타벅스" 키워드 검색 → 마커 72개 렌더링
2. 첫 번째 마커 클릭 → 상세 패널 열림, "🚗 길찾기" 섹션에 "현재 위치에서 길찾기" 버튼 노출 확인
3. 버튼 클릭 → `#directionsResult`에 **"약 1.0km · 약 4분 소요 (택시요금 약 4,800원)"** 텍스트 정상 표시
4. 스크린샷으로 지도 위에 실제 파란색 경로선(Polyline)이 출발지에서 목적지까지 정확히 그려지고,
   `fitBounds()`로 지도가 그 경로 전체가 보이도록 자동 조정된 것을 육안 확인

전 과정 콘솔 에러 0건.
