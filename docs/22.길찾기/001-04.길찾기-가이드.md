## 2. 키 준비
------------------------------------------------------------------------
NCP(네이버클라우드플랫폼) 콘솔에서 Maps 상품군의 **"Direction 5"** API를 활성화하고 발급받은 Client ID/
Secret을 `.env`에:
```
NCP_MAPS_CLIENT_ID={Client ID}
NCP_MAPS_CLIENT_SECRET={Client Secret}
```
지도 렌더링용 `ncpKeyId`(`tmp-map-test.html`의 `maps.js` 스크립트 태그)와 Client ID가 같은 값일 수 있다
(이 프로젝트에서는 동일했음). Secret이 없으면 `GET /api/directions`가 `500
DIRECTIONS_SERVICE_UNAVAILABLE`을 반환한다.

## 3. 기능별 호출 흐름
------------------------------------------------------------------------
### 3-1. 음식점 상세에서 길찾기
1. 음식점 상세 조회(`GET /api/restaurants/{id}`, 07)로 받은 `latitude`/`longitude`를 목적지 좌표로
   기억해둔다
2. 사용자가 "길찾기" 버튼을 누르면 브라우저 `navigator.geolocation.getCurrentPosition()`으로 현재
   위치를 받는다(위치 권한 요청 팝업이 뜸)
3. 현재 위치 + 목적지 좌표로 `GET /api/directions`를 호출
4. 응답의 `path`(경도,위도 순서)를 지도 라이브러리 좌표 순서(위도,경도)로 뒤집어서 `Polyline`으로 그림
5. 거리(`distanceM`)/소요시간(`durationMs`)/통행료(`tollFare`)/택시요금(`taxiFare`)을 사람이 읽기 좋게
   변환해서 표시(km 단위, 분 단위)

## 4. API 상세
------------------------------------------------------------------------
### 4-1. 경로 조회
```
GET http://localhost:8081/api/directions?startLat=37.4979&startLng=127.0276&goalLat=37.5030&goalLng=127.0362
```

응답(200):
```json
{
  "distanceM": 1314,
  "durationMs": 407379,
  "tollFare": 0,
  "taxiFare": 4800,
  "fuelPrice": 175,
  "path": [[127.0276109, 37.4979025], [127.0276201, 37.4978836], "... 경도,위도 좌표 배열 계속"]
}
```
`path`는 경도(lng)가 먼저, 위도(lat)가 나중이다 — Naver Maps JS SDK의 `LatLng(lat, lng)` 순서와
반대이므로 프론트에서 반드시 뒤집어서 써야 한다(`tmp-map-test.html`의 `findDirections()` 참고).

실패(500): `{ "success": false, "code": "DIRECTIONS_SERVICE_UNAVAILABLE", "message": "길찾기 서버와 통신할 수 없습니다." }`
