## 2. 검증 (2026-07-24, 실 서버 + 실 DB)
------------------------------------------------------------------------
DB VM(72.155.72.187)을 붙여 서버를 재기동하고, throwaway 회원 2명(`e2e/dbHelper`로 직접 시딩) +
`e2e/jwtHelper`(토큰 직접 발급) + `e2e/redisHelper`(access 세션 활성화)로 Node `fetch` 스크립트를 작성해
전체 흐름을 순서대로 확인(검증 후 스크립트/데이터 모두 삭제).

### 2-1. `ddl-auto=update`로 컬럼이 실제로 추가되었는지 확인
```sql
SELECT COLUMN_NAME, IS_NULLABLE, DATA_TYPE FROM information_schema.COLUMNS
WHERE TABLE_NAME = 'recommendation_histories' AND COLUMN_NAME IN ('was_helpful','feedback_at')
```
결과: `feedback_at`(datetime, nullable), `was_helpful`(bit, nullable) — 서버 재기동만으로 정상 추가됨을
확인.

### 2-2. 비로그인 추천 요청 → 이력 저장 안 됨
`Authorization` 헤더 없이 `POST /api/recommendation/query` 호출 → `200`, `history_id: null` 확인.

### 2-3. 로그인 추천 요청 → 이력 저장 + historyId 응답
회원 A 토큰으로 같은 API 호출 → `200`, `history_id: 1`(신규 이력). DB에서 직접 조회한 결과:
```
member_id: 2045, recommendation_type: 'KEYWORD',
query_text: '강남역 분위기 좋은 파스타집', extracted_keywords: '강남역, 분식, 감성',
current_latitude: '37.50', current_longitude: '127.03',
was_helpful: null, feedback_at: null
```
요청한 회원 ID/질문 문장/추출 키워드/좌표가 정확히 기록됨을 확인. `was_helpful`/`feedback_at`은 아직
피드백 전이라 `null`.

### 2-4. 피드백 제출 (본인 이력) → 정상 저장
회원 A 토큰으로 `PATCH /api/recommendation/1/feedback` `{ "wasHelpful": true }` 호출 → `200
{ success: true, message: "피드백이 저장되었습니다." }`. DB 재조회 결과 `was_helpful: 1(true)`,
`feedback_at`에 현재 시각이 채워짐을 확인.

### 2-5. 다른 회원 토큰으로 피드백 시도 → 404
회원 A의 `historyId`에 회원 B 토큰으로 `PATCH` 시도 → `404 RECOMMENDATION_HISTORY_NOT_FOUND` 정상 거부.

### 2-6. 존재하지 않는 historyId → 404
`PATCH /api/recommendation/999999999/feedback` → `404 RECOMMENDATION_HISTORY_NOT_FOUND` — 2-5와 같은
코드로 응답해 "다른 회원 소유"와 "존재하지 않음"을 구분하지 못하게 한 설계(001-02 2-5장)가 실제로
동작함을 확인.

검증에 쓴 회원 2명/추천 이력 1건은 확인 직후 DB에서 직접 삭제해 정리함. 검증 스크립트(Node ad-hoc,
`e2e/verify18.js`)도 확인 완료 후 삭제.
