## 요청사항 원문 요약
------------------------------------------------------------------------
PPT 출처 정리 작업 중 참고용으로 보여드린 [ UI 수정 필요 ] 목록에 아래 항목이 있었음:
```
[ UI 수정 필요 ] 피드백
   - AI 답변이 마음에 들었어요
   - AI 답변이 마음에 들지 않았어요
   - Database에 수집 후 모델 정확도 학습에 활용
```
이 문구를 보고 "지금 AI 그 추천해서 있잖아 그거 이렇게 해서 받으려고 하는데 현재 DB에서 수정 없이
가능한지 확인 후 알려줘"라는 요청 — AI 추천(12.음BTI가 아니라 자연어 추천 검색,
[project_ai_recommendation_search_deferred] 메모리 참고) 결과에 👍/👎 피드백을 받는 UI를 기존 DB 스키마
수정 없이 붙일 수 있는지 먼저 확인해달라는 것.

------------------------------------------------------------------------
## 확인 결과 (구현 전 조사)
------------------------------------------------------------------------
`recommendation_histories`/`recommendation_results` 두 테이블 모두 원래 기획 단계(`docs/00.공통/
DB-테이블설계.md` 6-1/6-2장)에서부터 존재했지만, **실제로는 완전히 죽어있는 테이블**이었음을 확인:
- 두 테이블 모두 0행
- Java 쪽에 이 두 테이블을 위한 JPA 엔티티가 어디에도 없음(아예 코드로 접근한 적이 없음)
- 팀원이 만든 Python 추천 서버(`recommendation_api.py`)도 grep으로 확인한 결과 `INSERT INTO`/
  `pymysql`/`sqlalchemy`/`mysql.connector` 등 DB 접근 코드가 전혀 없음 — 응답만 만들어 돌려줄 뿐 아무 데도
  기록하지 않음

사용자가 참고로 보여준 원래 기획 스케치(다이어그램 스크린샷)에는 `recommendation_histories` 밑에
`was_helpful` 컬럼이 있었지만, 이건 **처음부터 계획만 되고 실제로 만들어진 적이 없는 컬럼**이다(현재 DB
스냅샷 문서에도 없음).

**결론: "수정 없이는 불가능"** — 피드백을 저장할 컬럼 자체가 없다. 다만 어느 단위로 피드백을 받을지에
따라 필요한 변경 범위가 달라져서, 먼저 그 부분을 확인함:
- 질문(한 번의 추천 요청) 전체에 대한 피드백인지 (`recommendation_histories` 레벨)
- 추천된 음식점 하나하나에 대한 피드백인지 (`recommendation_results` 레벨)

사용자 답변: "응 내가 강남역 주변 분위기 좋은 파스타집 추천해줘 그 질문에서 피드백 그거야" — **질문
단위(1회 추천 요청 = 1개 피드백)** 로 확정. 이어서 "그럼 컬럼 더 추가하고 그거도 docs에 정리하고 지금
내가 요청한 사항도 docs에 요청사항, 분석 설계, 구현 테스트, 가이드 까지 전체 다 만들어줘"로 구현·전체
문서화까지 지시함. "디비 다이어그램은 나중에 다시 만들게 메모리에 저장해놔"도 함께 지시 — 최근 배포한
ERD Artifact가 이 컬럼 추가로 다시 낡아지므로, 재작성은 나중에 별도로 요청하겠다는 의미(메모리에 기록).

------------------------------------------------------------------------
## 이번 범위 정리
------------------------------------------------------------------------
- `recommendation_histories`에 `was_helpful`(bit)/`feedback_at`(datetime) 두 컬럼 추가
- 로그인한 회원이 추천을 요청하면 그 요청 1건을 `recommendation_histories`에 저장(기존엔 저장 자체가
  없었음)하고, 그 이력의 ID로 피드백을 남길 수 있는 API 신규 추가
- `recommend-test.html`에 결과가 나온 뒤 👍/👎 버튼 UI 추가(로그인 상태에서만 노출)

------------------------------------------------------------------------
## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- `recommendation_results`(추천된 음식점 개별 결과) 저장 — 피드백이 질문 단위로 확정됐고, 이 테이블의
  `final_score` 컬럼이 NOT NULL인데 Python 서버가 그런 점수를 응답에 안 주기 때문에, 굳이 저장할 이유가
  없다고 판단해 이번엔 손대지 않음(테이블 자체는 그대로 남아있음, 나중에 개별 결과 피드백이 필요해지면
  그때 다시 검토)
- 비로그인 사용자의 피드백 — `/api/recommendation/query`는 그대로 로그인 불필요를 유지하지만, 이력이
  안 남으므로 비로그인 요청에는 피드백을 남길 방법 자체가 없음(추천 자체는 그대로 동작)
- "Database에 수집 후 모델 정확도 학습에 활용" — 이번엔 피드백을 저장하는 것까지만, 그 데이터를 실제로
  모델 학습/추천 로직 개선에 쓰는 것은 팀원의 Python 서비스 쪽 작업이라 이번 범위 밖
- DB 다이어그램(ERD) 재작성 — 이번 컬럼 추가로 최근 배포한 ERD Artifact가 낡아지지만, 사용자가 나중에
  직접 다시 요청하겠다고 해서 이번엔 안 함
