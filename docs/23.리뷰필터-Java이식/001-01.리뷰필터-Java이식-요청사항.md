# 리뷰/채팅 욕설 필터 — Python 서버 제거 후 Java 이식
------------------------------------------------------------------------

------------------------------------------------------------------------
## 실행 환경
------------------------------------------------------------------------
사용하는 툴
- STS, VS Code
사용하는 코드
- Spring Boot(백엔드) — Python은 이번 작업으로 완전히 제거됨
작업 영역
- Project2, SoldeskProject2_Python(review-filter 폴더 삭제)

------------------------------------------------------------------------
## 요청사항 원문 요약
------------------------------------------------------------------------
"지금 현재 리뷰나 그런 욕설 검열하는거 있잖아 그거가 지금 Python에서 FastAPI 서버로 켜야 하는 구조여서
그걸 그렇게 안하고 python에서 아예 안쓰고 Java에서 바로바로 하게 해줘" — 17(리뷰-필터링)에서 도입한
korcen 기반 욕설 필터가 별도 Python(FastAPI) 프로세스를 팀원이 매번 로컬에서 띄워야 하는 구조였는데,
이 의존성 자체를 없애고 Java 안에서 즉시 처리되게 해달라는 요청.

------------------------------------------------------------------------
## 배경
------------------------------------------------------------------------
17(리뷰-필터링)에서 korcen(Tanat05, MIT License, PyPI 라이브러리)을 채택할 당시엔 "Python 서버를
팀 로컬에서 별도 기동, Spring이 그 서버를 대신 호출"하는 이 프로젝트의 기존 패턴(business-verify,
recommendation과 동일)을 그대로 재사용했다. 그런데 이 패턴은 리뷰 필터처럼 매 요청마다 호출되는
가벼운 텍스트 판정 로직에는 과했다 — AI 모델(추천, OCR)과 달리 korcen은 순수 규칙+정규화 기반이라
무거운 딥러닝 프레임워크가 필요 없고, Python 프로세스를 유지할 이유가 없다.

또한 실사용 중 "Python 서버가 꺼져 있으면 필터를 그냥 통과시킨다(fail-open)"는 기존 설계 때문에,
팀원이 그 Python 서버 켜는 걸 깜빡하면 욕설 필터 자체가 조용히 무력화되는 문제도 있었다 — Java로
이식하면 이 fail-open 자체가 필요 없어진다(별도 프로세스가 없으니 "꺼져 있는" 상태가 존재하지 않음).

## 이번 범위 정리
------------------------------------------------------------------------
- korcen의 실제 판정 로직(정규화 테이블, 카테고리별 오탐/욕설 패턴, 매칭 알고리즘)을 원본 소스
  (github.com/KR-korcen/korcen, MIT License)를 그대로 읽고 Java로 직접 이식
  (`KorcenProfanityFilter`, `com.foodtrip.foodsearch.reviewfilter.filter` 패키지)
- 이 프로젝트가 실제로 쓰던 호출 범위(`korcen.check(text)`, `foreign=False`)만 이식 —
  general/minor/sexual/belittle/race/parent/special/politics 8개 국내 카테고리. english/japanese/chinese는
  원래도 안 쓰던 부분이라 이식 대상에서 제외
- `ReviewFilterClient.containsProfanity(String)` 메서드 시그니처는 그대로 유지 — 내부 구현만 HTTP 호출에서
  인프로세스 호출로 교체, 호출부(`ReviewServiceImpl`, `ChatMessageServiceImpl`)는 코드 변경 없음
- `SoldeskProject2_Python/review-filter` 폴더 완전 삭제, `application.yml`의 `review-filter.base-url`/
  `.env`의 `REVIEW_FILTER_BASE_URL` 제거
- (부수 발견) `pom.xml`에 `project.build.sourceEncoding`이 없어서 Windows 환경의 플랫폼 기본 인코딩
  (CP949)으로 컴파일되고 있었음 — 순수 한글 텍스트는 우연히 문제없었지만 이모지(서로게이트 쌍) 리터럴이
  깨지는 걸 이번에 발견해서 `UTF-8`로 명시 추가

## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- english/japanese/chinese 카테고리 — 원본 korcen에는 있지만 이 프로젝트가 원래도 쓰지 않던 기능이라
  이식하지 않음(필요해지면 나중에 원본 소스를 참고해 추가 가능)
- `highlight_profanity`(욕설 부분을 강조 표시하는 기능) — 이 프로젝트는 boolean 판정(`containsProfanity`)만
  쓰고 있어서 이식하지 않음
- 판정 기준 자체의 변경 — korcen 원본의 판정 로직을 그대로 이식하는 것이 목표이지, 더 엄격하게/느슨하게
  바꾸는 것은 이번 범위 아님(17에서 이미 "korcen의 의도된 동작을 신뢰한다"고 확정한 방침 유지)
