## 3. 유일하게 안 맞은 케이스 — 원본 라이브러리 자체의 모순으로 판단
------------------------------------------------------------------------
"내 보ㅈㅣ 보여줄게"는 원본 `korcen.py`의 `__main__` 데모에 "sexual 카테고리에서 true가 나와야 한다"는
의도로 적혀 있는 예시지만, 실제로 원본의 `SINGLE_CHAR_NORMALIZATION_MAP` 데이터를 코드 그대로 따라가면
`'ㅣ': 'ㅏ'`로 정규화되도록 되어 있어서(같은 딕셔너리 안에 `'ㅣ'`를 소스로 갖는 항목이 이것 하나뿐,
나중에 재정의되지 않음), "보ㅈㅣ"가 전처리 후 "보ㅈㅏ"가 되어 "보ㅈㅣ"/"보지" 패턴과 매칭되지 않는다.
즉 이건 Java 이식의 버그가 아니라 **원본 데이터와 원본 데모 주석이 서로 어긋나는 부분**으로 판단 —
Java 포트는 원본 데이터를 있는 그대로 따라갔으므로 원본과 동일하게 동작하는 것이 맞다(원본을
"고쳐서" 이식하는 건 이번 범위가 아님, 001-01 참고).

## 4. 배포 및 실 서버 검증
------------------------------------------------------------------------
1. `main-push` 스크래치 클론을 통해 Web 저장소 `main`에 커밋/푸시 → GitHub 웹훅 → Jenkins 빌드 자동
   트리거
2. 첫 빌드는 VM 메모리 부족(846MB)으로 `Java heap space` 오류로 war 패키징 실패 — 이 시점엔 이전
   빌드가 배포한 버전이 그대로 서비스 중이라 실제 서비스 영향은 없었음
3. 빈 커밋으로 재빌드를 트리거하는 도중 VM 자체가 응답 불능(OOM) 상태가 됨 — Azure Portal에서 수동
   재시작 필요(`docs/00.공통/CI-CD-Jenkins-구축-가이드.md` 3장에 이미 기록된 것과 같은 종류의 문제)
4. VM 재시작 후 MariaDB/Docker(Redis)/Jenkins/`soldesk-app` 전부 systemd 자동 기동 확인, 재부팅 중
   큐에 남아있던 웹훅이 자동으로 재실행되어 빌드 SUCCESS, 실제 배포까지 완료
5. `curl http://localhost:8081/`(VM 내부) 및 `curl http://72.155.72.187:8081/`(외부, NSG `Allow-App-8081`
   규칙 확인) 둘 다 `HTTP 200` 확인
