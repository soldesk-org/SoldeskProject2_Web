------------------------------------------------------------------------

------------------------------------------------------------------------

작업 영역
- Project2 (신규 정적 페이지 1개)

------------------------------------------------------------------------
## 요청사항 원문 요약
------------------------------------------------------------------------
"새로운 기능을 하나 만들거야 룰렛 또는 사다리타기 기능을 만들어서 내가 먹고 싶은 음식, 룰렛 칸 갯수를
정하면 룰렛 생기면서 Start 버튼 누르면 돌아가게 당첨 결과도 보여주는 그런 랜덤한 그런거도 넣고 싶어" —
"룰렛 또는 사다리타기" 둘 중 하나를 제안했지만, 뒤이은 구체적인 동작 설명("칸 개수를 정하면 룰렛이
생기고, Start를 누르면 돌아가고, 당첨 결과를 보여줌")이 명확히 룰렛(회전판) 방식이라 **룰렛**으로
구현했다.

------------------------------------------------------------------------
## 이번 범위 정리
------------------------------------------------------------------------
- 먹고 싶은 음식을 여러 개 입력(하나씩 추가 또는 쉼표로 한번에 여러 개)
- 입력한 개수만큼 자동으로 룰렛 칸(파이 조각)이 생성됨 — 최소 2개, 최대 12개
- "룰렛 만들기"를 누르면 룰렛이 그려지고, "START"를 누르면 회전 애니메이션 후 무작위 결과가 당첨으로
  표시됨
- 당첨된 항목을 빼고 다시 돌리는 기능(예: "이미 먹은 곳/질린 메뉴 빼고 다시 고르기")

------------------------------------------------------------------------
## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- 사다리타기 방식 — 요청에서 룰렛으로 방향이 명확해져서 이번엔 구현하지 않음(필요해지면 별도 기능으로
  추가 가능)
- 로그인 연동/결과 이력 저장 — 순수 클라이언트 사이드 랜덤 도구로, 서버에 아무것도 저장하지 않는다
  (18.추천-피드백처럼 이력을 남기는 기능과는 성격이 다름 — 그때그때 즉흥적으로 쓰는 도구)
- 다인원 동시 참여(각자 스마트폰으로 같은 룰렛 결과를 보는 것 등) — 단일 브라우저에서 혼자 쓰는 도구

## 후속 요청 (2026-07-26, 같은 날) — 카테고리 선택 방식 + 주변 음식점 추천
------------------------------------------------------------------------
처음 버전을 만든 뒤 두 가지 개선 요청이 이어짐:

1. "음.. 조금 마라탕, 떡볶이, 비빔밥 이런 형식 말고 좀 더 좋게 해주고" — 자유 텍스트 입력 대신 더 나은
   UX로 바꿔달라는 요청. 07(음식점-메뉴-검색)이 이미 쓰고 있는 고정 카테고리 10개를 아이콘 버튼으로
   탭해서 고르는 방식으로 변경.
2. "그리고 메뉴 정해졌으면 그 메뉴 내 위치 주변에 있는 그 음식을 판매하는 음식점도 추천해주게 해줘" —
   룰렛 당첨 결과가 나오면, 내 위치 주변에서 그 카테고리를 파는 실제 음식점을 찾아서 보여달라는 요청.
   07의 기존 카테고리 필터 API를 재사용해서 구현(상세는 001-02 2-6장).

이 두 요청은 서로 연결돼 있다 — 자유 텍스트를 카테고리 선택으로 바꾼 덕분에, 당첨 결과가 우리 시스템의
`categoryId`와 자연스럽게 연결되어 2번 요청(주변 음식점 검색)이 훨씬 간단하게 구현됐다.

상세 설계는 [001-02.음식-룰렛-분석-설계.md](001-02.음식-룰렛-분석-설계.md) 참고.
