## 1. 구현 결과 (2026-07-24)
------------------------------------------------------------------------
### 1-1. 신규 Python 서버 (`SoldeskProject2_Python/review-filter`)
- `requirements.txt`: fastapi, uvicorn[standard], python-dotenv, korcen
- `config.py`: `.env`의 `ALLOWED_ORIGINS`(콤마 구분)로 CORS 허용 오리진 관리, 생략 시 `*`
- `filter_api.py`: `POST /check` — `korcen.check(text)` 결과를 그대로 `{ "profanity": bool }`로 응답
- `main.py`: FastAPI 앱 진입점 + `GET /health`(business-verify와 같은 헬스체크 패턴)
- `venv` 가상환경으로 로컬 설치/실행 확인(`pip install korcen` 정상 설치됨, 버전 1.0.3)

### 1-2. 백엔드(Spring) 구현
- `com.foodtrip.foodsearch.reviewfilter.client.ReviewFilterClient`(신규) — `RecommendationClient`와 같은
  패턴(`JdkClientHttpRequestFactory`, 연결 5초/읽기 5초 타임아웃), `containsProfanity(text)`가 Python
  서버 통신 실패 시 예외 대신 `false`를 반환(fail-open, 001-02 2-5장)
- `ReviewServiceImpl`에 `ReviewFilterClient` 주입, `create()`/`update()`에 `validateNoProfanity(content)`
  호출 추가 — 태그(`keywords`) 검증 이후, 음식점/영수증 검증 이전 단계에 위치
- `ErrorCode.REVIEW_CONTENT_PROFANITY`(400) 추가
- `application.yml`에 `review-filter.base-url`(기본값 `http://localhost:8002`) 추가, `.env.example`에
  `REVIEW_FILTER_BASE_URL` 설명 추가

### 1-3. 컴파일
`./mvnw.cmd compile` 정상 통과.

## 2. 검증 (2026-07-24, 실 서버 + 실 DB + 실제 Python 필터 서버)
------------------------------------------------------------------------
Python 서버를 실제로 띄우고(`uvicorn main:app --port 8002`), Node `fetch` 스크립트로 Spring API를 순서대로
호출해 확인(throwaway 회원 계정 + `e2e/jwtHelper`·`redisHelper`·`dbHelper` 재사용, 검증 후 정리).

### 2-1. korcen 라이브러리 자체 동작 확인 (Python REPL)
| 입력 | check() 결과 |
|---|---|
| "정말 맛있고 친절했어요" | False |
| "씨발 존나 맛없어서 다시는 안감" | **False** (의도된 예외 처리, 001-02 2-3장) |
| "사장님이 병신같이 응대함" | True |
| "개새끼같은 알바생" | True |
| "위생상태 최악 좆같음" | True |
| "ㅅㅂ 맛없어" | True |
| "음식에서 머리카락 나옴" | False |

### 2-2. Python 서버 단독 확인
```
POST http://localhost:8002/check {"text":"병신같은 서비스"}   -> {"profanity":true}
POST http://localhost:8002/check {"text":"정말 친절하고 맛있어요"} -> {"profanity":false}
```

### 2-3. Spring API 통합 확인 (실 리뷰 작성/수정 흐름)
- 영수증 인증까지 정상 완료한 회원이 `content: "진짜 병신같은 서비스네요"`로 리뷰 작성 시도
  → `400 REVIEW_CONTENT_PROFANITY` 정상 거부
- 같은 회원이 `content: "정말 친절하고 맛있었어요"`로 작성 → `200` 정상 등록
- 방금 등록한 리뷰를 `content: "역시 좆같은 서비스"`로 수정(`PATCH`) 시도 → `400
  REVIEW_CONTENT_PROFANITY` 정상 거부(수정 경로에도 필터가 똑같이 적용됨을 확인)

### 2-4. 필터 서버 다운 시 fail-open 동작 확인
Python 서버 프로세스를 강제 종료한 뒤(`/health` 호출 시 연결 자체가 안 됨을 확인) 같은 회원으로
`content: "필터서버 꺼진 상태 테스트"`(욕설 없는 정상 문구) 리뷰 작성 시도 → `200` 정상 등록됨을 확인 —
필터 서버가 꺼져 있어도 리뷰 작성 핵심 기능은 막히지 않는다는 001-02 2-5장 설계가 실제로 동작함을 확인.
(주의: 이 테스트는 필터 서버가 꺼졌을 때 "정상 문구가 통과되는지"만 확인한 것으로, 그 상태에서 욕설이
섞인 문구를 보내면 검사 자체를 건너뛰므로 그대로 통과된다 — 의도된 트레이드오프, 001-02 7장 참고)

검증에 쓴 테스트 회원/리뷰/영수증 행은 확인 직후 DB에서 직접 삭제해 정리함. 검증 스크립트(Node ad-hoc)도
확인 완료 후 삭제.
