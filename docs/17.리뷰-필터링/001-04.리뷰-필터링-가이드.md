## 1. 서버 접속 정보
------------------------------------------------------------------------
- Spring 로컬 개발 서버: `http://localhost:8081`(기존과 동일)
- 필터 Python 서버: `http://localhost:8002`(신규, 로컬에서 별도로 켜야 함 — 2장 참고)
- 프론트에서 필터 Python 서버를 직접 호출할 필요 없음 — 기존 리뷰 작성/수정 API(`POST /api/reviews`,
  `PATCH /api/reviews/{id}`) 안에서 자동으로 적용됨

------------------------------------------------------------------------
## 2. 필터 Python 서버 실행 방법 (팀원 각자 로컬에서)
------------------------------------------------------------------------
```
cd SoldeskProject2_Python/review-filter
python -m venv venv
./venv/Scripts/python.exe -m pip install -r requirements.txt
./venv/Scripts/python.exe -m uvicorn main:app --port 8002
```
- 이 서버를 안 켜도 리뷰 작성 자체는 막히지 않는다(001-02 2-5장 fail-open) — 다만 그 경우 욕설 필터가
  전혀 동작하지 않으니, 필터링 기능을 실제로 테스트하려면 반드시 켜져 있어야 함
- business-verify(8000)/recommendation(8000)과 포트가 겹치지 않으므로 셋 다 동시에 켜둘 수 있음

------------------------------------------------------------------------
## 3. 프론트 연동 시 알아둘 것
------------------------------------------------------------------------
1. 리뷰 작성/수정 요청은 기존과 똑같이 보내면 된다 — 새로 추가할 파라미터 없음
2. 응답이 `400 REVIEW_CONTENT_PROFANITY`로 오면 "리뷰 내용에 부적절한 표현이 포함되어 있습니다" 같은
   안내를 보여주고, 사용자가 내용을 수정해서 다시 제출하게 하면 됨
3. 어떤 단어 때문에 걸렸는지는 알려주지 않는다(단순히 통과/거부만 응답) — 클린봇처럼 특정 단어를
   하이라이트해서 보여주는 기능은 이번 범위 밖

## 4. API 상세
------------------------------------------------------------------------
### 4-1. 리뷰 작성 (기존 API, 필터만 추가됨)
```
POST http://localhost:8081/api/reviews
Authorization: Bearer {accessToken}
Content-Type: application/json

{
  "restaurantId": "16421356",
  "rating": 1,
  "content": "진짜 병신같은 서비스네요",
  "receiptId": 12,
  "restaurantName": "농민백암순대 강남직영점"
}
```
실패 응답(400, 신규)
```json
{ "success": false, "code": "REVIEW_CONTENT_PROFANITY", "message": "리뷰 내용에 부적절한 표현이 포함되어 있습니다." }
```
정상적인 문구면 기존과 동일하게 `200`으로 등록됨.

### 4-2. 리뷰 수정 (기존 API, 필터만 추가됨)
```
PATCH http://localhost:8081/api/reviews/{reviewId}
Authorization: Bearer {accessToken}
Content-Type: application/json

{ "rating": 2, "content": "역시 좆같은 서비스" }
```
작성과 동일하게 `400 REVIEW_CONTENT_PROFANITY`로 거부될 수 있음.
