# 리뷰 필터링 (욕설/비속어 자동 차단)
------------------------------------------------------------------------

------------------------------------------------------------------------
## 실행 환경
------------------------------------------------------------------------
사용하는 툴
- STS, VS Code(Python)
사용하는 코드
- Spring Boot(백엔드), Python/FastAPI(신규 필터 서버)
작업 영역
- Project2, SoldeskProject2_Python(신규 `review-filter` 폴더)

------------------------------------------------------------------------
## 요청사항 원문 요약
------------------------------------------------------------------------
"리뷰 필터링 (강화된 모델 / 네이버 클린봇)"을 만들어달라는 요청 — 리뷰 본문에 욕설/비속어가 포함되면
등록 자체를 막는 기능. "네이버 클린봇"을 예시로 든 걸로 봐서, 10(리뷰)에 이미 있던 리뷰 태그/키워드
필터(고정 목록 방식)와는 별개로, **실제 자유 텍스트(리뷰 본문)를 검사하는 욕설 필터**를 원하는 요청.

------------------------------------------------------------------------
## 배경
------------------------------------------------------------------------
이 프로젝트에는 이미 `NicknameProfanityFilter`(2026-07-21, 05 회원정보수정)가 있다 — 닉네임에 비속어가
있으면 막는 기능으로, 오픈소스 한국어 비속어 단어 목록(badwords-ko)을 파일로 옮겨 담아 단순 부분 문자열
포함 여부로 판단하는 방식이다. 하지만 이건 닉네임(짧은 단어 하나)에만 적용되고 있었고, 리뷰 본문(긴
자유 텍스트, 띄어쓰기/특수문자로 필터를 피하려는 시도가 훨씬 다양할 수 있음)에는 적용된 적이 없었다.

"강화된 모델"이라는 표현과 "네이버 클린봇" 비유를 듣고, 얼마나 강한 수준(딥러닝 AI 모델까지 갈지, 규칙
기반 필터를 강화하는 수준일지)을 원하는지 확인 질문을 했고, 사용자가 "Github에서 찾아줘봐 한국인이
만든 모델이나 그런 욕설 방지 스크립트 그런거"로 답해서, 직접 만드는 대신 검증된 오픈소스 라이브러리를
조사해서 가져다 쓰기로 확정했다.

조사 결과 [korcen](https://github.com/KR-korcen/korcen) (Tanat05, 한국인 개발자가 만든 한국어 비속어
판별 라이브러리, MIT License, PyPI `pip install korcen`)을 채택했다 — 자모 분리/특수문자 치환/반복문자
등 회피 기법까지 처리하는 정규화 로직이 들어있어서, 기존 `NicknameProfanityFilter`의 단순 단어목록
방식보다 훨씬 강화된 수준이다. 순수 규칙+정규화 기반이라 무거운 딥러닝 프레임워크(torch 등) 설치 없이
가볍게 붙일 수 있다는 것도 이 프로젝트 규모에 맞다고 판단.

## 이번 범위 정리
------------------------------------------------------------------------
- 리뷰 작성(`POST /api/reviews`)/수정(`PATCH /api/reviews/{id}`)의 자유 텍스트(`content`)에 욕설/비속어가
  있으면 `400 REVIEW_CONTENT_PROFANITY`로 등록/수정을 거부
- 판별 로직은 새로 만든 Python(FastAPI) 서버(`SoldeskProject2_Python/review-filter`)가 korcen 라이브러리로
  처리하고, Spring이 그 서버를 호출하는 구조(01/07/08/12에서 이미 쓰던 "Python 서버는 팀 로컬에서 별도
  기동, Spring이 대신 호출" 패턴 그대로 재사용)
- 필터 서버가 꺼져 있어도 리뷰 작성이라는 핵심 기능이 막히면 안 된다고 판단해, 필터 서버 통신 실패 시엔
  검사를 건너뛰고 통과시킴(방어적 설계 — 08 영수증OCR의 "매칭 실패해도 업로드는 성공" 톤과 동일)

------------------------------------------------------------------------
## 이번 범위에서 제외된 것
------------------------------------------------------------------------
- 태그(키워드) 필터링 — 이미 고정 목록(`ReviewKeywordCatalog`)만 허용하는 구조라 자유 텍스트가 아님,
  검사 대상 아님
- 닉네임 필터 강화 — 기존 `NicknameProfanityFilter`(badwords-ko 단어목록 방식)는 이번 범위에서 안 건드림.
  나중에 필요해지면 korcen으로 교체하는 것도 검토 가능하지만 이번엔 리뷰 본문만
- 신고(16.리뷰-신고)와의 자동 연동 — 욕설이 감지돼도 자동으로 신고 처리되거나 하지 않음, 그냥 등록/수정
  자체를 막을 뿐
- 마스킹(별표 처리) 후 등록 허용 — 클린봇처럼 "***"로 가려서 올리는 방식이 아니라, 아예 등록을 막는
  방식으로 확정(마스킹은 원문이 서버에 남는지/사용자가 수정할 기회를 어떻게 줄지 등 추가 설계가 필요해서
  이번 범위 밖)
- 관리자 화면에 "필터에 걸린 시도 이력" 조회 기능 — 이번엔 즉시 거부만, 이력 저장/조회는 범위 밖
